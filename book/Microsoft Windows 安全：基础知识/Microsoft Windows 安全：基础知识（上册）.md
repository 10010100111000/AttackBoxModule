## 第 3 章 理解用户身份验证

**确保安全的主要方法之一**是限制对已知用户的访问。这要求用户进行身份验证，即通过提供某种类型的凭据来证明其身份。身份验证通常分为三种类型，即三种身份验证因素：*所知信息( Something You Know )*、*持有物品( Something You Have )* 和 *固有特征( Something You Are )*。理解这些因素至关重要，包括它们的优势与弱点，以及如何结合使用以增强安全性。

密码是最常用的身份验证方法。了解什么是强密码以及如何创建强密码非常重要。Windows Server 2008 包含许多工具，可用于确保用户在密码使用中遵循最佳实践。这包括在用户尝试猜测密码时锁定账户的选项。智能卡( Smart Card )和生物识别( Biometrics )是更强的身份验证方法，可单独使用，也可与用户名和密码结合使用。

Kerberos 是 Microsoft 域中的主要身份验证协议，但它有严格的时间要求需要理解。以下各节将介绍这些主题及其他内容。

- 比较三种身份验证因素
- 使用密码进行身份验证
- 使用智能卡和令牌设备进行身份验证
- 使用生物识别进行身份验证
- 以管理员身份运行启动应用程序
- 防止 Kerberos 时间偏差( Time Skew )
- 识别 RADIUS 功能
- 识别不安全的身份验证协议

### 比较三种身份验证因素

*身份验证( Authentication )* 发生在实体提交凭据且凭据被验证为有效时。例如，当用户使用用户名和密码登录时，系统会检查用户名和密码是否有效，如果有效，则对用户进行身份验证。

您可能之前使用用户名和密码访问过系统，但在更高安全性的环境中，可能配置了其他身份验证方法。三种主要的身份验证类型或因素如下：

**所知信息( Something You Know )** 包括密码或个人识别码( Personal Identification Number ,PIN)等信息。

**持有物品( Something You Have )** 包括可以持有的物品，例如智能卡。

**固有特征( Something You Are )** 包括可区分的个人特征，例如指纹，可通过生物识别进行验证。

这些方法中的任何一种均可用于身份验证。不过，通过同时使用两个或三个因素，还可以增强安全性。*多因素身份验证( Multi-Factor Authentication ,MFA)* 使用两个或更多因素。例如，当用户同时使用智能卡和 PIN 码时，他们便使用了“你拥有的物品( something you have )”和“你知道的信息( something you know )”这两个因素。

身份验证与授权之间存在区别。用户能够通过登录证明其身份，并不一定意味着他们有权访问系统上的资源。然而，身份验证是这一过程的第一步。第4章“使用权限保护访问安全”介绍了如何通过权限授权用户访问资源。

#### 标识符与身份验证 

标识（身份声明）和身份验证二者有所区别。例如用户使用用户名和密码登录时：**用户名是标识符，用于标识身份；密码用于身份验证。**

**标识（Identification）**：用户申明自身身份、宣称 “我是某某主体” 的过程。 **身份验证（Authentication）**：借助密码等佐证信息，核验上述身份声明是否真实。

在 Windows 系统中，独立主机拥有**安全账户管理器（Security Account Manager, SAM）**数据库，存储本机本地账户信息。在微软域环境中，域控制器运行 Active Directory（活动目录），集中存储域内全部账户信息。

#### 使用密码进行身份验证

密码是最常见的身份验证形式。然而，它们也是最薄弱、最易受攻击的形式。了解什么是强密码以及如何创建强密码至关重要。此外，了解如何在 Microsoft 环境中强制实施强密码也很有价值。本节将介绍密码的许多弱点以及如何加强它们。

### 比较密码攻击方法

攻击者认识到密码是最薄弱的身份验证形式之一，并使用多种方法来破解它们。如果攻击者能发现用户的密码，他们就能访问该用户的帐户并冒充该用户。

在 Microsoft 域环境中，攻击者能够访问用户有权访问的任何资源。攻击者可以读取、修改和删除被入侵账户通常能够访问的数据。如果组织使用了审核跟踪( Audit Trail )，审核跟踪会记录被入侵用户账户执行了这些操作，但不会表明攻击者的存在。

如果攻击者能够获取用户在线账户的密码，他们就可以执行用户能做的任何操作。例如，若攻击者发现了用户银行账户的密码，便可登录并将资金转出账户。

大多数用户对泄露银行密码较为谨慎。然而，他们经常在其他账户中使用相同的密码，并且对这些账户的保护不够谨慎。例如，用户可能对其 Hotmail 账户使用与 eBay、PayPal 账户甚至银行账户相同的密码。

以下列表列出了攻击者常用的一些密码发现方法：

**社会工程学( Social Engineering )** 社会工程学攻击者发现，如果以恰当的方式提问，用户会主动泄露密码。这包括网络钓鱼( Phishing )攻击及其他诱使用户透露密码的方法。用户教育是抵御社会工程学攻击的最佳手段。

第 2 章将涵盖社会工程学攻击，包括网络钓鱼。

**字典攻击( Dictionary Attack )** 字典攻击尝试使用单词列表（类似于字典）中的每个单词作为密码，直到找到匹配项。大多数字典攻击会使用多种语言的单词列表，因此使用外语单词作为密码并无帮助。此外，大多数字典攻击会尝试常用密码，例如 *123456*、*12345678*、*qwerty*、*abc123*、*111111*、*letmein* 等。使用强密码是抵御字典攻击的最佳保护措施。

**暴力破解( Brute Force )** 在暴力破解攻击中，攻击者简单地尝试猜测密码的每一种可能组合。存在可加速此过程的自动化破解工具。使用强密码和账户锁定策略( Account-Lockout Policy )可提供针对暴力破解攻击的最佳保护。

您可能会注意到保护措施中的共同主题：使用强密码是保护密码的最佳方法之一。下一节将定义强密码，并介绍可用于创建易于记忆的强密码的方法。

### 密码破解工具

攻击者可使用多种自动化工具来破解密码。其中一些工具被宣传为管理员用于恢复密码的"密码恢复工具"，但同样会被攻击者利用。

举例来说，假设你是一名网络管理员，有人更改了 Windows 7 系统的本地管理员密码。此时，你可以选择从头重建该系统，或使用密码恢复工具来恢复管理员密码。显然，能够恢复密码会更省事。

Ophcrack 是一款免费的密码恢复工具。你可以下载该程序的 .iso 镜像文件，将其刻录到 CD 并从 CD 启动。该工具能快速恢复 Windows 7 及其他 Windows 系统上的所有密码。即使是 10 个字符的密码，也能在不到一分钟内恢复。更长的密码则需要更多时间。

虽然管理员可以使用 Ophcrack 恢复密码，但攻击者同样可以利用它来破解密码。过程相同，但意图不同。

类似地，Nessus 是一款流行的漏洞评估工具。它可以捕获网络流量并分析数据以发现密码。以明文形式通过网络传输的密码很容易被发现。然而，即使使用了加密方法来保护密码，当密码较弱时，Nessus 也能发现它们。

安全专业人员使用 Nessus 评估网络弱点，但如果攻击者能够访问网络，他们也可以利用它来发现并利用这些弱点。

### 创建强密码

提升密码安全性的最佳方法之一是使用*强密码*。强密码更难被攻击者破解。然而，密码破解工具一直在不断改进，进一步武装了攻击者，因此密码需要变得更强才能抵御攻击。

密码破解工具可以在无需事先了解密码的情况下发现弱密码。

构成强密码的两个主要要素是长度和复杂性。微软建议使用至少 14 个字符的密码，并包含多种字符类型，以获得足够的复杂性。表 3-1 展示了强密码的特征。

**表 3-1：** 强密码的特征

| 特征                     | 描述                                                         |
| ------------------------ | ------------------------------------------------------------ |
| 足够长度                 | 微软建议至少 14 个字符。                                     |
| 大小写混合               | 同时使用大写和小写字母。                                     |
| 使用数字                 | 包含 0–9 的数字。                                            |
| 使用特殊字符             | 包含特殊字符，例如 !@#$%^&*()_+。                            |
| 不在字典中               | 密码不应出现在任何语言的字典中。                             |
| 不包含个人信息           | 密码不应包含用户名、家庭成员或宠物的名字，或其他公开信息。   |

如果你使用 5 个字符的密码，可能会认为没人会使用 14 个字符的密码，因为难以记忆。尽管某些组织仍对大多数用户使用 6 或 8 个字符的较短密码，但行业趋势是要求更长的密码。

许多组织要求管理员使用至少 14 个字符的密码。

挑战在于确保用户创建强健、复杂的密码，但又不将密码写下来以便记忆。有一些技巧可用于创建既长又复杂、同时易于记忆的密码。以下练习展示了两种可行方法：

**1.** 从一个包含至少 14 个字符的短语开始。例如，可以使用以下短语之一：

I will be certified

I love technology

**2.** 移除空格，并将每个单词的首字母改为大写：

IWillBeCertified

ILoveTechnology

**3.** 将每个字母 *e* 转换为数字 3：

IWillB3C3rtifi3d

ILov3T3chnology

**4.** 将每个字母 *i* 转换为感叹号 (!)：

!W!llB3C3rtifi3d

!Lov3T3chnology

你可以将任何字母替换为对你有意义的符号或数字。例如，可以将每个字母 a 改为 @，或将每个字母 o 改为 0（零）。

此时，你已拥有一个长度达 14 个字符（或更多）且便于记忆的强密码。你还可以采用其他技巧，例如在密码开头和/或结尾添加数字或符号，或将某些字母替换为符号，比如将每个字母 *s* 替换为 $。

以下再举一例。

**1.** 从一个包含至少 10 个单词的短语入手。例如，可使用如下短语：

I am learning and will become MTA Security Fundamentals certified

**2.** 提取每个单词的首字母：

ialawbmsfc

**3.** 将每隔一个字母改为大写：

IaLaWbMsFc

**4.** 在开头添加一个数字和一个符号，例如 1*：

1*IaLaWbMsFc

**5.** 在末尾添加相同的数字和符号，但顺序颠倒（例如 *1）：

1*IaLaWbMsFc*1

如果有人要求你记住 *1\*IaLaWbMsFc\*1*，你可能会觉得不写下来很难记住。然而，如果你花几分钟时间用此技巧创建密码，则更有可能记住它。此外，如此长度和复杂度的密码，攻击者破解起来需要耗费大量时间和计算资源。

强制实施强密码

在 Windows Server 2008 中，你可以强制实施强密码。主要方法是使用组策略( Group Policy )配置密码策略( Password Policy )。你可以对单台计算机使用本地组策略( Local Group Policy )或本地安全策略( Local Security Policy )，或在域中使用组策略。本地安全策略设置适用于本地计算机上的所有账户，而基于域的组策略设置则适用于整个域中的所有用户账户。

组策略是一种内置工具集，允许你一次性配置设置，然后将这些设置应用于组策略作用域内的所有账户。

本地组策略仅适用于本地计算机，包含数千项设置。在本地组策略中，有一个名为安全设置( Security Settings )的单一节点。如果你只想操作安全设置节点，可以通过启动本地安全策略控制台来访问，本节后续部分将展示具体操作。

| 用可还原的加密来存储密码( Store Passwords Using Reversible Encryption ) | 某些非微软系统要求使用可还原的加密来存储密码。由于攻击者可能利用可还原的加密来发现原始密码，因此不建议启用此设置。 |

部分策略元素可防止用户规避书面密码策略。例如，有些用户可能希望在两套密码之间来回切换。然而，在组策略( Group Policy )的密码策略( Password Policy )部分使用强制密码历史( Enforce Password History )设置即可阻止此行为。

书面安全策略( Security Policy )会明确安全要求，例如使用强密码( Strong Password )。组策略等技术可用于强制执行书面安全策略。

此外，有些用户可能希望连续使用同一密码，以免记忆新密码。他们可能会反复更改密码，试图恢复原始密码。若密码历史( Password History )设置为24，则用户需更改25次才能回到原始密码。尽管这可能需要15到20分钟，但意志坚定的用户仍可能愿意花时间这样做。而最短密码使用期限( Minimum Password Age )设置可阻止最执着的用户，确保至少一天后才能更改密码。结合密码历史为24的设置，用户需要25天才能恢复原始密码。这足以打消大多数用户规避密码策略的念头。

探索帐户锁定策略( Account Lockout Policies )

除配置密码策略外，大多数组织还会配置*帐户锁定策略( Account Lockout Policy )*。帐户锁定策略会在错误密码输入次数过多时锁定帐户。用户无法使用已锁定的帐户成功进行身份验证。

帐户锁定策略有助于防止攻击者通过反复尝试猜测密码来破解帐户。

例如，你可以配置锁定策略，在连续输入三次错误密码后将帐户锁定30分钟。如果攻击者试图猜测密码，他们只能在帐户被锁定前连续尝试少数几次密码。

内置管理员账户( Built-in Administrator Account )不受账户锁定策略( Account Lockout Policy )的约束。换言之，管理员账户永远不会被锁定。

被锁定的账户可由管理员或其他具有相应权限的管理人员解锁。以下部分展示了如何解锁账户。

解锁账户

当账户被锁定时，用户会看到类似以下消息：“引用的账户当前已锁定，无法登录。”只要“账户锁定时间”未设置为 0，用户可以等待该时间过后再尝试登录。或者，他们可以请求管理员解锁账户。

如果“账户锁定时间”设置为 0，则账户将保持锁定，直到管理员将其解锁。

您可以使用以下步骤解锁 Windows 计算机上的本地账户：

**1.** 通过依次单击“开始”、键入 **Computer** 并选择“计算机管理( Computer Management )”来启动计算机管理。

**2.** 展开"系统工具"⇒"本地用户和组"，然后选择"用户"。

**3.** 找到被锁定的用户账户。右键单击该用户账户，选择"属性"。显示界面将类似于图 3-3。

**图 3-3：** 查看本地用户账户的属性

![f0303.tif](./image/Chapter%203%20Understanding%20User%20Authentication/f0303_fmt.webp)

账户被锁定的唯一原因是输入了过多错误密码。管理员可以从图 3-3 所示的界面中禁用账户，但无法手动将其锁定。

**4.** 取消选中"账户已锁定"复选框。单击"确定"。

此时，账户已解锁，用户将能够登录（前提是用户知道正确的密码）。

如果被锁定的账户是域账户，则需要使用 Active Directory 用户和计算机( Active Directory Users and Computers ,ADUC)工具重置该账户。以下步骤展示了此过程：

ADUC 默认安装在已提升为域控制器的服务器上。

**1.** 依次选择"开始"⇒"管理工具"⇒"Active Directory 用户和计算机"，启动 Active Directory 用户和计算机。

**2.** 展开域，选择包含该用户账户的组织单位。

**3.** 右键单击该用户账户，选择"属性"。

**4.** 选择"账户"选项卡。选中"解锁账户"复选框。您将看到类似于图 3-4 的显示界面。

**图 3-4：** 解锁域账户

![f0304.tif](./image/Chapter%203%20Understanding%20User%20Authentication/f0304_fmt.webp)

**5.** 单击"确定"。

此时，账户已解锁，用户将能够登录（前提是他们知道自己的密码）。当然，有时用户可能记不住密码。如果出现这种情况，他们可能需要由管理员重置密码。下一节将介绍如何重置密码。

重置密码

重置密码需要具备管理权限。普通用户账户不具备这些权限。

以下是域内操作步骤：

**1.** 依次选择"开始" ⇒ "管理工具" ⇒ "Active Directory 用户和计算机"，启动 Active Directory 用户和计算机( Active Directory Users and Computers ,ADUC)。

**2.** 展开域，选择包含该用户账户的组织单位( Organizational Unit ,OU)。

**3.** 右键单击该用户账户，找到"重置密码"。显示界面类似于图 3-5。

**4.** 选择"重置密码"。在"新密码"文本框中输入新密码，然后按 Tab 键。

**5.** 在"确认密码"文本框中再次输入新密码。

**6.** 确保选中"用户下次登录时须更改密码"复选框，如图 3-6 所示。

**7.** 如果账户已锁定，还可选中"解锁该用户的账户"复选框。单击"确定"。只要密码匹配且满足复杂性要求，系统将显示密码已更改的确认信息。

**2.** 展开"系统工具"⇒"本地用户和组"，然后选择"用户"。

密码重置与社会工程学攻击

大多数组织会实施密码重置流程以防止社会工程学攻击。其目标是确保只有组织内的用户才能为自己的帐户请求密码重置。

请考虑此类攻击场景。心怀不满的 Joe 知道公司使用个人名字的首字母和姓氏来创建用户帐户。例如，Mark Smith 的帐户是 msmith。如果心怀不满的 Joe 知道某位员工（当时正在短期出差）的姓名，他也就知道了该员工的用户名。接着，他致电帮助台，自称是该员工，并请求重置该帐户的密码。

如果没有相应的流程来验证来电者的身份，心怀不满的 Joe 就能成功获取该用户帐户的新密码，从而登录并冒充该用户。然后，他可以访问该出差员工有权访问的任何资源，并且根据其不满程度，可能造成相当大的破坏。如果他能冒充经理，就可以访问该经理的任何文件，甚至包括其电子邮件。

组织通常要求个人在更改密码前提供身份证明，以防止此类攻击。

更改密码

当系统设置了密码策略( Password Policy )后，用户会在密码最长使用期限( Maximum Password Age )到期前收到更改密码的提醒。用户可通过以下步骤主动更改密码：

以下步骤适用于 Windows Server 2008、Windows Server 2008 R2 及 Windows 7 系统。

**1.** 同时按下 Ctrl+Alt+Delete（三个按键同时按下）。

**2.** 点击“更改密码”。屏幕将显示类似图 3-8的界面。

**图 3-8：** 更改密码

![f0308.tif](./image/Chapter%203%20Understanding%20User%20Authentication/f0308_fmt.webp)

**3.** 在“旧密码”文本框中输入旧密码，然后按 Tab 键。

**4.** 在“新密码”文本框中输入新密码，然后按 Tab 键。

**5.** 在“确认密码”文本框中再次输入新密码，然后按 Enter 键。

系统将根据密码策略检查新密码。若不符合密码策略要求，更改将失败，系统会显示错误信息。

只要旧密码正确、新密码与确认密码输入一致，且新密码符合密码策略的强制要求，密码即可成功更改。

创建密码重置盘

*密码重置盘( Password-Reset Disk )*允许你在忘记原始密码时重置密码。但必须在忘记密码前创建密码重置盘。密码重置盘信息可存储在 USB 闪存盘或软盘上，具体取决于可用设备。

当前大多数系统已不配备软驱，但均提供 USB 端口用于插入 USB 闪存盘。

可通过以下步骤为本地账户( Local Account )创建密码重置盘：

**1.** 将 USB 闪存盘插入系统。该闪存盘将作为密码重置盘。

**2.** 同时按下 Ctrl+Alt+Delete（三个按键同时按下）。

**3.** 点击“更改密码”。

**4.** 点击“创建密码重置盘”链接。

**5.** 查看“欢迎使用忘记密码向导”屏幕上的信息，然后点击“下一步”。

**6.** 在“创建密码重置磁盘”页面上，从下拉列表中选择 USB 驱动器。此列表仅显示可移动磁盘。单击“下一步”。

**7.** 输入当前登录用户的密码，然后单击“下一步”。

**8.** 系统会将一个文件写入此磁盘。当进度条显示 100% 完成时，单击“下一步”。单击“完成”。如果用户忘记密码，此磁盘现在可用作密码重置磁盘。

使用智能卡和令牌设备进行身份验证

到目前为止，我们一直关注密码，这被认为是第一种身份验证方法的一部分：*你所知道的信息( something you know )*。第二种身份验证因素是*你所拥有的物品( something you have )*。对于此方法，用户必须拥有某件物品才能成功进行身份验证。两个常见示例是智能卡( Smart Card )和令牌设备( Token Device )。

*智能卡*是一种信用卡大小的卡片，其中嵌入了证书。它还具有电气触点，当卡片插入智能卡读卡器( Smart-Card Reader )时，可以读取卡片中的数据。图 3-9 展示了一张智能卡和一个智能卡读卡器。

智能卡通常还包含用户信息，例如照片和姓名。

**图 3-9：** 智能卡和智能卡读卡器

![f0309.eps](./image/Chapter%203%20Understanding%20User%20Authentication/f0309_fmt.webp)

智能卡读卡器可以是单独的硬件设备，也可以购买内置智能卡读卡器的系统组件（例如键盘）。

组织需要部署公钥基础结构( Public Key Infrastructure ,PKI)才能有效利用智能卡。PKI 系统包括可颁发和管理证书的证书颁发机构( Certificate Authority ,CA)。每张智能卡至少嵌入一个证书，用户可使用该证书登录或在登录后访问资源。

智能卡很少单独使用。相反，在用户将卡片插入读卡器后，系统会提示他们输入其他信息，例如个人识别码( Personal Identification Number ,PIN)或用户名和密码。

当要求用户同时拥有某件物品（智能卡）和知道某些信息（PIN）时，这种身份验证就使用了多因素身份验证( Multi-Factor Authentication ,MFA)。

令牌设备( Token Device )在要求用户"拥有某物"这一点上类似，但其运作方式略有不同。令牌也被称为*密钥卡( Key Fob )*，可挂在钥匙链上以便携带。请参阅图 3-10。左侧显示的是基于令牌的身份验证服务器，右侧为用户持有的令牌。令牌屏幕上显示的数字会定期变化，例如每 60 秒一次。服务器与令牌相互同步，因此每当令牌中的数字变化时，服务器都会知晓新数字。

**图 3-10：** 用于身份验证的令牌

![f0310.eps](./image/Chapter%203%20Understanding%20User%20Authentication/f0310_fmt.webp)

当用户尝试登录时，需输入令牌上显示的数字以及用户名和密码（或 PIN 码）等附加信息。只要所有信息准确无误（且在令牌数字变化前输入），用户即可成功通过身份验证。

令牌提供了多因素身份验证( Multi-Factor Authentication ,MFA )，因为它同时证明了用户拥有某物（令牌）和知晓某物（用户名和密码，或 PIN 码）。

使用生物特征进行身份验证

生物特征( Biometrics )（*你是谁*）是一种比前述*你知道什么*和*你拥有什么*方法更为安全的身份验证方式。生物特征测量用户的特定物理信息。例如，每个人的指纹都是独一无二的。由于指纹的唯一性，可用于准确验证用户身份。

生物特征身份验证的配置方法是预先采集生物特征样本。这些数据存储在身份验证数据库中，当用户尝试进行身份验证时，数据库信息会与验证尝试进行比对。若数据匹配，则用户成功通过身份验证。

用于身份验证的生物特征方法包括以下内容：

**指纹与掌纹** 许多笔记本电脑配备了指纹读取器，可用于身份验证。部分 USB 闪存盘内置指纹读取器，仅允许已注册指纹的个人访问驱动器中的数据。某些场所使用完整掌纹来验证个人身份。

**视网膜与虹膜** 视网膜扫描是最精确的生物识别方法，通过映射眼球后方的血管结构进行识别。但扫描过程约需10秒，且要求用户将眼睛紧贴扫描仪，同时设备会向眼球投射光线。虹膜扫描则通过识别瞳孔周围的细节特征（如不同色带）进行验证。用户只需距离虹膜扫描仪约20英寸（约50厘米），其侵入性远低于视网膜扫描。

**体重** 部分设施入口会结合体重测量与其他身份验证方式。例如，用户可先进入小型门厅，再通过指纹验证进入下一区域。系统会实时追踪门厅内的总重量，防止多人同时进入。

尽管生物识别验证方法可能比其他方式更精确，但其成本也更高。通常，当组织需要增强身份验证时，会采用多因素身份验证( Multi-Factor Authentication ,MFA)，即结合智能卡或令牌与密码或PIN码的组合使用。

**以管理员身份运行启动应用程序**

许多组织要求管理员使用两个不同的账户。一个账户用于日常常规工作，不具备管理权限或权限。第二个账户拥有提升的（管理）权限。管理员仅在执行管理任务时使用提升权限账户。

IT工作人员在绝大多数时间会以普通用户身份登录。若需执行管理任务，可通过管理权限或管理凭据启动应用程序。例如，用户可通过右键单击项目并选择"以管理员身份运行"来以管理员身份执行许多命令，如图3-11所示。

在早期Windows版本（Windows Server 2008之前）中，"以管理员身份运行"命令被称为"运行方式"。

Windows Server 2008引入了用户账户控制( User Account Control ,UAC)。UAC使用两个逻辑令牌：常规用户令牌和提升的管理员令牌。即使用户以管理员身份登录，操作系统默认也仅授予常规用户令牌的访问权限。若用户尝试执行需要提升权限的任务，UAC可能会提示用户批准管理访问请求。

![f0311.tif](./image/Chapter%203%20Understanding%20User%20Authentication/f0311_fmt.webp)

如果管理员使用普通用户帐户登录，并尝试执行需要提升权限的操作，用户帐户控制( User Account Control ,UAC)仍会介入。但此时，UAC 不会要求用户批准操作，而是提示用户提供具有所需权限的帐户凭据。

双帐户的必要性

组织可能要求管理员使用两个帐户（一个用于日常常规工作，另一个用于管理工作）的原因如下：

**非管理员访问** 如果管理员以管理员身份登录计算机后因紧急事务离开，可能会忘记注销或锁定计算机。此时，路过者便可访问计算机并拥有完全的管理权限。

**意外损坏** 管理员以管理员身份拥有对资源的完全控制权。如果管理员始终以管理员身份登录，则意外损坏的可能性会增加。例如，普通用户可以查看许多配置设置，但无法更改它们；而管理员可能因一次误点击而意外修改设置。

**恶意软件权限提升** 某些恶意软件能够利用已登录用户的权限。如果用户在持有管理凭据登录时威胁成功渗透网络，恶意软件可能获得管理员提升后的权限。然而，如果管理员通常使用普通帐户登录，恶意软件获取提升权限的可能性就会降低。

使用 Kerberos 防止时间偏差

Kerberos 是 Microsoft 域中使用的主要网络身份验证协议。自 Windows 2000 起，它一直是 Active Directory 域的首选身份验证协议。

用户通过 Kerberos 向域完成身份验证后，Kerberos 还会在后台用于确保只有经过身份验证的实体才能访问资源。Kerberos 采用一种系统，其中用户和计算机会获得用于访问资源的票证( Ticket )。密钥分发中心( Key Distribution Center ,KDC)负责管理这些票证。

Kerberos 使用端口 88。在使用 Kerberos 进行基于域的用户身份验证的网络基础结构中，路由器必须允许流量通过端口 88。

Kerberos 的一个重要要求是域内的每个系统必须使用相同的时间。如果任何系统与环境中的域控制器相差超过五分钟，就会产生时间偏差( Time-Skew )错误。时间不正确的系统将被拒绝访问网络资源，用户可能无法完成身份验证。

Kerberos 的五分钟时间要求可防止攻击者拦截数据、修改数据并在稍后时间重放以冒充用户。在五分钟内完成此操作是不可行的。

域内的所有计算机都会同步时间以防止时间偏差错误。以下元素提供时间同步：

- 域内的单个域控制器持有主域控制器( Primary Domain Controller ,PDC)仿真器的操作主控角色。此计算机应配置为定期与外部时间源同步。
- 域内的每个域控制器从 PDC 仿真器获取其时间。
- 域内的每台计算机从其中一个域控制器获取其时间。

如果域计算机的时间有误，重新启动通常可以解决问题。当计算机重新启动时，它会从域控制器更新其时间。

如果用户能够更改其系统的时间，则可能发生问题。因为在 Windows Server 2008 和 Windows 7 系统上更改时间需要提升的权限，所以如今这种情况不太可能发生。

识别 RADIUS 功能

*远程身份验证拨入用户服务( Remote Authentication Dial-in User Service ,RADIUS)* 是一种用于对广泛客户端进行身份验证的身份验证服务。虽然它最初设计用于对使用调制解调器拨入的客户端进行身份验证，但其用途已扩展。

如果组织为远程用户提供通过虚拟专用网络( Virtual Private Network ,VPN)访问网络的权限，RADIUS 可以为这些客户端提供身份验证。RADIUS 作为集中式身份验证点非常有用。例如，如果组织包含 10 台 VPN 服务器，则可以使用单个 RADIUS 服务器为访问这 10 台 VPN 服务器中任意一台的客户端提供身份验证服务。

第 7 章将介绍与 VPN 相关的一些概念。本系列中的《Microsoft Windows 网络基础知识》一书提供了有关 VPN 的更深入信息。

类似地，如果某组织需要支持无线客户端，则 RADIUS 服务器可在客户端获得访问权限之前提供身份验证服务。例如，WPA2 企业版( WPA2 Enterprise )包含一个配置为支持 802.1x 的 RADIUS 服务器。要求无线客户端使用 WPA2 企业版进行身份验证，比仅使用 WPA2 个人版( WPA2 Personal )能提供更高的安全性。

第 8 章将涵盖无线安全问题，包括 WPA/WPA2 企业版和 WPA/WPA2 个人版的使用。WPA/WPA2 个人版不使用 802.1x 服务器。

RADIUS 服务器支持多种不同的协议。图 3-12 展示了 RADIUS 服务器的协议配置界面，下文将对此进行说明：

**可扩展身份验证协议( Extensible Authentication Protocol ,EAP )** EAP 通过扩展操作系统的基本功能来提供额外的身份验证方法。两种内置的 EAP 方法为受保护的 EAP( Protected EAP ,PEAP )和智能卡或其他证书( Smart Card Or Other Certificate )（请参见以下列表项）。

**受保护的 EAP( Protected EAP ,PEAP )** PEAP 使用传输层安全性( Transport Layer Security ,TLS )在设备之间创建加密通道以进行身份验证过程。PEAP 可用于 802.11 无线客户端。

**图 3-12：** RADIUS 身份验证协议

![f0312.eps](./image/Chapter%203%20Understanding%20User%20Authentication/f0312_fmt.webp)

**智能卡或其他证书( Smart Card Or Other Certificate )** 智能卡提供最强的身份验证。智能卡嵌入了由受信任的证书颁发机构( Certification Authority ,CA )颁发的证书，并使用 EAP 与 TLS (EAP-TLS)。第 11 章将更深入地介绍证书和证书颁发机构。

**Microsoft 质询握手身份验证协议 v2 (MS-CHAP v2)** Microsoft 通过 MS-CHAP 改进了 CHAP，随后又通过 MS-CHAPv2 进一步改进。例如，它提供了客户端与身份验证服务器之间的相互身份验证。这仅适用于 Microsoft 客户端。

**质询握手身份验证协议( Challenge Handshake Authentication Protocol ,CHAP )** 此协议提供与非 Microsoft 客户端的兼容性。

**密码身份验证协议( Password Authentication Protocol ,PAP )** 密码以明文形式发送。不建议使用此协议，因为网络嗅探器可以捕获这些密码。

### 识别不安全的身份验证协议

一些较旧的身份验证协议被认为是不安全的，应避免使用。确保这些协议不被使用的第一步是识别它们。以下各节将介绍 LAN Manager (LM) 和新技术 LAN Manager 版本 1 (NTLMv1) 身份验证协议的问题。NTLMv2 优于 LM 和 NTLMv1。

#### LM

LAN Manager (LM) 是一种非常古老的身份验证协议，至今仍被某些应用程序使用。LM 最大的弱点在于其密码存储方式。LM 存储的密码很容易被黑客工具破解。

LM 首先将密码转换为全部大写，然后添加空值将密码扩展为 14 个字符。例如，如果密码是 8 个字符，LM 会添加 6 个空值。然后 LM 将密码拆分为两个 7 字符片段。最后，它使用弱加密方法来保护这两个 7 字符片段，并将结果存储为 LM 哈希。由于结果实际上是两个 7 字符片段，密码破解工具无需破解整个密码，只需分别破解每个 7 字符片段即可。由于使用的加密方法较弱，破解 LM 密码非常容易。

长度超过 14 个字符的密码无法存储为 LM 哈希。某些密码策略要求使用 15 个字符的密码以防止此漏洞。

Windows Server 2008 和 Windows Server 2008 R2 包含对 LM 的支持，但默认情况下处于禁用状态。

#### NTLM (NTLMv1)

新技术 LAN Manager (NTLM 或 NTLMv1) 安全协议是在 Windows 2000 之前引入的，用于身份验证。尽管 NTLM 改进了 LM 的安全问题，但微软不建议在任何应用程序中使用它。

第 10 章将介绍 AES 和其他加密方法。

例如，NTLM 不提供相互身份验证。换句话说，客户端需要向服务器进行身份验证，但客户端不会收到服务器身份的验证。此外，NTLM 不支持许多当前的加密方法，例如用于加密的高级加密标准( Advanced Encryption Standard ,AES)。

某些密码破解工具（如 Ophcrack）可以破解受 NTLM 保护的密码。NTLM 将密码存储为 NTLM 哈希。尽管 NTLM 哈希比 LM 哈希更复杂，但仍可被破解。

在 Windows Server 2008 和 Windows Vista 中，NTLM 默认启用，以保持与旧版客户端的向后兼容性。

NTLM 中发现了其他缺陷，微软已发布更新来修复这些问题。例如，微软安全公告 MS10-012（**[www.microsoft.com/technet/security/bulletin/ms10-012.mspx](http://www.microsoft.com/technet/security/bulletin/ms10-012.mspx)**）记录了 NTLM 中发现的若干缺陷，并概述了解决这些缺陷所需的更新。

NTLMv2 是 NTLMv1 的升级版本。它提供相互身份验证( Mutual Authentication )，并在 Windows Server 2008 系统中默认启用。如果组织中没有使用 NTLMv1 的旧版客户端，建议禁用 NTLMv1。

NTLMv2 比 NTLMv1 更安全，建议使用它替代 NTLMv1。

基础知识与扩展

在本章中，你学习了身份验证的三个要素：所知信息（如密码）、持有物品（如智能卡( Smart Card )）以及固有特征（通过生物识别( Biometrics )验证）。你可以单独使用任一要素，或组合两个及以上要素实现多因素身份验证( Multi-Factor Authentication ,MFA)。密码最佳实践可通过密码策略( Password Policy )强制执行，而账户锁定策略( Account Lockout Policy )可阻止他人猜测密码。大多数组织要求管理员使用两个账户，并在需要时通过“以管理员身份运行”( Run As Administrator )功能启动具有管理权限的应用程序。Kerberos 是微软域中主要的网络身份验证协议( Network Authentication Protocol )，它要求所有计算机的时钟设置彼此相差不超过五分钟。RADIUS 可用于 VPN，并在配置为 802.1x 服务器时对有线及无线客户端进行身份验证。LM 不安全，不应启用。NTLMv2 比 NTLM 更强大；在可能的情况下，应禁用 NTLM。

## 第4章 使用权限保护访问安全

**权限是限制** Microsoft 域中资源访问的主要方法。你可以为新技术文件系统( New Technology File System ,NTFS)驱动器、共享、Active Directory 对象和注册表分配权限。

不同资源的许多权限概念是相同的。例如，每个权限都可以配置为允许( Allow )或拒绝( Deny )，如果分配了拒绝权限，则拒绝始终优先。同样，所有权限都可以分配给父对象，并由所有子对象继承。对于 NTFS 文件夹和共享，子对象是文件或子文件夹，但 Active Directory 和注册表也包含子对象。本章在以下主题中介绍这些概念：

- 比较 NTFS 权限
- 探索共享权限
- 识别 Active Directory 权限
- 分配注册表权限

### 比较 NTFS 权限

Microsoft 环境中使用的几乎所有驱动器都使用新技术文件系统( New Technology File System ,NTFS)。NTFS 管理驱动器上的文件，帮助维护文件完整性，并提供安全性。

NTFS 最重要的优势之一是安全性。你可以通过使用权限限制对 NTFS 驱动器上任何文件的访问。本节中的主题介绍不同类型的权限及其交互方式。

许多应用程序支持扩展属性。如果文件包含扩展属性，其属性页面将显示"详细信息"选项卡（如图4-4中"安全"选项卡旁所示）。例如，Microsoft Word 会包含作者、最后保存者、最后打印时间以及文档的字符数、单词数和页数等信息。若用户拥有此权限，则可读取这些扩展属性。

#### 组合权限

你可以为任何文件或文件夹向用户或组分配权限。大多数组织通过组来管理权限，因为这样能大幅简化管理工作。

例如，某组织财务部门有三名员工。每位员工需要对预算数据拥有完全控制权限、对薪资数据拥有读取权限、对员工数据拥有修改权限。你可以单独分配这些权限，但更简便的做法是将用户放入一个组，然后向该组分配权限，如图 4-5 所示。

大多数组织使用组来简化管理。

用户可属于多个组。此外，用户可能属于被分配了不同权限的不同组。在这种情况下，用户将获得所有权限的累积总和。

例如，假设某用户同时是财务组( Finance group )和财务经理组( FinanceManagers group )的成员。若财务组对某文件夹拥有读取权限，而财务经理组对同一文件夹拥有写入权限，则该用户将同时获得对该文件夹的读取和写入权限。

**图 4-5：** 使用组来分配权限

![f0405.eps](./image/Chapter%204%20Securing%20Access%20with%20Permissions/f0405_fmt.webp)

当分配了多项权限时，用户将获得所有这些权限的组合。

一个重要的例外情况（前文已提及）是：如果任何权限被设置为“拒绝”，则用户将被拒绝访问。换言之，如果某用户因属于某个组而被允许对文件拥有读取权限，但同时又因属于另一个组而被拒绝读取权限，则“拒绝”权限优先。该用户将无法读取文件中的数据。

拒绝权限始终优先。不过，建议谨慎使用拒绝权限。

权限可以被显式拒绝或隐式拒绝。当选中“拒绝”复选框时，权限被显式拒绝。然而，如果某项权限未被授予，结果相同，访问同样被拒绝。

例如，假设管理员组( Administrators group )（且仅此组）被授予对某文件的读取权限。任何不属于管理员组的用户都没有读取该文件的权限。非管理员的访问被隐式拒绝。当权限被隐式拒绝时，无需再显式拒绝它们。

#### 启用和禁用权限继承

权限可以从文件夹继承到文件，以及继承到文件夹内的子文件夹。对于 NTFS 驱动器，继承默认是启用的，但你可以禁用它。首先，理解继承的工作原理很重要。

在驱动器级别分配的权限会被该驱动器上的所有根文件夹继承。

继承机制可减少管理工作量。为文件夹分配权限后，无需在每次添加文件或文件夹时都进行调整。父文件夹的权限会自动被子对象继承。然而，有时可能需要禁用继承。例如，若要修改继承的权限，必须先禁用继承。尝试禁用继承时，系统会提供三个选项：

1. **复制** ：所有继承的权限都会被复制并直接应用于该对象。但由于这些权限现在是直接应用的，因此不再显示为灰色，并且可以修改。
2. **删除** ：所有继承的权限都会被删除。此操作仅影响继承的权限。换言之，如果某个用户或组被直接分配了文件夹或文件的权限，这些权限不会被删除。删除继承权限时，任何显式分配给对象的权限都将保留。
3. **取消** ：取消禁用继承的请求，不进行任何更改。

#### 移动和复制文件

了解移动或复制文件或文件夹时，显式分配的文件和文件夹权限会发生什么变化非常重要。你可以记住两条简单规则，它们能说明权限的变化情况：

- 如果在同一分区内移动文件，则显式分配的权限会保留。
- 在其他任何情况下，权限将从新位置继承，原始权限将丢失。

在同一分区内移动文件时，权限会保留。在其他任何情况下移动或复制文件时，原始权限都会丢失。

在考虑这两条规则时，理解分区的含义很重要。你在 Windows 资源管理器( Windows Explorer )中看到的任何驱动器号（如 C: 或 D:）都是一个分区。

不同的驱动器号表示不同的分区。

物理驱动器可以包含单个分区（如 C:），但也可以划分为多个分区（如 C: 和 D:）。如果看到两个驱动器号（如 C: 和 D:），说明存在两个分区；但这可能是两个物理驱动器（各含一个分区），也可能是一个物理驱动器划分为两个分区。在判断权限变化时，无需关心文件移动或复制是否发生在同一物理驱动器上，但必须明确是否跨不同分区。

### 比较 NTFS 与 FAT

FAT 文件系统( File Allocation Table ,FAT)用于管理不同类型媒体上的文件。FAT32 是当前版本，它使用 32 位来寻址驱动器上的文件。FAT32 通常用于 USB 闪存盘以及数码相机等小型设备中使用的存储卡。几乎所有操作系统（包括 Microsoft 和非 Microsoft）都支持 FAT32。

FAT32 驱动器不支持本地权限。无法通过向其分配 NTFS 权限来保护任何文件或文件夹。==如果将任何文件或文件夹从 NTFS 驱动器复制到 FAT32 驱动器，所有权限都将丢失。==

FAT 最大的局限性在于缺乏安全性。

FAT32 的另一个限制是不支持 4 GB 或更大的文件大小。如果尝试将大于 4 GB 的文件复制到 FAT32 系统，系统将提示错误，指示空间不足。即使将 4 GB 的文件复制到空的 8 GB USB 闪存盘，也会收到此错误。这并非空间不足，而是 FAT32 无法处理大文件。

使用 FAT32 时，无法将大于 4 GB 的文件复制到 USB 闪存盘。

可以将 FAT32 驱动器重新格式化为 NTFS 驱动器。可以通过 Windows 资源管理器( Windows Explorer )，右键单击驱动器并选择“格式化”来完成此操作。但请注意，这样做将删除驱动器上的所有数据。

### 识别共享权限

**任何共享都只有三种共享权限。这些权限在用户通过网络访问共享时适用，但在用户从本地文件系统访问 NTFS 文件夹或文件时不适用。共享权限仅在用户通过网络访问共享时生效。**

共享权限与 NTFS 权限相互交互。下一节将解释其工作原理。不过，在本节中，假设用户从 FAT 卷访问共享，且该卷没有任何 NTFS 权限。此时，当您分配以下三种共享权限之一时，通过网络访问共享的用户仅受共享权限约束：

您无法向文件分配共享权限。您将权限分配给共享，共享内的所有文件和文件夹将继承这些权限。

**读取( Read )** 拥有此权限的用户可以读取共享内的任何文件或文件夹。

**更改( Change )** 更改权限允许用户读取、写入、修改和删除共享内的文件和文件夹。这实际上等同于 NTFS 的修改( Modify )权限。

**完全控制( Full Control )** 拥有完全控制权限的用户可以对共享内的文件和文件夹执行任何操作，包括更改底层权限。

共享权限不会取代 NTFS 权限。相反，共享权限与 NTFS 权限相互交互。

还可以使用共享角色( Share Roles )分配权限。在 Windows Server 2008 和 Windows Server 2008 R2 中，权限级别名称存在细微差异。Windows Server 2008 使用角色名称标识权限级别，而 Windows Server 2008 R2 则使用权限名称标识权限级别。表 4-4 列出了不同的名称及其授予的权限。

### 识别 Active Directory 权限

Active Directory 是一个对象数据库。例如，它包含用户对象( User Object )以表示用户，计算机对象( Computer Object )以表示计算机，以及组对象( Group Object )以表示组。这些对象在 Active Directory 中通过组织单位( Organizational Unit ,OU)和简单容器（如用户和计算机容器）进行组织。

Active Directory 托管在域控制器( Domain Controller )上，域控制器是运行 Active Directory 域服务( Active Directory Domain Services ,AD DS)的服务器。

例如，组织可以为不同部门创建不同的 OU。它可以为销售部门、IT 部门、财务部门等分别创建 OU。每个部门的所有用户和计算机对象都放置在相应的 OU 中。

您可以修改这些 OU 的权限，以授予特定用户或组管理 OU 中对象的权限。例如，技术支持人员( Help Desk )可能需要修改销售 OU 中的对象，例如重置用户密码。您可以授予他们对销售 OU 的相应权限，以执行相关任务。

比较 NTFS 与 Active Directory 权限

若你了解 NTFS 权限的工作原理，那么对 Active Directory 权限的工作原理也已掌握大半。具体而言，以下概念是相同的：

**权限是累积的** 如果用户作为多个组的成员被分配了权限，则该用户拥有所有权限的累积结果。

**拒绝优先** 如果同一权限同时被授予和拒绝给用户，则拒绝优先。用户将不具有该权限。

**权限是可继承的** 分配给 OU 或容器的权限会被该容器或 OU 中的所有对象继承。这包括子 OU，类似于文件夹中的子文件夹。

**可禁用继承** 尽管继承默认启用，但你可以禁用它。在 ADUC 和 NTFS 中，相关界面和过程几乎完全相同。

以 Active Directory 中的继承为例，请参考图 4-12（如前所示）。如果为名为 SalesAdmins 的组授予对 Sales OU 的完全控制( Full Control )权限，则该组也将对 Main Office、North Region 和 South Region OU 拥有完全控制权限。

查看 Active Directory 权限

在 ADUC 中，默认情况下权限不可见。但可以轻松启用它们。在 ADUC 中，从“查看”下拉菜单中选择“高级功能”。随后对象将显示“安全”选项卡。右键单击任意对象，选择“属性”，再选择“安全”选项卡，即可查看该对象在 ADUC 中的权限。

图 4-13 显示了 Sales OU 的权限。在该图中，可以看到 SalesAdmins 组已被授予对 Sales OU 的完全控制权限。SalesAdmins 组通常包含为销售部门人员提供日常支持的个人。

分配给一个 OU 的权限不会由同级 OU 继承。例如，即使 SalesAdmins 组对 Sales OU 拥有完全控制权限，组成员也不会对 IT OU 或 Human Resources OU 拥有完全控制权限。

继承仅从父容器传递到子容器。

Active Directory 权限如下：

**完全控制( Full Control )** 顾名思义，允许用户对对象执行任何操作。

**读取( Read )** 拥有读取权限的用户可以查看对象，包括对象的属性。

**写入( Write )** 拥有写入权限的用户可以修改对象的任何属性。这包括重命名用户帐户和重置用户密码。

**创建所有子对象( Create All Child Objects )** 允许用户在容器内创建对象。例如，用户可以创建其他用户、计算机、组，甚至子 OU。

**删除所有子对象( Delete All Child Objects )** 拥有此权限的用户可以删除容器内的任何对象。

**生成结果集( Generate Resultant Set of Policy ,RSoP)（日志记录）** 允许用户使用组策略工具，精确确定当特定用户登录到特定计算机时，哪些组策略设置会应用于该用户。用户必须至少登录过该计算机一次，此功能才能生效。

**生成结果集( Generate Resultant Set of Policy ,RSoP)（规划）** 允许用户提出“假设”场景，并确定最终的组策略设置。例如，用户可以确定来自一个组织单位( Organizational Unit ,OU)的用户登录到另一个组织单位( OU )中的计算机时的设置。

正如 NTFS 同时拥有基本权限和高级权限，Active Directory 也拥有基本权限和高级权限。然而，如前所述，NTFS 仅有 13 个高级权限。而 Active Directory 拥有成百上千个高级权限。幸运的是，您无需全部掌握。

相反，您可以在必要时使用“控制委派向导( Delegation of Control Wizard )”来为常见任务分配高级权限。例如，如果您希望允许技术支持人员重置“销售”组织单位( OU )中用户帐户的密码，可以使用“控制委派向导( Delegation of Control Wizard )”来完成。启动该向导的方法是：右键单击您要分配权限的容器。

注册表( Registry )是 Windows 中使用的设置数据库。它包含多个不同的设置组，称为*项( Keys )*或*配置单元( Hives )*。Windows Server 2008 包含以下可通过注册表编辑器访问的项。每个项都包含许多子项( Subkeys )或子树( Subtrees )：

可通过单击“开始”，在“开始搜索”文本框中键入 **regedit**，然后按 Enter 键来启动注册表编辑器。

**HKEY_CURRENT_USER** 也称为 HKCU，此配置单元存储本地系统上已登录用户的用户配置文件。配置文件包括环境变量、桌面设置、打印机等信息。

**HKEY_CURRENT_CONFIG** 也称为 HKCC，此配置单元存储用于启动系统的硬件配置文件中的信息。

**HKEY_CLASSES_ROOT** 也称为 HKCR，此配置单元包含应用程序和文件关联的信息。此配置单元中的数据源自 HKLM\Software\Classes 和 HKCU\Software Classes 中存储的信息。如果两处均存储了数据，则 HKCU 值优先。

要点与扩展

本章介绍了可分配给 NTFS 驱动器、共享文件夹、Active Directory 和注册表的权限。这些权限具有许多共同特征。若用户被分配了多项权限，最终生效的权限是所有已分配权限的组合，除非用户被明确拒绝某项权限。"拒绝"始终具有最高优先级，因此若用户同时被授予同一权限的"允许"和"拒绝"，则最终结果为"拒绝"。默认情况下权限可被继承（注册表除外），但您也可以禁用继承。注册表支持启用继承。移动或复制文件时，若在同一分区内移动文件，NTFS 权限保持不变；其他情况（例如在同一分区内复制，或跨分区移动/复制），权限将从新位置继承。FAT 驱动器完全不支持权限；移至 FAT 驱动器的文件将丢失其权限。共享权限仅在用户通过网络访问共享时生效。当组合使用共享权限和 NTFS 权限时，最终权限取两者组合结果中更严格的限制。Active Directory 用户和计算机工具包含"控制委派向导"，可用于向组织单位( Organizational Unit ,OU)分配权限。

## 第5章 使用审核策略与网络审核

**审核为管理员提供了一种**跟踪系统活动的简便方法。您可以跟踪用户何时访问文件、关闭系统、创建或修改帐户等操作。Windows Server 2008 包含九个独立的审核类别可供操作。

尽管 Windows Server 2008 默认审核许多事件，但这些事件可能不足以满足组织的需求。了解可以审核哪些内容以及如何为不同事件启用审核至关重要。当然，启用审核后，您还需要知道如何查看已审核的事件。例如，Microsoft Windows 将可审核事件记录在安全日志中，您可以使用事件查看器( Event Viewer )查看它们。

Microsoft 基准安全分析器( Microsoft Baseline Security Analyzer ,MBSA)提供了另一种类型的审核。它允许您审核网络中的计算机是否存在各种漏洞。这是一个免费工具，您可以下载并安装在网络中的单个系统上。然后，您可以使用它对网络上运行的其他 Windows 系统执行基本漏洞扫描，并根据已知安全漏洞审核其合规性。本章在以下部分涵盖所有这些主题：

- 探索审核策略
- 启用审核
- 查看审核信息
- 管理安全日志
- 使用 MBSA 审核网络

### 探索审核策略

安全操作系统需要能够识别单个用户、根据其身份授予访问权限并跟踪其操作。这始于实施体现*安全三A( AAA )*的实践：身份验证( Authentication )、授权( Authorization )和记账( Accounting )。图5-1展示了它们如何结合以在组织内实现可靠的问责制。

安全三A指的是身份验证、授权和记账。它们共同提供问责制。

**图5-1：** 安全三A

![f0501.eps](./image/Chapter%205%20Using%20Audit%20Policies%20and%20Network%20Auditing/f0501_fmt.webp)

当用户尝试访问系统时，第一步是确保用户证明其身份或通过系统进行身份验证。第3章“理解用户身份验证”介绍了身份验证的三大要素。第4章“使用权限保护访问”讲解了权限如何为不同资源提供授权。在本章中，你将学习*审核*如何跟踪用户活动并提供记账功能。

可靠的问责制还提供了*不可否认性( Nonrepudiation )*。简而言之，不可否认性可防止某人否认其执行过某项操作。日志记录将事件记录在*审核日志( Audit Log )*中，例如谁执行了操作、执行了什么操作以及何时执行。如果用户的操作被记录，该用户便无法否认执行过该操作，因此日志提供了不可否认性。

数字签名( Digital Signature )也为电子邮件提供了不可否认性。第10章将介绍数字签名。

在 Microsoft Windows 环境中实现记账功能相对容易。你可以使用组策略( Group Policy )为整个域启用审核策略( Audit Policy )，或使用本地安全策略( Local Security Policy )为单个服务器启用。

如您所见，可以同时启用成功事件和失败事件的审核。例如，图5-2显示已为对象访问( Object Access )启用了成功和失败事件。如果为某个文件夹启用完全对象访问审核，当有人删除该文件夹中的文件时，系统会在安全日志中创建一条记录，包含用户和文件的详细信息。如果有人试图删除同一文件但无权限，安全日志中会生成一条失败事件，同样显示相关用户和文件信息，表明有人尝试了未经授权的操作。

为何监控失败事件？

失败事件并不代表实际变更，但许多组织仍会监控它们。其主要优势在于，记录的失败尝试可揭示潜在的恶意活动。

例如，普通用户除非有特定需求，否则无权访问公司专有数据。但如果日志显示某用户反复尝试访问这些数据，则可能引发警报。有必要调查该用户为何试图访问这些数据。

当然，也可能是用户因工作需要或执行特定功能而需访问权限。但在此情况下，用户通常会告知他人自己遇到困难，并向IT部门提交修改权限的请求。

启用这些安全审核设置相对简单。挑战在于，在启用前需先仔细规划审核目标。如果启用所有审核，日志将被无关细节淹没，消耗系统资源，且难以识别关键事件。反之，若启用不足，则无法记录重要事件。

尽管大多数系统的安全需求相似，但域控制器( Domain Controller )存储了所有用户帐户和密码，因此需要更高的安全性，这包括对审核( Auditing )的安全要求。表5-1介绍了适用于所有服务器的设置。表5-2介绍了仅适用于域控制器的设置。这些表格列出了这些设置的默认行为( Default Behavior )。默认行为与默认设置( Default Setting )并非同一概念。首次安装 Windows Server 2008 时，查看这些设置会发现它们均配置为“无审核( No Auditing )”。然而，根据每个设置的默认行为，审核仍然会发生。

比较账户登录( Account Logon )和登录事件( Logon Events )

两个账户策略审核设置包含单词*logon*，这常常让人混淆。这两个设置是审核账户登录事件( Audit Account Logon Events )和审核登录事件( Audit Logon Events )：

账户登录( Account Logon )和登录( Logon )审核的默认行为是记录成功( Success )事件。

**账户登录( Account Logon )** 此设置在用户或计算机使用Active Directory账户进行身份验证（或尝试身份验证）时创建一个事件。

**登录** 此设置会在用户本地登录（也称为*交互式*登录）到计算机或通过网络（远程）登录时生成事件。例如，用户使用计算机上的本地账户（而非域账户）登录计算机时，即为登录事件。再如，用户通过网络访问共享时，会在托管该共享的服务器上记录为登录事件。

账户登录事件仅适用于域控制器。登录事件可在任何服务器上记录。

请注意，账户登录事件仅针对 Active Directory 身份验证。每当用户或计算机使用域账户登录时，如果启用了审核，则审核会生成账户登录事件。

另一方面，当用户在本地 Windows 服务器上拥有账户时，他们不会通过 Active Directory 进行身份验证。相反，本地计算机的安全账户管理器( Security Account Manager ,SAM)数据库会对用户进行身份验证。如果启用了审核，则此操作会记录为登录事件。

域控制器托管 Active Directory，且没有本地 SAM。

每当用户通过网络访问资源（例如访问共享文件夹或共享打印机）时，也会生成登录事件。例如，假设在名为 Server1 的服务器上启用了登录事件，并且该服务器使用名为 Projects 的共享来共享文件夹。如果 Sally 访问该共享，则会在 Server1 上记录一个登录事件。在这种情况下，无论 Server1 是成员服务器还是域控制器，该事件都会记录为登录事件。此外，无论 Sally 使用的是哪种类型的用户账户（本地账户或域账户），都会根据她使用的账户记录其访问。

探索目录服务访问审核

目录服务访问审核允许因对 Active Directory 对象的任何访问而生成审核日志。提醒一下，Active Directory 是一个大型对象数据库，包含用户、计算机、组和组织单位( Organizational Unit ,OU)等。如果服务器不是域控制器，则它不托管 Active Directory，此设置不适用。

目录服务访问审核的默认行为是在域控制器上记录成功事件。它不适用于成员服务器或客户端。

目录服务访问审核( Directory Service Access Auditing )与对象访问审核( Object Access Auditing )类似，均需在两个位置启用。首先，必须在审核策略( Audit Policy )设置中启用审核功能。其次，必须在 Active Directory 中针对要跟踪的特定对象启用审核。

默认情况下，这些目录服务访问事件难以解读。例如，条目不会使用名称标识对 Active Directory 进行修改的用户，而是使用全局唯一标识符( Globally Unique Identifier ,GUID )来标识对象和属性。举例来说，如果 Sally 修改了 Bob 账户的密码，条目会将 Bob 的账户标识为 {bf967a9c-0de6-11d0-a285-00aa003049e2}，即代表 Bob 用户账户 GUID 的标识符。

虽然可以确定 GUID 所标识的对象，但这样做需要耗费一定的时间和精力。

不过，Windows Server 2008 通过 Active Directory 域服务( Active Directory Domain Services ,AD DS )审核引入了新的审核功能。如果启用了增强功能，系统会按名称列出被修改的账户，同时包含更多易于解读的详细信息。要启用高级功能，可在域控制器上以管理权限在命令提示符下输入以下命令：

以管理权限启动命令提示符的方法是：在“开始”菜单中右键单击“命令提示符”，然后选择“以管理员身份运行”。



```
auditpol /set /subcategory:"directory service changes"
/success:enable /failure:enable
```



可以使用 auditpol 命令修改审核策略的默认行为。上述语法展示了如何修改目录服务访问审核，但该命令的用途远不止于此。Microsoft TechNet 包含多个相关网页，如需了解可从此处开始：

**http://technet.microsoft.com/library/cc731451.aspx**

如果需要，可以通过包含 /success:enable 但不包含 /failure:enable 来仅启用成功事件。同样，通过包含 /failure:enable 但不包含 /success:enable 可仅启用失败事件。如果后续决定关闭附加审核，可将 enable 改为 disable，如下命令所示：



```
auditpol /set /subcategory:"directory service changes"
/success:disable /failure:disable
```



了解账户管理审核( Account Management Auditing )

账户管理审核用于跟踪系统上对账户和组的修改。在本地系统上启用时，它会跟踪对本地 SAM 账户数据库的更改。在域控制器上启用时，它会跟踪对 Active Directory 中账户的更改。

账户管理( Account Management )审核的默认行为是在域控制器上记录成功( Success )事件。

账户管理审核会跟踪以下对象的事件：

**用户账户( User Accounts )** 所有对用户账户的添加、删除和修改操作均被跟踪。

**组( Groups )** 所有对组的添加、删除和修改操作均被跟踪。

**计算机账户( Computer Accounts )** 所有对用户账户的添加、删除和修改操作均被跟踪。

计算机账户仅存在于 Active Directory 中。无法将计算机账户添加到本地 SAM。

了解系统事件( System Events )审核

系统事件审核会跟踪多种系统事件，例如系统关闭或重启。它还会跟踪任何影响安全日志( Security log )的操作。

系统事件审核的默认行为是在域控制器上记录成功事件。

安全日志存储所有审核数据。如果用户能够清除这些条目，数据可能会丢失，并且可能没有之前活动的记录。攻击者深知这一点，并意识到如果能够清除日志，就能抹去其活动痕迹。清除日志会删除所有日志条目，但日志会继续记录新条目。然而，系统事件审核会记录日志被清除的事件，包括清除者及清除时间。此条目会在日志清除后包含在日志中。

事件 ID 1102 表示审核日志被清除。了解事件 ID 编号有助于在日志中搜索特定事件。“查看审核信息”部分将介绍具体方法。

因此，许多组织都制定了定期存档日志并清除日志的流程。例如，管理员可能每周三审查并存档日志。如果审核日志显示在其他日期被清除，则表明可能存在潜在问题；攻击者可能试图清除日志以掩盖其行为。

如果使用了事件订阅( Event Subscriptions )，则整个日志不会丢失。事件订阅可将事件从一台服务器转发到另一台服务器。本章后面的“保存审核信息”部分将详细介绍事件订阅。

监控重启的重要性

每次系统关闭时，其安全事件极易处于无人监控状态。由于审核由操作系统管理，当操作系统未运行时不会进行任何审核。然而，攻击者无需启动操作系统即可实施大量操作。

例如，市面上存在多种可引导磁盘，可用于启动系统。攻击者可能制作可引导 USB 或 DVD，并以此介质引导服务器。根据可引导介质中包含的操作系统，此人可能访问系统上的所有数据。若攻击者实施此操作，只需将所有感兴趣的数据复制到便携式 USB 驱动器，甚至刻录 DVD（取决于可用资源）即可。

这并非意味着每次服务器重启都代表攻击，但计划外重启可能值得调查。

了解特权使用审核( Privilege Use Auditing )

特权使用审核记录用户行使特定权限( Right )的情况。权限是指系统允许用户执行的操作。例如，用户可能拥有更改系统时间或关闭系统的权限。若启用特权使用审核，当用户执行此类操作时，事件将被记录在安全日志( Security Log )中。

特权使用审核的默认行为是不进行审核。

本地安全策略( Local Security Policy )中的“用户权限分配( User Rights Assignment )”节点标识了用户权限。图 5-5 展示了部分列表。请注意，这些用户权限列在“审核策略( Audit Policy )”节点下方。

- 绕过遍历检查( Bypass Traverse Checking )
- 调试程序( Debug Programs )

了解策略更改审核( Policy Change Auditing )

策略更改审核记录对策略的更改。这包括对审核策略、用户权限分配策略和信任策略( Trust Policy )的任何更改。例如，事件 ID 4704 表示已分配用户权限，事件 ID 4719 表示审核策略已更改。

策略更改事件的默认行为是在域控制器( Domain Controller )上记录成功( Success )事件。

了解进程跟踪( Process Tracking )

进程跟踪( Process Tracking )在排查应用程序问题时非常有用。它会记录与程序、应用程序和进程相关的事件。这可能是管理员使用最少的审核设置。另一方面，开发人员在调试应用程序时，往往会发现此设置的价值。

进程跟踪事件的默认行为是不进行审核。

查看审核信息

审核事件和信息存储在事件查看器( Event Viewer )的安全日志( Security log )中，并可通过该工具查看。安全日志的一个挑战是可能变得非常庞大。不过，你可以搜索特定事件，而无需手动浏览整个日志。

管理安全日志

安全日志需要执行一些基本的管理维护任务。如果要保留日志，则需要定期保存或存档。此外，您可能还需要调整日志的最大大小，并指示是否应覆盖较旧的事件。

例如，图5-11 显示了安全日志的属性页面。该图显示日志文件的大小已配置为 131072 KB（约 130 MB）。

**图5-11：** 查看安全日志属性

![f0511.tif](./image/Chapter%205%20Using%20Audit%20Policies%20and%20Network%20Auditing/f0511_fmt.webp)

图5-11 显示了安全日志的默认设置。如果未进行管理，日志不会填满硬盘，而是在达到最大大小时覆盖事件。

当日志填满时，您有三个选项。每个选项都有其权衡：

**按需覆盖事件（最旧的事件优先）** 如果从不清除日志，此选项可确保硬盘永远不会填满。但是，较旧的已记录事件会丢失。这是默认设置。

**日志满时存档，不覆盖事件** 此设置会自动创建日志的存档并清除正在运行的日志。如果未从服务器中删除存档的日志，这些日志将消耗硬盘空间。

**不要覆盖事件（手动清除日志）** 此选项会在日志已满时停止记录事件，较新的活动不会被记录。启用此设置后，攻击者可能通过生成无害活动填满日志，然后执行未记录在内的恶意活动。

最佳做法是通过定期存档和清除日志来管理这些日志，无论是手动操作还是通过自动化流程。同时，最好将日志的最大大小设置为远超正常需求的值。例如，如果日志在一周内通常增长到 10 MB，可以将最大大小设置为 100 MB。这样，即使发生恶意活动，也能确保其被记录。

**保存审核信息**

如果安全是关注重点，应定期存档审核日志。否则，将无法保留随时间推移发生的事件记录。审核可能仍在进行，但事件会被定期覆盖。

在事件查看器( Event Viewer )中，右键单击安全日志并选择“清除日志”，即可保存该日志。系统会提示为日志命名并保存到任意位置。随后，可将保存的日志复制到其他服务器，或纳入服务器的备份计划。

Windows Server 2008 提供了一项强大功能：通过事件订阅( Event Subscription )将事件转发到其他系统。例如，若需管理三台文件服务器，可配置事件订阅，将这些计算机的事件转发到单台计算机。这样，只需监控一台计算机上的事件，而无需逐一检查所有计算机。

图 5-12 展示了事件订阅的工作原理。事件首先记录在一台或多台源计算机( Source Computer )上，然后转发到收集器计算机( Collector Computer )。在收集器计算机的事件查看器中，可在 Windows 日志的“转发事件”部分查看这些事件。

可以调整事件转发的频率。例如，可将订阅配置为每 10 分钟转发一次事件。

**图 5-12：** 使用事件订阅

![f0512.eps](./image/Chapter%205%20Using%20Audit%20Policies%20and%20Network%20Auditing/f0512_fmt.webp)

事件订阅的一个优势在于，它会自动创建日志的存档。源计算机保留原始日志。事件转发后，收集器计算机会保存事件的另一份副本。

管理员通过从命令行执行 **winrm qc** 命令，在源计算机和收集器计算机上启用 Windows 远程管理( Windows Remote Management ,WinRM)，以实现事件订阅。

保护审核信息

如果确保审核日志在需要时可用且保持原始形式至关重要，则必须对其进行保护。你可以采取多种措施来保护审核日志，具体措施取决于日志的长期价值。

以下列表列举了保护审核日志的一些常见措施：

**创建备份** 日志备份是可在必要时还原的副本。如果已存档日志，则可将日志位置纳入服务器的常规备份计划中。

务必注意，仅清除和存档日志并不会创建备份。如果存储存档的硬盘驱动器发生故障，存档日志将丢失。

**将日志存储在其他服务器上** 存储在其他服务器（例如通过事件订阅）上的日志提供了可在需要时访问的副本。你还可以从其他服务器备份这些日志。

**将日志存储在一次性写入介质上** 例如，可以使用一次性写入多次读取( Write Once Read Many ,WORM) DVD。目标是确保历史日志文件不会被重写。

**使用权限保护日志** 确保只有授权人员才能访问日志。访问存档日志的权限可能比查看原始日志的权限更为严格。

**对存档文件启用审核** 可以通过对日志文件启用审核来跟踪对存档日志的任何访问。这会记录对日志的所有访问和修改。

某些法律要求采取极端措施来保护审核日志。例如，核设施需要对关键数据进行详细审核。所有访问均被记录，且日志保存多年。尽管上述示例提供了一些保护日志的思路，但这些方法并非适用于所有情况。

使用 MBSA 审核网络

Microsoft 基准安全分析器( Microsoft Baseline Security Analyzer ,MBSA)是 Microsoft 提供的一款免费工具。它可检查计算机是否存在各种已知漏洞，确保系统安全，随后生成报告列出所有发现的问题。作为管理员，您可以逐一调查这些问题并采取措施加以解决。

许多组织会实施合规性审计( Compliance Auditing )，以确保其系统符合基本安全要求。例如，组织可能制定书面安全策略，明确需要保护的系统或数据，然后使用各种技术落实保护要求，并持续更新系统以确保持续合规。

MBSA 提供基本的合规性审计功能，可验证系统是否符合基本安全标准。

您可以使用 MBSA 检查单台计算机或一定范围内的多台计算机。例如，可针对域中所有计算机或特定 IP 地址范围内的所有计算机运行扫描。

## 第6章 保护客户端和服务器

**理解保护客户端（最终用户计算机）和服务器**可采取的不同措施至关重要。某些通用技术同时适用于两者，而其他技术仅适用于客户端或仅适用于服务器。用户帐户控制( User Account Control ,UAC)是一种内置机制，用于在客户端和服务器上将管理操作与常规用户操作分离。此外，保持组织内每个系统处于最新状态对于防范新发现的潜在漏洞同样重要。

还需考虑用户可以使用脱机文件夹( Offline Folders )存储从共享访问的数据。有时，你可能希望通过加密脱机文件夹来保护这些脱机数据。此外，还可以通过使用软件限制策略( Software-Restriction Policies )控制哪些应用程序运行来保护客户端。

你可以通过将服务器置于虚拟局域网( Virtual Local Area Network ,VLAN)中，并确保服务器未运行存在安全目标冲突的服务，为服务器增加一层保护。只读域控制器( Read-Only Domain Controller ,RODC)是一种新型域控制器，可在分支机构中保护并进一步限制Active Directory。每个Active Directory环境必须包含一台运行域名系统( Domain Name System ,DNS)服务的服务器。由于DNS对任何Active Directory环境都至关重要，你应采取措施在DNS中提供额外安全性。本章在以下主题中涵盖这些概念：

- 理解用户帐户控制
- 保持系统更新
- 保护客户端
- 保护服务器
- 探索DNS安全问题

### 理解用户帐户控制

*用户帐户控制( User Account Control ,UAC)*通过分离标准任务所需权限和管理任务所需权限，为系统提供非常基础的保护级别。管理帐户包括内置管理员帐户( Administrator Account )以及管理员组( Administrators Group )中的任何其他帐户。当用户使用管理帐户登录时，该用户会被分配两个访问令牌( Access Token )。一个令牌用于常规用户帐户活动，也用于启动桌面。第二个令牌用于管理目的。其目标是通过限制管理凭据可用的实例，防止对计算机进行未经授权的更改。

管理帐户包括Administrator帐户以及Administrators组中的任何帐户。

当用户执行创建文档或处理电子邮件等基本任务时，系统使用常规令牌( Regular Token )。然而，当用户尝试执行需要管理权限的任务时，会看到类似图 6-1 的对话框。如果用户单击"继续"，则使用管理令牌( Administrative Token )来执行该管理任务。

**图 6-1：** UAC 提示批准执行任务

![f0601.tif](./image/Chapter%206%20Protecting%20Clients%20and%20Servers/f0601_fmt.webp)

关于 UAC 的一个要点是：管理令牌仅用于执行单个已批准的任务。如果用户希望执行另一项管理任务，UAC 对话框会再次出现以请求批准。这可以防止恶意软件利用提升权限的令牌来执行其他未经批准的任务。

如果非管理用户尝试执行需要管理员权限的操作，UAC 也会介入。非管理员没有管理令牌，因此无法直接单击"继续"。UAC 会向非管理员提供输入管理凭据的机会，如图 6-2 所示。其工作方式类似于第 3 章"理解用户身份验证"中描述的"以管理员身份运行"功能。

### 理解变暗桌面

当用户账户控制( User Account Control ,UAC)提示你继续操作或提供管理员凭据时，它会将桌面变暗。在变暗桌面（也称为安全桌面）中，你唯一能执行的操作就是响应 UAC 提示。

变暗桌面也被称为安全桌面( Secure Desktop )。例如，组策略( Group Policy )设置中使用了术语“安全桌面”。

变暗桌面可防止恶意软件绕过 UAC。UAC 会等待手动干预，在此期间，应用程序活动被暂停。虽然可以禁用变暗桌面，但不建议这样做。如果禁用，恶意软件可能触发并响应 UAC，在无需任何用户交互的情况下批准操作。

Windows Vista 和 Windows Server 2008 仅提供启用或禁用 UAC 的选项。

**图 6-3：** 用户账户控制设置页面

以下设置可用：

**始终通知我** 此设置在程序尝试安装软件或更改计算机时提供通知。如果你经常安装新软件或访问不熟悉的网站，建议使用此设置。这是 Windows Vista 和 Windows Server 2008 的默认行为（但 Windows 7 和 Windows Server 2008 R2 除外）。

**默认 - 仅当程序尝试更改我的计算机时通知我** 此设置会在程序尝试更改需要管理员权限的计算机设置时通知你。只要你拥有管理员权限，它不会在你更改 Windows 设置时通知你。如果你使用熟悉的程序并访问熟悉的网站（例如仅访问公司网站或合法网站，如 **[www.msn.com](http://www.msn.com/)**），建议使用此设置。这是 Windows 7 和 Windows Server 2008 R2 的默认设置。

**仅当程序尝试对我的计算机进行更改时通知我(不降低桌面亮度)** 此设置类似于 Windows 7 和 Windows Server 2008 R2 的默认设置，但桌面不会变暗。由于桌面不会变暗，恶意软件可以在无需任何用户交互的情况下响应 UAC。此设置是为资源有限(如较旧的处理器或最小内存)且桌面变暗耗时较长的系统提供的一个选项。然而，不建议使用此设置，因为它会削弱安全性。

**从不通知** 此设置会关闭 UAC。不建议使用此设置，它仅作为完全不兼容 UAC 的旧版应用程序的选项提供。例如，如果某个应用程序是为 Windows 2000 或 Windows XP (在 UAC 开发之前)编写的，它可能不兼容 UAC。你可以禁用 UAC 来运行此类程序，但这会削弱计算机的整体安全性。

### 保持系统更新

保护所有系统(客户端和服务器)的重要一步是确保它们保持最新状态。原因是操作系统和应用程序中会定期发现错误和安全漏洞。一旦发现这些漏洞，通常会得到解决，并作为系统更新的一部分进行处理。安全漏洞的发现和解决全过程包括以下几个步骤：

第 1 章在"强化服务器"部分介绍了保持系统更新的重要性。

**1. 发现漏洞** 该漏洞可能首先由安全人员或黑客发现。许多专业安全人员会定期检查软件并发现漏洞。攻击者也会尝试发现任何可以利用的漏洞，并且许多攻击者会与其他攻击者共享此信息。

零日漏洞( Zero-Day Vulnerability )是指未被广泛知晓或供应商未知的漏洞。零日攻击( Zero-Day Attack )利用的就是零日漏洞。

**2. 通知供应商** 大多数供应商(包括 Microsoft )都设有保密渠道，安全人员可以通过这些渠道私下报告漏洞。有时这些漏洞会通过书面文章公开报告，这同时也会通知攻击者和供应商。其他时候，会注意到可疑活动，供应商自行发现漏洞。

**3. 供应商开发并测试解决方案作为更新** 随后，供应商会以更新的形式创建修复程序。由于任何变更都可能引发问题，该更新在发布前需经过测试。所需时间取决于漏洞的严重程度。部分更新可能需要长达六个月才能发布，而另一些则在一个月内即可发布。

**4. 供应商提供更新** 微软在每个月的第二个星期二（即“补丁星期二”( Patch Tuesday )）通过其更新网站发布安全更新。当天发布的更新包含所有经微软测试的更新。

针对严重漏洞的补丁可能会在补丁星期二以外的日期（即带外( out of band )发布）发布。这种情况较为罕见，仅针对严重漏洞。

**5. 下载并安装更新** 客户端随后可下载并安装系统更新。理想情况下，此过程应自动完成。例如，微软通过 Windows 更新( Windows Update )和 Microsoft 更新( Microsoft Update )发布更新。配置了自动更新( Automatic Updates )的系统可自动下载并将更新安装到系统中。当然，更新只有在被下载并安装后才能解决漏洞。若未安装，系统仍将处于易受攻击状态。更糟的是，由于更新中公开了漏洞信息，更多攻击者会因此知晓该漏洞（请参阅边栏“逆向工程更新”）。

**逆向工程更新**

部分攻击者会等待补丁星期二，以查看已发布的补丁。随后，他们会对代码进行反编译和分析，以了解其功能。在发现代码正在修复的漏洞时，他们也会发现原始的弱点。整个过程称为逆向工程( reverse engineering )，几乎可应用于任何软件，包括系统更新。

由于许多系统并未立即更新，或根本未更新，攻击者现在可以开发攻击手段来利用该漏洞。只要系统未打补丁，它们就始终处于易受攻击状态。

有多种方法可保持系统更新。最常见的方法是使用自动更新，但组织也可使用更高级的服务器技术（如 Windows Server 更新服务( Windows Server Update Services ,WSUS)或 System Center 配置管理器( System Center Configuration Manager ,SCCM)）来保持系统更新。

**使用自动更新更新系统**

使用 WSUS 或 SCCM 更新系统

需要认识到，尽管 Microsoft 会进行测试，但无法测试所有可能的硬件和软件配置。最坏的情况是，补丁修复了一个问题却引发了另一个问题。可能出现意外结果，例如迫使系统进入无限重启循环。

在无限重启循环中，系统重新启动，在用户登录之前再次重启。此过程持续进行，直到系统关闭。

如果这种情况发生在一两台系统上，虽然不便，但只需进行故障排除即可恢复系统运行。然而，如果大量机器（例如组织中的 500 台计算机）出现此问题，后果可能是灾难性的。此时，不仅 500 名员工无法正常开展工作，IT 人员也面临必须解决的危机。

许多组织通过集中管理和分发更新来控制更新，以防止类似情况发生。微软为组织提供了两种工具：

**Windows Server 更新服务( Windows Server Update Services ,WSUS)可免费下载。** 可将其安装在 Windows 服务器上，用于管理组织内客户端的更新。

**System Center Configuration Manager (SCCM) 是一个附加服务器产品。** 它并非免费，但相比 WSUS 有显著增强。主要优势在于，你可以使用 WSUS 安排更新部署到客户端的时间。

保护客户端

前几节涵盖了客户端和服务器，但某些问题仅适用于客户端。例如，用户可能在客户端计算机上启用并使用脱机文件夹( Offline Folders )，但脱机文件夹在服务器上的使用方式不同。同样，一些管理员希望阻止用户在客户端系统上运行特定软件，他们可以通过软件限制策略( Software-Restriction Policies )实现这一点。本节将解释脱机文件夹是什么、如何对其进行加密，以及为何应考虑使用软件限制策略。

了解脱机文件夹

第 3 章介绍了共享( Shares )和共享权限( Share Permissions )。提醒一下，共享是服务器上已共享并可供网络上用户使用的文件夹。用户可以通过映射驱动器或直接在“开始搜索”文本框中输入通用命名约定( Universal Naming Convention ,UNC )路径来访问共享。

UNC 路径的格式为 \\服务器名\共享名。

**图 6-7：** 使用组策略配置客户端从 WSUS 服务器接收更新

![f0607.tif](./image/Chapter%206%20Protecting%20Clients%20and%20Servers/f0607_fmt.webp)

当用户连接到网络时，只要被授予了相应共享权限，即可访问网络中的共享资源。例如，Sally 在办公场所工作时可以定期访问 \\File1\Sales 共享（位于网络中的 File1 服务器上）。然而，当她出差到客户现场时，由于不再连接工作网络，便无法访问 Sales 共享。

脱机文件夹( Offline Folders )允许用户在断开网络连接时仍能访问共享数据。用户可指定哪些文件缓存在本地计算机上，这些文件随后会存储在本地计算机上一个名为"脱机文件夹"的特殊文件夹中。若用户已连接网络，则使用共享中的副本；若未连接网络，则使用缓存副本。

文件的缓存副本存储在用户本地硬盘驱动器的 Windows\CSC 文件夹中。

当系统重新连接网络时，会检查脱机文件夹中的文件是否发生更改，然后执行同步操作。若共享中的文件已更改，则将其下载到客户端；若客户端上的文件已更改，则将其上传至共享（前提是设置允许）。若两端副本均发生更改，系统会通知用户，由用户决定如何处理冲突。

某些脱机设置仅允许文件下载到客户端。在此情况下，客户端计算机上所做的更改无法上传至服务器。

在 Windows 7 系统上，可通过脱机文件夹配置页面管理脱机文件。从控制面板( Control Panel )进入，在控制面板搜索文本框中输入 **offline**，然后选择"管理脱机文件"。

加密脱机文件夹

第 1 章将机密性( Confidentiality )列为安全三元组（亦称 CIA 三元组或 AIC 三元组）的三大要素之一。机密性保护数据免遭未授权泄露。尽管权限提供了基础保护，但某些数据需要额外保护（如加密）来防止机密性丧失。

可以使用加密文件系统( Encrypting File System ,EFS )加密存储在 NTFS 驱动器上的数据。只有授权人员才能打开 EFS 加密的文件。

第 10 章将详细介绍如何使用 EFS 加密 NTFS 文件和文件夹。EFS 内置于 NTFS 中。

不过，理解其基本工作原理仍然很重要。当授权用户打开加密文件时，该文件会自动解密以便用户读取。这在本地系统上没有问题；但请参阅图 6-8，了解加密文件存储在共享位置时的影响。当用户访问该文件时，文件由服务器解密，并通过网络以明文形式发送。

![f0608.eps](./image/Chapter%206%20Protecting%20Clients%20and%20Servers/f0608_fmt.webp)

可以对通过网络传输的数据进行加密。第 7 章将介绍 Internet 协议安全性( Internet Protocol Security ,IPsec)。IPsec 能够加密网络上的数据。

此外，如果用户使用脱机文件( Offline Files )，默认情况下会缓存文件的解密版本。这可能带来安全风险，尤其是当用户将计算机带出工作环境时。如果计算机被盗，攻击者可能获取未加密数据的访问权限。不过，可以对脱机文件进行加密。图 6-9 显示了选中“加密”选项卡的“脱机文件”属性页面。如前所述，您可以通过在控制面板搜索文本框中输入 **offline** 并选择“管理脱机文件”来访问此页面。

使用软件限制策略( Software-Restriction Policies )

管理员可用于保护客户端的另一工具是软件限制策略。软件限制策略是一组规则，可用于阻止特定软件在系统上运行，或仅允许特定软件运行。

Windows Server 2008 和 Windows 7 系统支持软件限制策略。

软件限制策略提供了多种用于标识应用程序的选项。首先定义默认安全级别，然后针对该默认级别创建例外。例如，可将默认安全级别定义为"不受限"( Unrestricted )（即允许任何软件运行），然后定义例外来标识哪些软件被阻止。

![f0610.tif](./image/Chapter%206%20Protecting%20Clients%20and%20Servers/f0610_fmt.webp)

图 6-10 显示了已展开"软件限制策略"的本地安全策略( Local Security Policy )。默认情况下，此节点为空。但若右键单击"软件限制策略"并选择"新建软件限制策略"，则会创建相应策略。以下内容解释各项规则：

**不允许( Disallowed )** 此规则阻止所有软件运行。随后在"其他规则"部分创建例外，以标识允许运行的软件。例如，位于公共场所的自助服务终端( Kiosk )计算机可设置此规则，并添加例外以允许特定应用程序运行，该规则将阻止所有其他应用程序。

**基本用户( Basic User )** 仅允许需要基本用户权限的程序运行。需要管理员权限的程序将被阻止。

**不受限制( Unrestricted )** 这是默认规则。该规则允许所有软件运行（只要用户拥有相应权限），但被识别为例外的软件除外。

| 证书( Certificate ) | 标识由数字证书( Digital Certificate )签名过的应用程序。这是识别应用程序的可靠方式。但若要使用此类规则，需拥有应用程序创建厂商提供的证书。 |

哈希值( Hash )是由哈希算法( Hashing Algorithm )生成的数字。只要文件未被修改，哈希算法始终会生成相同的哈希值。

保护服务器

正如某些保护措施直接适用于客户端，另一些则直接适用于服务器。需要认识到，这些额外的保护措施是在已提及的服务器和客户端其他步骤基础之上的补充。

例如，第1章强调了加固服务器的重要性。加固服务器包括减少攻击面、保持系统更新、启用防火墙以及安装防病毒软件。本章进一步扩展了保持系统（包括服务器）更新的方法。以下各节将介绍其他可用于保护服务器的措施。

**使用独立 VLAN**

虚拟局域网( Virtual Local Area Network ,VLAN)是一种可在三层交换机上创建的可管理局域网。它提供更高的安全性、更好的性能，并允许将客户端添加到网络段，无论其物理位置如何。基于此，你可以使用 VLAN 将服务器与客户端分离。

VLAN 的详细内容在《Microsoft Windows 网络基础》(Wiley, 2011)中有深入介绍，该书覆盖了考试 98-366。

例如，图 6-12 展示了在交换机上配置的两个 VLAN。左侧的 VLAN 用于客户端，右侧的 VLAN 用于服务器。

![f0612.eps](./image/Chapter%206%20Protecting%20Clients%20and%20Servers/f0612_fmt.webp)

VLAN 通过将服务器的广播流量限制到特定端口，从而提高了局域网安全性。如图所示，来自服务器的广播流量仅会到达端口 F0/21 至 F0/24，而不会到达客户端 VLAN 中的任何客户端。

**分离服务**

一台 Windows Server 2008 服务器可以承载多个角色。例如，域控制器通常也会托管 DNS 服务。同样，文件服务器也常兼作打印服务器。

DNS 提供名称解析服务，将名称解析为 IP 地址。在 Microsoft 域中，必须有一台运行 DNS 的服务器。

然而，应避免将安全需求相互冲突的服务合并到同一台服务器上。例如，域控制器承载 Active Directory，包含用户帐户、组、计算机帐户等内部信息；而托管 Internet 站点的 Web 服务器可能被全球任何具有 Internet 访问权限的用户匿名访问。将两者部署在同一台服务器上并不明智，因为其安全上下文( Security Context )截然不同。

Windows Server 2008 支持 16 种角色，如图 6-13所示。Windows Server 2008 R2 还支持用于虚拟化的 Hyper-V 角色，总计 17 种角色。

**图 6-13：** Windows Server 2008 中的角色

![f0613.tif](./image/Chapter%206%20Protecting%20Clients%20and%20Servers/f0613_fmt.webp)

图 6-13中的服务器承载了两种角色：Active Directory 域服务器和 DNS。

以下指南可用于判断哪些服务可考虑合并，哪些应保持分离：

**Active Directory 服务** 将 Active Directory 服务相互合并是可接受的。Active Directory 域服务( Active Directory Domain Services ,AD DS )是域的主要角色，而其他 Active Directory 服务（如 Active Directory 证书服务( Active Directory Certificate Services ,AD CS )）则扩展了 Active Directory 的功能。此外，建议在域控制器上托管 DNS 并启用 Active Directory 集成( Active Directory–integrated ,ADI ) DNS。

第 11 章将介绍 Active Directory 证书服务的基础知识。

**应用程序服务器** 应用程序服务器承载服务器应用程序，例如 Microsoft 的 Forefront Threat Management Gateway 或用于电子邮件的 Microsoft Exchange Server。Forefront 是一系列安全产品。若将 Forefront 用作网络防火墙，则不应包含其他提供数据的角色（如 Web 服务器）。然而，Microsoft Exchange 的某些元素需要 Web 服务器。需明确服务器应用程序的用途，避免安全冲突。

**DHCP 与 DNS** 将 DHCP 和 DNS 角色合并是常见且可接受的做法，但这并非必需。两者均提供网络服务。如果在域控制器上安装 DNS，则可以创建 Active Directory 集成 DNS 区域( Active Directory–integrated DNS zones )并启用安全动态更新( secure dynamic updates )。

**网络策略和访问服务** 此角色中的服务提供保护，不应与任何 Active Directory 角色合并。可以使用此角色托管虚拟专用网络( Virtual Private Network ,VPN)服务器。还可以将此角色用于网络访问保护( Network Access Protection ,NAP)，在授予客户端网络访问权限之前检查其基本安全性。

第 7 章将更深入地介绍 NAP。

**传真服务器、文件服务、打印服务** 这些角色可以合并。例外情况是其中一个角色处理敏感数据。例如，如果文件服务器托管需要额外保护的敏感研发数据，则可以选择将敏感数据存储在不同的服务器上。这取决于数据的价值。

**终端服务（Windows Server 2008 R2 上的远程桌面服务）** 终端服务（在 Windows Server 2008 R2 中更名为远程桌面服务( Remote Desktop Services )）为远程用户托管应用程序和/或 Windows 桌面。不应在托管任何 Active Directory 角色的服务器上安装此角色。

**UDDI 服务** 通用描述、发现和集成( Universal Description, Discovery, and Integration ,UDDI)用于在 Intranet 或 Extranet 内共享有关 Web 服务的信息。通常将其托管在 Web 服务器上，但不应与 Active Directory 角色合并。

**Web 服务器 (IIS)** 如果 Web 服务器用于托管面向 Internet 访问的网站，通常最好将服务器限制为仅 Web 服务器 (IIS) 角色。然而，内部使用的 Web 服务器可以托管其他角色。例如，内部 Web 服务器还可以包括文件服务和打印服务角色。其他一些角色（如 Active Directory 权限管理服务( Active Directory Rights Management Services )）使用并需要此角色。

**Windows 部署服务( Windows Deployment Services ,WDS)** WDS 将操作系统映像部署到网络中的系统。通常会在 WDS 服务器上包含 DHCP，但不建议在 WDS 服务器上包含任何 Active Directory 角色。

使用服务器管理器( Server Manager )添加其他角色时，如果角色不建议共存，它将提供警告。

你可能已经注意到前面描述中的一个主题。Active Directory 角色通常包含最敏感的数据，因此最佳做法是确保 Active Directory 角色不会添加到可公开访问的服务器上。

**使用只读域控制器**

域中的传统域控制器都保存相同的数据，并且可以在任何这些域控制器上更改数据。然而，Windows Server 2008 中引入的*只读域控制器( Read-Only Domain Controller ,RODC)* 不包含 Active Directory 中识别为“机密”的某些敏感数据。此外，无法将更改写入存储在 RODC 上的数据库副本。

Active Directory 中的敏感数据包括帐户密码。管理员帐户的密码不会存储在 RODC 上。

在分支机构中，如果其物理安全级别不如组织主站点高，使用 RODC 会非常有用。如果域控制器从安全性较低的分支机构被盗，该损失不会危及域的敏感机密。

大多数组织将服务器（包括域控制器）保护在锁定的服务器机房中。分支机构通常没有独立的、安全的服务器机房。

分支机构通常通过 WAN 链路与公司的主站点分离。有时，WAN 链路可能速度较慢或被认为不可靠。如果未在远程办公室部署域控制器，并且到主站点的 WAN 链路不可用，这可能会影响用户登录域以及访问远程办公室中网络资源的能力。通过在远程办公室放置域控制器，即使到主站点的 WAN 链路速度较慢或不可靠，也可以允许用户进行身份验证，从而提高员工的工作效率。

在 Windows Server 2008 之前，管理员必须权衡在远程办公室放置域控制器的利弊。如果他们在远程办公室放置了传统域控制器，则可以提高这些用户的工作效率。但是，如果域控制器被盗，则可能危及整个域。通过部署 RODC，管理员不再需要牺牲安全性，并且可以有效地减轻与远程办公室域控制器部署相关的一些风险。

每个只读域控制器( RODC )均可配置密码复制策略( PRP )。PRP 用于标识哪些账户的密码可以存储在 RODC 上。例如，若分支机构包含 10 个拥有普通用户账户的用户，可修改 PRP 使其包含这 10 个用户的密码。当这些用户首次登录时，RODC 会通过广域网( WAN )链路向常规域控制器验证凭据。若用户身份验证成功，RODC 会缓存该用户的密码。下次用户登录时，RODC 将使用缓存的密码进行登录验证；若登录尝试成功，用户即可完成登录，无需身份验证流量穿越 WAN 链路。

PRP 仅适用于单个 RODC，每个 RODC 可配置不同的 PRP。

然而，若未在 PRP 中标识的用户尝试登录，RODC 会向主站点的域控制器验证密码，但不会缓存该密码。每次该用户尝试登录时，身份验证请求均需通过 WAN 链路发送至常规域控制器。

支持 RODC 的域包含以下两个特殊组。

**允许的 RODC 密码复制组( Allowed RODC Password Replication Group )**：添加到此组的用户，其密码会自动缓存在域中的每个 RODC 上。这与仅影响单个 RODC 的 PRP 不同。默认情况下，此组为空。

允许的 RODC 密码复制组适用于域中的所有 RODC。

**拒绝的 RODC 密码复制组( Denied RODC Password Replication Group )**：此组包含多个其他组，例如企业管理员组( Enterprise Admins )和域管理员组( Domain Admins )。此组（或其任何成员组）中的用户，其密码永远不会缓存在 RODC 上。

若某用户同时属于这两个组，则拒绝权限优先。其密码不会缓存在 RODC 上。

探索 DNS 安全问题

域名系统( Domain Name System ,DNS )服务是 Microsoft 域的核心组成部分。DNS 的主要功能是将主机名解析为 IP 地址，并标识运行特定服务的服务器。

DNS 在《Microsoft Windows 网络基础》(Wiley, 2011)一书中有更深入的介绍，该书涵盖 98-366 考试内容。

针对 98-367 考试，您应熟悉以下三种重要的 DNS 记录：

**A（主机）记录**  
*A 记录( A Record )* 包含用于将主机名解析为 IP 地址的信息。DNS 客户端使用主机名查询 DNS 服务器，DNS 服务器查找 A 记录并返回对应的 IP 地址。在此上下文中，主机是指具有 IP 地址的设备，通常为计算机，但也可能是路由器、防火墙或任何其他具有 IP 地址的设备。

AAAA 记录为 IPv6 提供相同服务：将主机名解析为 IPv6 地址。

**PTR（指针）记录**  
*PTR 记录( PTR Record )* 用于提供反向查找。客户端可使用 IP 地址查询 DNS 服务器，若 PTR 记录存在，DNS 服务器将返回主机名。PTR 记录在 DNS 服务器上为可选配置；若不存在，DNS 服务器无法执行反向查找，但名称到 IP 地址的解析功能仍可正常运作。

**SRV（服务）记录**  
*SRV 记录( SRV Record )* 用于标识运行特定服务的计算机。例如，当用户登录域时，客户端计算机会查询 DNS 以获取标识用户域中域控制器的 SRV 记录。

**SPF（发件人策略框架）记录**  
*SPF 记录( Sender Policy Framework Record ,SPF Record )* 用于标识授权为特定域发送电子邮件的特定系统。这些记录发布在公共 DNS 服务器上，可供任何邮件服务器查询。例如，wiley.com 域可能拥有三台用于收发电子邮件的邮件服务器，它们会发布 SPF 记录以标识这三台服务器。SPF 记录通过检查电子邮件欺骗来验证邮件合法性，并有助于防止垃圾邮件。

SPF 记录有助于防范电子邮件欺骗。

通常，欺骗( Spoofing )指冒充或伪装成某人或某物的行为。在电子邮件欺骗中，被欺骗的邮件看似来自合法来源，实则由垃圾邮件发送者发送。在 IP 欺骗中，源 IP 地址被篡改，使数据看似来自某个 IP 地址（如受信任的 IP），实则源自攻击者。

**使用 SPF 记录防范电子邮件欺骗**

垃圾邮件发送者常使用伪造源地址发送数千封邮件。他们可能篡改邮件头中的“发件人”和“回复”字段，但实际源 IP 地址仍会被保留。

源地址很少能识别攻击者。例如，第2章“了解恶意软件与社会工程学”介绍了由攻击者控制的僵尸网络的相关信息。僵尸网络中的计算机在攻击者指令下常会发送垃圾邮件。这些电子邮件很难追溯到真正的攻击者。然而，SPF记录有助于识别伪造的电子邮件。

假设某邮件服务器收到一封“发件人( From )”字段被伪造的电子邮件，声称来自 wiley.com 的某位用户。邮件中嵌入了源计算机的 IP 地址。邮件服务器向公共 DNS 服务器查询 wiley.com 的 SPF 记录。SPF 记录标识了被授权代表 wiley.com 发送邮件的邮件服务器。如果邮件来自未包含在 SPF 记录中的服务器，则视为伪造邮件并被忽略或丢弃。

合法组织不会伪造电子邮件，因此邮件服务器丢弃伪造邮件是常见做法。

一个关键点是，拥有邮件服务器的合法组织必须向公共服务器提交 SPF 记录。如果某个组织没有 SPF 记录，攻击者就能更轻易地利用该域名伪造电子邮件。延续上述示例，如果 wiley.com 域没有外部 SPF 记录，垃圾邮件发送者就能使用来自 wiley.com 的伪造邮件。合法邮件服务器将无法利用 SPF 记录来判断看似来自 wiley.com 的邮件是合法还是伪造。

了解动态更新

在互联网上，DNS 记录通常是手动创建的。管理员需要实际动手操作键盘，输入数据以将主机名与 IP 地址匹配。由于外部 IP 地址通常静态分配且很少更改，因此手动创建和维护 DNS 记录在互联网上运行良好。

然而，在内部 Microsoft 网络中，由于动态主机配置协议( Dynamic Host Configuration Protocol ,DHCP)，客户端每次启动时可能获得不同的 IP 地址。为大量内部客户端手动创建 DNS 记录并不可行。相反，可以允许客户端使用*动态更新*来创建或更新其 DNS 记录。

该过程始于 DHCP。大多数内部网络使用 DHCP 在客户端启动时为其分配 IP 地址及其他 TCP/IP 配置信息。

DHCP 在涵盖 98-366 考试的《Microsoft Windows 网络基础》(Wiley, 2011)中有更深入的介绍。

DHCP 为 Microsoft 系统分配 IP 地址后，系统会自动使用动态更新( Dynamic Update )创建 DNS 记录。图 6-14 展示了整体流程：

**1.** 客户端启动时，与 DHCP 交换数据以获取 TCP/IP 配置信息。例如，DHCP 分配 IP 地址和子网掩码，同时也可分配默认网关和 DNS 服务器地址。

**2.** 客户端随后与 DNS 通信，根据客户端主机名和分配的 IP 地址创建 A 记录。

上述每个步骤都有更深入的细节，但理解整体概貌至关重要。动态更新意味着 DNS 记录会动态更新。

使用安全动态更新

尽管动态更新简化了 DNS 上记录的创建，但许多组织希望确保该过程的安全性。*安全动态更新( Secure Dynamic Updates )* 提供两大主要优势。

首先，只有经过身份验证的客户端才能在 DNS 中创建记录。域中的计算机通过 Active Directory 进行身份验证。如果计算机无法通过身份验证，则不会创建记录。此外，你可以为 DNS 区域分配权限，使管理员对区域数据拥有更强的控制能力。

图 6-15 展示了 DNS 区域的属性页面。注意，类型设置为 Active Directory 集成( Active Directory-Integrated )，动态更新设置为仅安全( Secure Only )。这意味着仅允许安全动态更新，常规动态更新（非安全动态更新）将被阻止。

**图 6-15：** 动态更新流程

![f0615.eps](./image/Chapter%206%20Protecting%20Clients%20and%20Servers/f0615_fmt.webp)

如果你计划配置安全动态更新，以下两点至关重要：

**DNS 区域必须是 Active Directory 集成( ADI )区域** Active Directory 管理 ADI 区域，可减少管理负担，使 DNS 更易于维护。如果区域不是 ADI 区域，则无法选择将动态更新设置为仅安全。

**域控制器上必须安装 DNS** 只有在域控制器上安装了 DNS 时，才能创建 ADI 区域。如果 DNS 运行在成员服务器上，则只能创建主要区域和辅助区域，而无法创建 ADI 区域。换言之，如果服务器未托管 Active Directory，则无法在该服务器上创建 Active Directory 集成( Active Directory–Integrated ,ADI)区域。

微软官方文档一贯建议在域控制器上安装 DNS。由于 Active Directory 高度依赖 DNS，这一建议非常合理。此外，微软一贯建议将 DNS 区域转换为 ADI 区域。

**基础与进阶**

在本章中，你学习了用于保护客户端和服务器的常见技术。用户帐户控制( User Account Control ,UAC)将管理操作与普通用户操作分离，有助于防范恶意软件。你可以为系统配置自动更新以确保其保持最新状态；或者，如需更精细的控制，可使用 WSUS 或 SCCM 部署更新。WSUS 免费提供，而 SCCM 是附加服务器产品。脱机文件夹( Offline Folders )允许用户即使未连接到网络也能访问共享数据。你可以加密脱机文件夹中的数据以提供额外保护层。还可以使用软件限制策略( Software-Restriction Policies )限制客户端上运行的软件。保护服务器的一些技术包括：使用独立 VLAN、确保服务之间不存在冲突的安全要求，以及使用只读域控制器( Read-Only Domain Controller ,RODC)。DNS SPF 记录通过检测电子邮件欺骗尝试来防范垃圾邮件。如果对 DNS 使用 ADI 区域，还可以实施安全动态更新( Secure Dynamic Updates )。

**附加练习**

- 识别系统上用户帐户控制的当前设置。
- 确定系统是否正在使用自动更新( Automatic Updates )。
- 配置系统以加密脱机文件夹。
- 确定系统本地是否定义了软件限制策略。
