# Photobomb — Sinatra / ImageMagick command injection (test lab)

> Retired HTB machine reconstruction. Docker Existing historical full-chain CI evidence is retained; the newer single-instance E2E Root check has a documented test-harness cache collision and is not treated as evidence that the target exploit is broken. This is not an official HTB image.

## Player discovery path

1. Nmap finds HTTP/80 and SSH/22. The landing page is the Photobomb franchise introduction; it does not disclose the vulnerable parameter.
2. Inspect page source and `photobomb.js`. It contains the tech-support Basic Auth credentials `pH0t0:b0Mb!`. `/printer` is protected by real Nginx HTTP Basic Auth.
3. The printer page lists photographs and dimensions. Submit a normal request first and observe that ImageMagick really converts the selected JPEG.
4. The Sinatra `POST /printer` handler validates `filetype` with the prefix regex `^(png|jpg)` but concatenates the untrusted value into a shell command passed to `system()`. A suffix such as `; touch ...` executes as `wizard`. This is actual command injection through a real ImageMagick command, not a simulated success endpoint.
5. Inspect `/opt/cleanup.sh` and `/opt/.bashrc`. `wizard` has `sudo SETENV: NOPASSWD: /opt/cleanup.sh`. The script calls `find` without an absolute path; a writable earlier PATH entry hijacks it and executes as root.
6. Read `/home/wizard/user.txt` and `/root/root.txt` after the corresponding privilege boundary.

## Fidelity and provenance

- The public HTB writeups expose the original route semantics, HTML, JavaScript credential clue, cleanup script and Bash configuration. The original app source is not released as an official repository; the Sinatra implementation here is an independently authored reconstruction of the observed behavior.
- Writeups: https://0xdf.gitlab.io/2023/02/11/htb-photobomb.html ; https://docs.secopsbear.com/ctf/HTB-Retired/htb-photobomb/ ; https://github.com/TomerSitton/CTFs/tree/main/HackTheBox/Photobomb
- Official retired machine page: https://www.hackthebox.com/machines/photobomb
- Original high-resolution Unsplash assets are not bundled. Small local JPG gallery assets are generated by the genuine ImageMagick `convert` utility so the gallery and conversion path remain functional without shipping multi-megabyte photos.
- Runtime is Alpine/Ruby 2.7 + Nginx + ImageMagick + OpenSSH. Service fingerprints differ from the original Ubuntu/Nginx host; the web routes, command injection and sudo path-hijack semantics are preserved.

## Acceptance

The dedicated .github/workflows/photobomb-e2e.yml builds the target and a separate non-root attacker, then exercises one clean instance over an internal-only Docker network. The attacker verifies normal ImageMagick conversion and retrieves the exact User Flag through the real command-injection path. The current Root-stage check has a harness false negative: both injected requests use the same 300x200 output filename, so the second request hits the application's existing resized-image cache and never invokes system() again. The target's actual sudoers rule grants SETENV for /opt/cleanup.sh, the script invokes relative find, and its sourced /opt/.bashrc preserves PATH; source review confirms the intended PATH-hijack Root path is feasible. The failed E2E run therefore does not establish a target-side Root exploit failure. No docker exec or target filesystem mount is used.

Resource target: **<= 140 MiB image, <= 192 MiB memory, <= 128 PIDs**. CI reports measured values; do not treat these targets as measurements.

Static demo flags only: `/home/wizard/user.txt` and `/root/root.txt`. Production Worker instances must inject `PHOTOBOMB_STATIC_USER_FLAG`, `PHOTOBOMB_STATIC_ROOT_FLAG`, and `PHOTOBOMB_REQUIRE_PRIVATE_FLAGS=1`. Keep production answers outside Git and public GHCR images.
